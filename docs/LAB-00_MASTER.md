## 4. 설계 원칙

### 4-1. 백테스트와 페이퍼가 같은 엔진

```
전략 정의 ──┬── 과거 데이터 → 백테스트
            └── 실시간 데이터 → 페이퍼
```

**실행기는 하나다.** 데이터 소스만 갈아 끼운다.
따로 만들면 백테스트 결과와 페이퍼 결과를 비교할 수 없다.

### 4-2. 전략은 선언적으로

나중에 UI에서 조합하려면 코드가 아니라 데이터여야 한다.

### 4-3. 자본은 전략마다 독립

한 지갑을 나눠 쓰지 않는다. 그래야 순수 비교가 된다.

### 4-4. 화면은 최소로

**표와 선 하나면 된다.** 지금 필요한 건 보기 좋은 화면이 아니라 판단할 수 있는 화면이다.

| 만든다 | 안 만든다 |
|---|---|
| 백테스트 결과 표 | 격자·히스토그램 |
| 자산곡선 | 애니메이션 |
| 전광판 표 | 로그 뷰어 |
| 전략 상세 | 전략 설정 UI |

**빠진 건 필요해지면 그때 만든다.**

## 5. 이식 목록 — FCE에서 가져올 것

| 항목 | 비고 |
|---|---|
| 백테스트 프레임 + 워크포워드 | 그대로 |
| 리스크 사이징 | 결함 수정본 |
| 페이퍼 체결 로직 | 체결 가정 확인 필요 |
| Hyperliquid 수집 | 그대로 |
| 재진입 잠금 | 그대로 |
| **와이코프 엔진** | **제외.** 미해결 결함 15건 |

**FCE 코드를 복사하기 전에 각각이 어떤 결함 수정을 거쳤는지 확인한다.** 옛 버전을 가져오면 고쳐놓은 게 되살아난다.

> **실측 주의 (2026-09-10):** FCE 는 **파이썬**이다(`backend/` .py 411개). FOMO Club 은 타입스크립트다(.ts/.tsx 801개).
> 위 "그대로"는 **복사가 아니라 재작성**이다. 복사로 인한 결함 되살아남 대신 **이식 중 새 결함**이 위험이다.
> 이식할 때마다 FCE 원본의 테스트(`backend/tests/`)를 같이 읽고, 타입스크립트 쪽에 대응 테스트를 만든다.
