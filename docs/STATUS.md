## 7. WO-RENDER-01 — PART B·C **종결** (2026-08-17)

직전 판은 PART C 를 "부분 — 자동배포 경로 미해결" 로 남겼다. **이번에 닫았고, 닫는 과정에서
같은 틈이 하나 더 있었다는 것을 발견했다.**

### 무엇이 열려 있었나 — 두 겹

**틈 1: 페이로드.** `rebake-payload` 잡이 `vercel-production-deploy.yml`(트리거 `workflow_dispatch`
하나뿐) 안에만 있었다. 그런데 Vercel Git 자동배포가 살아 있어 `main` push 마다 배포가 나간다.
→ 재생성은 **수동 실행 배포에만** 붙고 평상시 머지 경로에는 안 붙었다.

**틈 2: 프론트 별칭.** `verify-production.ts` 를 붙인 첫 실측에서 곧바로 걸렸다.
백엔드 정규 도메인은 **프로젝트 도메인으로 등록돼 있어** Vercel 이 자동 할당한다.
프론트 정규 도메인은 **그냥 별칭**이라 `alias set` 스텝이 붙여줘야 한다.
→ **Git 자동배포는 프론트 별칭을 옮기지 않았다.** 머지 직후 실측:

```
프론트 최신 프로덕션 배포   READY · 커밋 4653190f · 별칭 0개
프론트 정규 도메인          1시간 반 전 빌드 (dpl_A3gJeVqx…, 15:03Z)
buildId                     정규 bd2mmusvXRD45Bco6elhc ≠ 최신 hTFMwPFrh0rn8vZBGJTwG
```

**#1076 과 같은 사고가 구조적으로 재발하고 있었다.** 페이로드만 보고 PART C 를 닫았다면 놓쳤다.

### 처리

`rebake-on-git-deploy.yml`(`push: [main]`) 3잡:

| 잡 | 하는 일 |
|---|---|
| `align-web-alias` | Vercel API 로 **이 커밋 SHA 와 일치하는 READY 프로덕션 배포**를 찾아 정규 도메인에 붙이고 확인. 못 찾으면 실패(엉뚱한 빌드 금지) |
| `rebake` | 버전 라우트를 폴링해 **정규 도메인이 이 커밋을 서빙할 때까지 기다린 뒤** 페이로드 재생성 |
| `verify` | `if: always()`. `verify-production.ts` 를 그대로 호출 — 검증 규칙을 복제하지 않는다 |

> **왜 배포를 기다리는가**: `push` 는 Vercel 빌드보다 먼저 발동한다. 그대로 굽면 **옛 코드가
> 페이로드를 만들고 `asOf` 만 새로워진다** — 검증은 통과하고 화면은 틀린, 가장 나쁜 위장된 통과다.

Deploy Hook(방향이 반대) · Vercel 웹훅→`repository_dispatch`(설정이 레포에 안 남고 PAT 을
Vercel 에 보관해야 한다) 대신 `push` 를 골랐다 — 전부 레포 안에 있고 이력이 Actions 에 남는다.

### 실측 검증 — "배선했다" 로 끝내지 않았다

| 머지 | 결과 |
|---|---|
| `4653190` (#1103) | 자동 트리거 → 배포 대기 2분 → 재생성 `published=10 ledgerAppended=1 ms=21571` → **verify exit 0** |
| `9197fbe` (#1104) | `Success! fomo-web-… now points to fomo-pqe2w2dcc-…` → 프론트 서빙 커밋 `9197fbe7` 확인 → 재생성 200 → **verify exit 0 (4/4 통과)** |

였고 스크립트가 **exit 1** 로 그 조건을 정확히 지목했다. 그 뒤 재생성으로 **exit 0** 이 됐다.
