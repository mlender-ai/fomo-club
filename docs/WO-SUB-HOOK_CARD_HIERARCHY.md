# WO-SUB-HOOK — 카드 위계·훅 재설계 (실행 기록)

| 항목 | 값 |
|---|---|
| 성격 | UI 위계 재설계 + 카피 재작성 + 렌더 결함 수정 |
| 진단 | 2026-08-14 화면 실측(카드 3장 + 디테일 1장) D1~D9 |
| 원칙 | **정보를 더 넣는 게 아니라 덜어내고 재배치한다** |

이 문서는 WO 본문(광혁 지시)의 실행 기록이다. 무엇을 왜 그렇게 고쳤는지와, 어떤 테스트가
그것을 지키는지를 한 장에 둔다. 카피·위계 결정은 WO 가 정본이고 여기서 바꾸지 않는다.

## 1. 훅 — 나열에서 한 문장으로 (D1·D3 / PART 1)

종전 훅은 이례성 문구를 em-dash 로 이어 붙였다.

```
전  기관이 25일 연속 — 최근 40거래일 중 가장 길어요 — 거래가 평소의 25%로 말라 있던 자리예요
후  기관이 25일째 조용히 사고 있어요
```

역할을 갈랐다.

- **훅** = 무슨 일이 일어났나 한 문장(주체 · 지속 · 매수). `buildQuietPickHook`
- **칩** = 훅이 말하지 않는 근거. 서로 다른 축 최대 3개. `buildQuietPickChips`

침묵 지표만 있는 종목의 훅이 `거래량도 안 늘었어요`(부정문)였던 것도 여기서 사라진다 —
훅은 이제 이례성 목록이 아니라 신호 자체에서 만들어지므로 항상 "무엇이 일어났는지"로 시작한다.

**골든 케이스 3건**은 `packages/fomo-core/__tests__/quiet-pick-hook.test.ts` 에 그대로 고정했다.

| 종목 | 훅 | 칩 |
|---|---|---|
| 빅텍 | 기관이 25일째 조용히 사고 있어요 | 40거래일 중 최장 · 거래량 평소의 25% · 기관 74주 |
| 한미반도체 | 외국인과 기관이 4일째 같이 사고 있어요 | 거래량은 그대로 · 47만주 · 4일 연속 |
| Amrize | 임원 7명이 사흘 새 같이 샀어요 | $3.6M · 52주 저점 +1% · 최근 3일 |

칩 축 순서는 신호 종류가 정한다 — 임원 매수는 금액이 먼저 읽히고(`size → unusual → …`),
연속 매수는 "얼마나 드문가"가 먼저 읽힌다(`unusual → position → …`).

### H4 를 어디까지 강제했나

"칩에 들어가는 숫자를 훅에 반복하지 않는다"는 **축 단위로** 강제한다. 훅이 가진 축(주체·인원·
지속)은 이례성 칩으로 만들지 않는다. 다만 축이 두 개뿐일 때 지속 칩(`4일 연속`)으로 세 번째를
채운다 — 골든 케이스 2·3이 그 형태이고, 숫자 단위로 금지하면 그 두 건을 구현할 수 없다.
숫자 반복의 상한은 **완료 조건 3**(한 화면에 같은 숫자 3회 미만)이 지키고, 테스트도 그것을 본다.

## 2. 카드 앞면 — 3단 위계와 가변 높이 (D4·D5 / PART 2)

```
[1순위] 훅 한 줄        22px bold
[2순위] 칩 3개
[3순위] 스파크라인 · 맥락 한 줄(슬롯 ②③)
[4순위] 되돌아보는 선   회색 12px 한 줄, 박스 없음
```

- 무효선 박스 제거 → 회색 한 줄(`되돌아보는 선 · …`). 계약이라 지우지 않지만 1순위처럼 보이면 안 된다.
- 스파크라인 캡션 `◆ 돈이 들어오기 시작한 자리` → `◆ 사기 시작한 시점`.
- 서브라인은 훅과 같은 일수면 렌더하지 않는다(`quietPickSubLine`).
- 신호 라벨 칩(`내부자 클러스터`)은 삭제. 주체는 훅이 말한다.

**D5 의 진짜 원인은 조건부 렌더가 아니라 무대였다.** 덱이 `h-[540px]` 고정에 카드가
`absolute inset-0` 이라, 슬롯이 없는 카드도 540px 를 차지했다. 이제 앞 카드가 문서 흐름 안에
있고 무대 높이가 카드를 따라간다. 카드 최소 높이는 슬롯 조합이 정한다
(`apps/fomo-web/lib/quietCardLayout.ts`, 스냅샷 4종: 372 / 404 / 480 / 512).

## 3. 디테일 — 순서와 중복 (D2 / PART 3)

새 순서: **무슨 회사인가 → 왜 지금인가 → 최근 무슨 일 → 값의 위치 → 차트 → 이게 틀리는 경우 → 기록.**

- 훅은 화면에서 **한 번만** 나온다. "얼마나 이례적인가"는 `얼마나 드문가`로 바뀌고 훅에 포함된
  문장은 제외한다.
- "어떤 회사예요"는 벤더 원문을 그대로 쓰지 않는다(`rewriteCompanySummary`) — 설립·상장 연혁
  문장을 버리고 `~하였음`을 해요체로 바꾼다. **원문은 "출처 보기"로 접어 둔다.**
- 기록의 빈 대시 `7일 — 30일 —` → `7일 아직 · 30일 아직` + `발행한 지 얼마 안 돼 아직 채점 전이에요`.

### D9 확인 결과 (등재)

네이버 금융 일별 투자자 순매매(KRX 확정치 재공개)의 순매매 컬럼 단위는 **주식 수**다
(`packages/fomo-core/src/supply-demand.ts`). 빅텍의 `74주`는 25거래일 누적 순매수 실값이고,
소형주에서 기관 순매수가 낱주로 찍히는 것은 정상이다. 표기 규칙은 하나다 —
**1만주 이상은 만주로 반올림, 미만은 낱주 그대로**(`formatShares`, 테스트 고정).

남은 질문은 표기가 아니라 **신호 임계**다. "25일 연속 74주(약 22만원)를 신호로 볼 것인가"는
카피·렌더가 아니라 신호 산출 규칙의 문제이고, 이 WO 는 문자열 조립부만 손대므로(§1-3)
여기서 바꾸지 않는다. **별건으로 등재한다.**

## 5-1. 배치 시차 — 머지가 화면을 바꾸지 않는 구간

배포 직후(2026-08-14 01:02 UTC) 프로덕션 API 를 읽어 보니 여전히 옛 문장이 나왔다.

```
GET https://fomo-club-backend.vercel.app/api/fomo/quiet-picks
"hook":"기관이 25일 연속 — 최근 40거래일 중 가장 길어요 — 거래가 평소의 25%로 말라 있던 자리예요"
"asOf":"2026-08-13T21:36:11Z"
```

픽 payload 는 **하루 한 번 크론(21:25 UTC)이 구워** `feed-content` 에 저장한다. 렌더는 저장된
것을 읽는다. 즉 코드 배포만으로는 화면이 바뀌지 않고, 다음 배치까지 옛 문장이 남는다.
배치 실행은 이 WO 범위가 아니다(`하지 않을 것`).

그래서 **읽는 쪽에서 고친다** — `apps/fomo-web/lib/pickCopyRepair.ts`.

- `repairPickCopy` — 사전 치환(내부자→임원, 관점은 무효→다시 봐야 해요, 매집 제거, 자리→시점).
- `pickHook` — 옛 훅이면 **payload 의 신호(주체·인원·일수)만으로** 한 문장을 다시 만든다.
  옛 훅 판정은 `em-dash · 금지어 · 주체 없음` 셋 중 하나다. 새 훅은 반드시 주체를 말하므로
  (코어 테스트가 그 불변식을 지킨다) 부정문 훅 `거래량도 안 늘었어요` 도 여기서 걸린다.

없는 사실을 만들지 않는다 — 복구는 payload 가 이미 들고 있는 값만 쓴다. 다음 배치가 돌면
새 payload 에는 걸릴 문자열이 없어 이 shim 은 아무 일도 하지 않는다(제거는 그때 별건으로).

실측 3건이 복구되는 것을 테스트로 고정했다(`pickCopyRepair.test.ts`) — 픽스처는 위 응답에서
그대로 가져왔다.

### 남은 것 — 정규 도메인이 최신 배포를 안 가리킨다 (사람 조치 필요)

`fomo-web-mlender-ais-projects.vercel.app` 는 **옛 빌드를 서빙한다**(빌드 ID
`xkBrVY9DbAY2QO_bxtrzJ`, 새 라우트에 404). Git 연동은 main 머지마다 `target: production`
배포를 만들지만 **정규 별칭을 옮기지 않는다** — 별칭은 `vercel-production-deploy.yml` 의
`vercel alias set` 단계만 옮기고, 그 워크플로는 `workflow_dispatch` 전용이다.

이 세션의 GitHub App 토큰에는 `actions:write` 가 없어 dispatch 가 403 이고, egress 정책이
`*.vercel.app` 을 막아 CLI·브라우저 접근도 불가하다. **광혁이 워크플로를 한 번 돌려야
사용자 화면이 새 빌드가 된다**:

```
gh workflow run vercel-production-deploy.yml -f ref=main
```

이건 이 WO 만의 문제가 아니다. #1069~#1073 도 같은 경로로 머지됐으므로, 그 사이 배포들도
정규 도메인에 반영됐는지 같이 확인하는 편이 낫다. **자동 배포와 정규 별칭이 갈라져 있다는
사실 자체가 등재 대상이다** — "머지했으니 배포됐다"가 성립하지 않는 구조다.

### 카피의 배치 시차

훅·칩은 위 shim 으로 즉시 새 문장이 되지만, **payload 자체**는 21:25 UTC 크론이 다시
구울 때 바뀐다. 그때 shim 은 아무 일도 하지 않게 되고, 그 시점에 프로덕션 API 를 다시 읽어
`hook` 필드가 한 문장인지 확인하면 배치 경로까지 닫힌다.
