## 0. 먼저 — 왜 6번 돌렸는가

1~4차 결과를 그대로 문서화했다면 **거짓이 박제됐을 것이다.** 0%로 나온 셀의 상당수가 데이터 부재가 아니라 프로브의 결함이었다.

| 회차 | 발견된 결함 | 그대로 적었다면 |
|---|---|---|
| 1차 | 응답 키를 추측으로 지정 | KR 시총·업종·사업설명 "0% 확보" |
| 2차 | 키 덤프로 대조 → 다수 오판 확인 | — |
| 3차 | KR 매출에 근거 없는 조건(`periodCount>=4`) | "매출만 확보 0%" |
| 4차 | SEC CIK 매핑 403 → CONTROL 전 필드 n=0 | "대형주 재무 확보 0%" |
| 5차 | 예외 1건이 종목 전체 조회를 중단 | US 표본이 필드별로 들쭉날쭉 |
| 6차 | §4-1 상향 편향 점검 | — |

**교훈**: 확보율을 세기 전에 응답 구조를 덤프해 근거를 만들어야 한다. 이 순서를 지키지 않은 것이 재작업의 원인이었다.

### 중요한 실측 사실 세 가지

**① KR 사업 설명이 이미 있다 (44/45).**
네이버 `finance/quarter → corporationSummary.comment1~3`이 한국어 3문장 요약을 준다. 예(종근당):
> "동사는 2013년 종근당홀딩스에서 의약품사업부문을 인적분할하여 설립된 국내 대형 제약사임." / "전문의약품 및 일반의약품 사업을 영위하며…" / "연간 매출액 대비 약 9~11%의 R&D 투자를 통해…"

1차 프로브는 이 필드를 하드코딩 `false`로 두고 있었다. 그대로 갔다면 WO-SUB-03을 "KR은 소스가 없으니 LLM 합성" 으로 잘못 설계했을 것이다.

**② 매출 컨센서스는 무료 경로 어디에도 없다 (전 그룹 0).**
Nasdaq `analyst/earnings-forecast`는 **EPS 예상만** 제공한다(CONTROL 11/11 확보). 네이버 `consensusInfo`는 투자의견 평균·목표주가뿐이며, 목표주가는 우리 원칙상 사용 금지 값이다.

**③ KR EPS 컨센서스는 미확인이다.**
네이버 `trTitleList[].isConsensus` 플래그가 있지만 **6개 컬럼 전부 `true`**로 나온다. "예상치 컬럼"을 뜻한다고 볼 근거가 없어 확보로 세지 않았다.

## 4. DART — 미확인 (49건)

`DART_API_KEY` 시크릿이 비어 있어 정기공시 경로를 **한 번도 조회하지 못했다.**
따라서 "KR 사업보고서 본문 파싱 가능 여부"는 이 실사에서 **판정하지 않는다.**

조치: 레포 Settings → Secrets and variables → Actions 에 `DART_API_KEY` 등록 후 워크플로 재실행하면 자동 반영된다(코드 변경 불필요).

## 5. 갱신 지연

프로브가 SEC XBRL 최신 분기 종료일(`latestPeriod`)을 원본 JSON에 기록한다. 다만 **지연일수를 그룹 단위로 집계하는 로직은 넣지 않았다.** 이 항목은 미완이며, WO-SUB-01(팩트시트) 착수 시 백필 스크립트에서 함께 측정하는 것이 자연스럽다.

---

## 6. 비용·라이선스

이번 실사는 **무료·무인증 소스만** 사용했다(SEC XBRL, Nasdaq 공개 API, 네이버 종목 API). 상용 API 가격 조사는 수행하지 않았다 — 컨센서스가 유일한 결손 축인데, 그 필요 여부는 WO-SUB-04의 범위 결정 이후에 판단하는 것이 순서다.

**주의**: 네이버·Nasdaq 응답의 재배포 라이선스는 확인하지 않았다. 화면 표시를 넘어 데이터셋 형태로 제공할 계획이 생기면 별도 검토가 필요하다.
