# 의존 변수 카탈로그 (WO-SUB-03 §4-6)

| 항목 | 값 |
|---|---|
| 정본 | `packages/fomo-core/src/business-context/dependency-variables.ts` |
| 소비자 | 슬롯 3 "그 대상은 지금 어떤 상태인가" |

---

## 1. 왜 카탈로그인가

슬롯 3 은 **자유 서술 금지**다. 슬롯 2 가 지목한 의존 대상을 이 표에 매핑하고, 매핑에 실패하면
슬롯 3 을 렌더링하지 않는다. 카탈로그 없이 즉석에서 변수를 만들면 "무엇에 걸려 있나"가
근거 없는 서술로 바뀐다.

매핑은 **키워드 사전 매칭이고 결정론**이다(LLM 없음). 여러 변수가 걸리면 슬롯 2 문장에서
**앞에 나온** 키워드의 변수를 쓴다 — 문장의 주된 의존 대상이 앞에 온다.

## 2. 문장 템플릿 — 인과 없음

```
{변수명}{은/는} {기준일} 기준 {값}입니다. ({기간} {방향})
```

인과를 쓰지 않는 이유는 규칙이기도 하지만 **사실**이기도 하다 — 우리는 이 변수가 이 회사 실적을
움직였다는 것을 증명할 수 없다. 시점 병기까지가 우리가 말할 수 있는 전부다.

조사는 받침으로 고르되 **괄호 표기는 건너뛴다** — "국제유가(WTI)은"이 되는 실패를 막는다.

방향은 3개월 전 값과 비교하며, 상대 변화가 ±2% 미만이면 "보합"이다. 소수점 흔들림을
"상승/하락"이라 쓰지 않기 위한 것이다.

가짜 숫자를 만들지 않는다.

## 4. 미확보 축이 남은 이유

원자재 현물가(DRAM·철강·구리·운임)는 무료·재배포 가능한 소스를 확보하지 못했다.
이 변수들은 **시클리컬 종목의 슬롯 2 가 가장 자주 지목하는 대상**이라, 슬롯 3 결손이
`CYCLICAL_COMMODITY` 에 몰린다. 유료 소스 검토는 WO-SUB-04 범위 결정 이후가 순서다.

`ai_capex_proxy` 는 빅테크 capex 합계라 분기 공시에서 조립해야 한다 — 파생 지표이므로
카탈로그에 두되 소스는 비웠다.

## 5. 변수를 추가할 때

1. **값을 실제로 가져올 수 있는지 먼저 확인한다.** 소스 없는 변수를 늘리면 매핑률은 오르고
   슬롯 3 채움률은 그대로다 — 지표가 좋아 보이고 화면은 그대로인 최악의 조합이다.
2. 키워드는 **슬롯 2 문장에 실제로 등장하는 표기**로 넣는다. 골든셋 리포트의 슬롯 2 문장을 보고 정한다.
3. 추가 후 `business-context.test.ts` 의 매핑 테스트에 케이스를 넣는다.
