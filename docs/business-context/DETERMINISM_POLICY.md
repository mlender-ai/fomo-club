# LLM 결정론 정책 (WO-SUB-03.5 PART C-2)

> **원칙 7(결정론)을 재해석한다.**
> "같은 입력에 같은 출력이 나온다" → **"같은 입력에 저장된 출력을 쓴다."**
> 외부 LLM 에 의존하는 한 전자는 보장할 수 없다. 이 문서는 그 한계와 대응을 명시한다.

작성일: 2026-07-25 · 대상: `business-context`(사업 실체 3슬롯) 합성 파이프라인

---

## 1. 왜 "온도 0 확인"은 결정론이 아닌가

WO-SUB-03 은 온도 0에서 동일 출력을 확인했다. 그것은 **한 세션 내 반복 실행 결과**다.

| 바뀌면 출력이 바뀌는 것 | 우리가 통제하는가 |
|---|---|
| 프롬프트 본문 | ✅ `prompt_version`(본문 해시) |
| LLM 입력(청크 선택·예산) | ✅ `input_hash` (이 WO 에서 추가) |
| **모델 가중치** | ❌ 제공자가 갱신한다 |
| 추론 스택(양자화·커널·배치) | ❌ 제공자가 갱신한다 |

즉 우리가 아무것도 바꾸지 않아도 **제공자가 모델을 갱신하면 같은 입력에 다른 문장이 나온다.**
"재현성"을 원칙으로 두면 지킬 수 없는 약속이 되고, 지킬 수 없는 약속은 게이트로 쓸 수 없다.

---

## 2. 정책 — 재현성이 아니라 불변성

```
동일 (input_hash, prompt_version, model) 조합에 대해 저장된 출력이 있으면
재호출하지 않고 그대로 사용한다.
재생성은 명시적 무효화 명령으로만 발생한다.
```

### 구현 위치

| 요소 | 위치 |
|---|---|
| `input_hash` 계산 | `apps/web/lib/business-context/build.ts` `computeInputHash()` |
| 레코드 필드 | `packages/fomo-core/src/business-context/types.ts` — `input_hash`·`prompt_version`·`model`·`synthesized_at` |
| 재합성 판정 | `apps/web/lib/business-context/repository.ts` `needsResynthesis()` — 프롬프트 버전 · 문서 해시 · **모델** |
| 불변 재사용 게이트 | 같은 파일 `isImmutablyReusable()` |
| 명시적 무효화 | `refreshBusinessContexts({ force: true })` — 크론/워크플로 파라미터 |

`input_hash` 는 **LLM 에 실제로 들어간 것만** 해싱한다: `canonical` · `archetype` ·
`revenueSummary` · 예산 통과 청크(`source_id:text`). 문서 스냅샷 해시로는 부족하다 —
청크 예산이 3,500자에서 24,000자로 바뀌면 문서는 그대로인데 입력은 완전히 달라진다.
그 변경이 해시에 잡히지 않으면 낡은 출력을 새 설정의 산출물로 오인한다.

### 모델 축을 판정에 넣은 이유

`needsResynthesis` 는 모델이 바뀌면 재합성을 요구한다. 저장본을 그대로 쓰면
**다른 모델이 만든 문장을 현재 모델의 산출물로 표기**하게 된다. 그건 `model` 필드를 거짓으로 만든다.

단, 기존 레코드의 `model` 이 빈 문자열인 경우(= LLM 호출 자체가 실패해 `emptyContext` 로 남은 레코드)는
이 축으로 판정하지 않는다. 빈 값과 모델 변경은 다른 사건이다.

## 3. 모델 핀 — 가능한 범위와 한계

WO 는 "별칭이 아니라 버전이 특정되는 식별자를 쓰고, 불가하면 그 사실을 기록"하라고 했다.

### 현재 상태

| 항목 | 값 | 성격 |
|---|---|---|
| 기본 모델 | `llama-3.3-70b-versatile` (`DEFAULT_GROQ_MODEL`) | **별칭** |
| 오버라이드 | `GROQ_MODEL` / `AI_MODEL` env | 별칭 또는 임의 식별자 |
| 응답 기록 | `callAI` 가 실제 사용 모델을 반환 → 레코드 `model` 에 저장 | 실측값 |

### 판정: 날짜 핀은 불가능하다

Groq 가 이 모델에 대해 `llama-3.3-70b-versatile-2025xxxx` 형태의 **날짜/버전 고정 식별자를 제공하지 않는다.**
`llama-3.3-70b-versatile` 자체가 제공자가 관리하는 롤링 별칭이다. 따라서:

- **핀할 수 없다는 사실을 기록한다** (이 문서 §3 이 그 기록이다)
- 대신 **레코드에 실제 응답 모델 문자열을 남긴다** — 제공자가 별칭 뒤 가중치를 바꿔도
  식별자가 함께 바뀌면 `needsResynthesis` 가 잡는다
- 식별자를 바꾸지 않고 가중치만 교체하는 경우는 **탐지할 수 없다**. 이것이 이 파이프라인의
  남은 결정론 구멍이고, 불변성 정책(§2)이 그 영향을 "저장본을 계속 쓴다"로 봉쇄하는 이유다

### 모델을 바꿀 때 규칙

1. `GROQ_MODEL`/`AI_MODEL` 을 바꾸면 `needsResynthesis` 가 전량 재합성을 요구한다 — 비용이 발생한다
2. 바꾸기 전에 골든셋(`EVAL_golden30.md`)을 새 모델로 재측정한다. 모델 교체는 품질 변경이다
3. 교체 사실을 `AC_DEBT_LEDGER.md` 가 아니라 이 문서 §5 변경 이력에 남긴다

## 4. 이 정책이 보장하는 것 / 보장하지 못하는 것

| 보장한다 | 보장하지 못한다 |
|---|---|
| 같은 설정에서 화면이 매일 같은 문장을 보여준다 | 같은 입력을 새로 호출하면 같은 문장이 나온다 |
| 입력·프롬프트·모델이 바뀐 것을 놓치지 않는다 | 제공자가 식별자 없이 가중치를 바꾼 것을 탐지한다 |
| 비용이 통제된다(변경 없으면 LLM 0콜) | 과거 문장을 지금 모델로 재현한다 |

**"재현 불가"를 숨기지 않는다.** 사용자에게 보이는 문장은 `synthesized_at` 시점의 산출물이고,
그 시점의 `model`·`prompt_version`·`input_hash` 가 레코드에 함께 남는다.
