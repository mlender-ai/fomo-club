# 시클리컬 슬롯 3 결손 — 측정 시도와 차단 사유 (WO-SUB-03.5 PART E-3)

> WO 의 전제: "원자재 현물가 소스 미확보로 슬롯 3 결손이 `CYCLICAL_COMMODITY` **에 집중**된다.
> 프레임이 가장 필요한 유형에서 값이 가장 안 붙는다."
> **측정해보니 전제가 성립하지 않는다 — 집중이 아니라 전 유형 0 이다.**

작성일: 2026-07-25

---

## 1. E-3 §1 요구 — 아키타입별 슬롯 3 확보율

산출 시도 결과: **측정 불가.** 두 가지가 동시에 막는다.

### (1) 슬롯 3 이 전 유형에서 0 이다

`golden30_raw.json`(30종목) 실측:

| 구분 | n | 슬롯1 | 슬롯2 | 슬롯3 |
|---|---|---|---|---|
| 전체 | 30 | **1** | **0** | **0** |

배지 분포: `없음` 29 · `낮음` 1.

슬롯 3 은 슬롯 2(의존 대상)에 연쇄한다 — `buildSlot3(slot2.text, observations)` 이므로
슬롯 2 가 0 이면 슬롯 3 은 구조적으로 0 이다. **"시클리컬에 몰린 결손"이 아니라
어느 유형에서도 슬롯 3 이 생성된 적이 없다.** 분포를 낼 모집단 자체가 없다.

### (2) 레코드에 아키타입이 없다

`BusinessContext` 레코드 필드:

```
canonical, market, synthesized_at, prompt_version, model,
slot1_revenue_source, slot2_dependency, slot3_dependency_state,
badge, insufficient_reason, documents, cited_chunks, errors
```

아키타입은 **합성 프롬프트의 맥락 입력으로만 쓰이고 저장되지 않는다**
(`build.ts` 에서 `classifyArchetype(...).code` 를 구해 프롬프트에 넣고 버린다).
따라서 슬롯 확보율을 아키타입별로 쪼개는 것이 애초에 불가능하다.

→ **이 WO 에서 `archetype` 을 레코드에 추가**했다(§4). 다음 골든셋 실행부터 측정이 가능해진다.

## 2. 왜 0 인가 — 원인은 슬롯 3 이 아니라 상류에 있다

`EVAL_input_size_impact.md` §2·§5 와 같은 원인이다.

```
429 (페이싱 없음)        → 30종목 중 23종목이 합성 호출 실패
청크 예산 3,500자        → 합성이 돌아간 종목도 근거 중위 89% 손실
                            (Rhinebeck 122개 → 2개)
     └ 슬롯2 0/30 → 슬롯3 0/30
```

**원자재 현물가 소스 부재는 슬롯 3 이 0 인 현재 원인이 아니다.**
그것은 슬롯 2 가 채워진 다음에야 드러나는 2차 제약이다. 지금 0 인 이유는 상류 차단이다.
소스 확보 여부를 논하기 전에 페이싱·입력 크기가 해결돼야 같은 질문을 다시 물을 수 있다.

## 3. E-3 §2 요구 — 원자재 가격 없이 사이클 위치를 전달할 수 있는가

측정은 막혀 있지만 **설계 검토는 지금 할 수 있다.** WO 의 제안은
"슬롯 3 대신 경고문 + 8분기 영업이익 추이"다.

### 이미 확보된 재료

| 재료 | 상태 | 위치 |
|---|---|---|
| `CYCLICAL_COMMODITY` 경고문 | **있음** | `doctrine.json` `warning_short`/`warning_full` |
| 8분기 영업이익 | **US 확보 / KR DART 로 열림** | 팩트시트 `fiscal.quarters` |
| `margin.operating_stdev_annual` | 있음(분류에 이미 사용) | 팩트시트 |
| 원자재 현물가 | **없음**(무료 소스 부재) | — |

경고문 실문안:

> `warning_short`: 이 유형은 이익이 정점일 때 PER이 가장 낮게 나옵니다.
> `warning_full`: 이 유형은 이익이 정점일 때 PER이 가장 낮게 나오는 경향이 있습니다.
> 지금의 낮은 PER은 값의 위치보다 이익의 위치를 반영하고 있을 수 있습니다.

### 검토 결론 — 대체가 아니라 보완이다

경고문 + 8분기 이익 추이는 **"지금 이익이 사이클의 어디쯤인가"를 관측값으로 전달**할 수 있다.
경고문이 "낮은 PER 은 이익 정점의 신호일 수 있다"고 말하고, 8분기 추이가 그 이익이
올라가는 중인지 꺾였는지를 보여주면, 유저는 PER 을 거꾸로 읽는 함정을 피할 수 있다.
**이 조합에는 원자재 가격이 필요하지 않다** — 이익 자체가 사이클의 결과이기 때문이다.

다만 이것은 슬롯 3 의 **대체가 아니다.**

| | 슬롯 3(원자재 현물가) | 경고문 + 8분기 이익 추이 |
|---|---|---|
| 답하는 질문 | "걸려 있는 그 대상이 지금 어떤 상태인가" | "이 회사 이익이 사이클의 어디쯤인가" |
| 선행성 | 이익보다 **앞선다**(가격 → 실적 반영에 1~2분기) | **후행**(이미 실적에 찍힌 결과) |
| 결손 시 | 프레임 없음 | 프레임 제공 가능 |

**슬롯 3 이 값을 전달하는 것과 이익 추이가 위치를 암시하는 것은 다른 정보다.**
후자는 전자가 없을 때의 **차선(fallback)** 으로 독트린에 명시해야 하고,
"슬롯 3 를 채웠다"고 표기하면 안 된다(배지가 거짓이 된다).

### 독트린 반영 제안 (사람 승인 필요)

`CYCLICAL_COMMODITY` 프레임에 폴백 규칙을 추가한다.

```
slot3 가 null 이고 archetype == CYCLICAL_COMMODITY 인 경우:
  - warning_full 을 노출한다(현재도 노출)
  - 8분기 영업이익 추이를 "관측값"으로 병치한다
  - 배지는 올리지 않는다 — 슬롯 3 은 여전히 결손이다
```

**독트린 정본(`doctrine.json`) 변경은 사람 판정 사항**이라 이 WO 에서 코드로 넣지 않았다.
문안·배지 정책은 WO-SUB-02 §12 와 같은 검토 경로를 따라야 한다.

## 4. 이 WO 에서 실제로 한 것

- `BusinessContext.archetype` 추가 — 다음 실행부터 아키타입별 슬롯 확보율이 측정 가능
- 측정 불가 사유를 추정이 아니라 **원본 로그로** 기록(§1·§2)
- 원자재 없는 프레임 대안을 검토하고 **"대체 아님"을 명시**(§3)
