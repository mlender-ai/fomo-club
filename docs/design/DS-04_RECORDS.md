# DS-04 — 성적표 · 내 기록 탭

| 항목 | 값 |
|---|---|
| 선행 | DS-00 |
| 주의 | **현재 데이터가 거의 비어 있다.** 빈 상태 설계가 이 문서의 절반이다 |
| 상태 | **v2 화면 정본 (2026-08-20 등재·구현).** 구현 대상: `apps/fomo-web/app/track-record/page.tsx`, `components/MyRecordTab.tsx` |
| 권위 | 두 탭의 구성·절대 규칙은 이 문서가 최상위. 토큰은 DS-00, 하단 탭 셸은 DS-02 |

---

## 1. 성적표 탭

### 1-1. 현재 상태 (실측)

- 가격 무효선 30건 **전부 판정 불가** (7일 창 미도래)
- 사업 무효 조건 28건 중 판정 불가 12건
- T+30 채점 표본 부족

**즉 지금 성적표를 열면 거의 빈 화면이다.** 이걸 정직하게 보여주되 고장처럼 보이지 않게 하는 것이 설계 과제다.

### 1-2. 구조

```
성적표 / 우리가 짚은 뒤 얼마나 움직였나
① 채점 결과      30일 후 중앙값 · 상승 비율 · 판단 수 + 기간 토글
② 아직 채점 전    채점 대기 N건 · 첫 판단 · 첫 채점 예정일
③ 그동안 이건     짚은 뒤 지금까지 변동 (채점 결과 아님)
④ 무효 조건      도달 · 미도달 · 사업 조건 충족 · 판정 불가
⑤ 짚은 픽        최신순 (구분선 리스트)
```

### 1-3. 스펙

| 요소 | 스펙 |
|---|---|
| 탭 제목 | `title-lg` 20/500 |
| 섹션 제목 | `label` mono, `text-2`, letter-spacing 0.06em |
| 대표 지표 | `data` mono 28/500, **accent** (화면당 1회) |
| 보조 지표 | `data` mono 16, `text-1` |
| 라벨 | `label` mono 12, `text-2` |
| 표본 수 | **항상 병기.** `caption` mono, `text-3` |
| 기간 토글 | 세그먼트, height 36px, 활성 `surface-2` |

### 1-4. 절대 규칙

| 규칙 | 내용 |
|---|---|
| 표본 30 미만 | **비율을 표시하지 않는다.** `표본 부족 (12건)` 으로 대체 |
| 판정 불가 | 분모에서 빼지 않는다. 별도 행으로 노출 |
| 평균 금지 | 중앙값 + 분포. 평균은 소수 대박이 왜곡한다 |
| 폐지·정지 종목 | 집계에서 제외하지 않는다 |
| 나쁜 성적 | 그대로 표시한다 |

### 1-5. 빈 상태 — 가장 중요

**핵심**: 채점은 안 끝났어도 **"짚은 뒤 지금까지 얼마나 움직였나"는 지금 계산 가능하다.** 그걸 보여주면 빈 화면이 아니게 된다. 다만 **채점 결과와 명확히 구분**한다. `첫 채점 예정일`을 표시해 다시 올 이유를 만든다. 일러스트·아이콘 금지, 텍스트만.

## 2. 내 기록 탭

관심으로 등록한 종목과 그 이후 변동 + 본 카드(날짜별 장수). 두 섹션뿐이다.

| 요소 | 스펙 |
|---|---|
| 행 | 구분선 리스트 (카드 아님) |
| 종목명 | `body` 14/500, `text-1` |
| 코드 | `label` mono, `text-3`, 우측 |
| 등록일·변동 | `caption` mono, `text-2` |
| 변동률 | 최고 수익 종목 1개만 accent, 나머지 `text-1` |

빈 상태: `아직 관심 종목이 없어요` + 안내 한 줄 + CTA 하나(픽 탭). **일러스트 금지.**

---

## 3. 성적표 vs 검증실

지금은 성적표 탭이 그 역할을 겸한다. **새 탭을 만들지 않는다** — 3개가 하단 탭의 적정 상한이고, 지금 채울 데이터도 없다.

---

## 4. 완료 기준

1. 표본 30 미만 항목이 비율 대신 `표본 부족 (N건)`으로 표시된다
2. 판정 불가가 분모에서 빠지지 않는다
3. 표본 수가 모든 지표에 병기된다
4. 성적표 빈 상태에서 **"짚은 뒤 현재까지 변동"**이 표시된다
5. 채점 결과와 현재 변동이 명확히 구분된다
6. 첫 채점 예정일이 표시된다
7. 각 탭에 accent가 1회만 있다
8. 일러스트·아이콘이 없다

## 5. 구현 결과 — 2026-08-20 실측 (375px·1280px)

| 완료 기준 | 결과 |
|---|---|
| 1. 표본 게이트 | ✅ `rateOrSampleShort()` — 29건이면 `표본 부족 (29건)`, 30건부터 비율. `packages/lab` 의 `MIN_SAMPLE`(INV-C13)과 같은 값 |
| 2. 판정 불가 | ✅ 도달·**미도달**·사업 충족·판정 불가 4행 + `분모에서 빼지 않아요`. 실측 `도달 4 / 미도달 57 / 충족 9 / 판정 불가 119 (판단 162건)` |
| 3. 표본 병기 | ✅ 모든 지표 값 아래 `판단 N건`. 표본 부족 시 `30건부터 비율을 내요` |
| 4·5. 짚은 뒤 변동 | ✅ 별도 섹션 `그동안 이건 볼 수 있어요` → `변동 중앙값 +1.1% / 대상 13곳` + `채점 결과가 아니라 현재 시점 변동이에요` |
| 6. 첫 채점 예정일 | ✅ `첫 판단 8월 17일` · `첫 채점 예정 8월 24일`(첫 발행일 + 7일, 지났으면 미표시) |

## 6. 판정 기록

| 항목 | 판정 |
|---|---|
| `미도달` 행 추가 | DS-04 §1-2 목업은 3행이지만 **무효 조건 정직성 규칙**(WO-SUB-07 §6-4)이 도달·미도달·판정 불가를 모두 요구하고 그 회귀를 테스트가 감시한다. 게이트를 약화시키지 않고 행을 하나 더 뒀다 |
| 규칙 버전 분포 | 같은 이유로 `caption` 한 줄 유지(감사 근거) |
| `평균 변동` → `변동 중앙값` | §1-5 목업은 `평균 변동`, §1-4 는 `평균 금지`. **규칙이 목업 라벨을 이긴다** — 중앙값으로 계산하고 라벨도 그렇게 썼다 |
| 같은 종목 여러 번 발행 | `sinceMove` 는 **가장 오래된 발행가로 한 번만** 센다. 세 번 발행했다고 성적이 세 배로 반영되면 안 된다 |
| 성적표 공유 이미지(캔버스) | **제거.** DS-04 구조에 없고, 네온 CTA 가 대표 지표 accent 와 경쟁했다. 필요하면 별건으로 되살린다 |
| 자산군·신호 유형·점수대 분해 | **제거.** 표본 30 미만이면 어차피 비율을 못 낸다(§1-4). 데이터가 쌓이면 §3 대로 성적표를 확장한다 |
| `KeywordHistory` | 파일은 남기고 라우팅에서 뺐다. mock 키워드 카드·요청함·후회 영수증이 섞여 있어 DS-04 §2 와 양립하지 않는다 |

## 7. 미해결

1. **기존 관심 종목은 변동이 안 나온다.** `priceAt` 을 이제 저장하므로 **이번 릴리스 이후 누른 것부터** 변동이 보인다. 이전 항목은 등록일만 나오고, 그 아래 `지금부터 누른 종목은 …` 안내를 둔다.
2. **본 카드는 서버 원장(세션) 기준이다.** 기기·세션이 바뀌면 장수가 리셋된다. 로그인 붙기 전까지 그렇다.
3. **`폐지·정지 종목 제외 금지`(§1-4)는 서버 집계의 몫이다.** 화면은 받은 값을 그대로 그린다 — 그 규칙은 `apps/web/lib/ledger` 쪽 테스트가 지킨다.
4. **성적표 픽 목록은 20건까지.** 그 이상은 페이지네이션이 필요하다(지금은 발행 자체가 적다).
5. **현재가 조회는 40건 상한**(벌크 라우트 제한). 발행이 40종목을 넘으면 `짚은 뒤 변동` 의 대상이 최근 40종목으로 제한된다 — 화면에 `대상 N곳` 으로 표시된다.
