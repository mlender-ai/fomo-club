# DS-05 — 결손·빈 상태

| 항목 | 값 |
|---|---|
| 선행 | DS-00 |
| 이유 | **이 제품은 결손이 정상 상태다.** 결손 처리가 곧 제품 품질이다 |
| 상태 | **v2 정본 (2026-08-20 등재·구현).** 전 화면 공통 규칙 |
| 권위 | 결손·빈 상태·오류·로딩 처리는 이 문서가 최상위. 화면별 배치는 DS-01~04 |

---

## 1. 결손 처리 3원칙

```
1  없는 것은 자리도 만들지 않는다     → 빈 헤더 금지
2  틀린 것보다 없는 것이 낫다        → 신뢰 안 되는 데이터는 숨긴다
3  "없다"와 "아직 모른다"를 구분한다  → 문구가 달라야 한다
```

## 2. 섹션 결손 — 숨김 vs 명시

| 섹션 | 결손 시 |
|---|---|
| 회사 설명 · 값(재무) · 매출 막대 · 밴드 위치 · 스파크라인 · 우리 기록 | **완전 숨김** |
| 종목 고유 리스크 | **명시** — `이 종목만의 리스크는 아직 못 찾았어요` |
| 무효 조건(사업) | **명시** — 가격 조건만 표시하고 사업 행 삭제 |

**판정 기준**: 사용자가 "왜 이게 없지?"라고 물을 만한 것만 명시한다. 나머지는 조용히 숨긴다.

## 3. 절대 금지

헤더만 있고 본문 없음 · 자기모순 문구 · 정보 없는 반복(`7일 아직 …`) · 고정 높이 공백 · 값 없는 대시(`—`) · 미확보를 0으로 표시.

## 4. 신뢰할 수 없는 데이터 — 섹터 오류

**지금 가장 심각한 신뢰 파괴 요인이다.** 실측: On Holding(스포츠화) → `화학`, 한화투자증권(증권사) → `코인`.

조치: ① 섹터 매핑 오류를 조사한다 ② 신뢰도를 판정할 수 없으면 섹터를 표시하지 않는다 ③ 분류 소스와 매핑 규칙을 문서화한다.

### 4-2. 같은 종류의 위험

종목명 축약(`On` vs `On Holding`) · 로고 품질 · 국기 이모지 · 단위 표기.

## 5. 로딩

스켈레톤(opacity 0.4↔0.7, 1.4s, 무한) · **스피너 금지** · 최소 표시 300ms.
덱은 카드 형태(블록 20/60/40) · 상세는 헤더 즉시 + 본문 4블록 · 성적표는 지표 행 3개.

## 6. 오류

| 상황 | 문구 | 액션 |
|---|---|---|
| 네트워크 실패 | `연결이 끊겼어요` | `다시 시도` |
| 서버 오류 | `잠시 후 다시 열어주세요` | `다시 시도` |
| 데이터 없음 | `오늘은 조용한 곳을 찾지 못했어요` | 없음 |
| 스테일 | 정상 표시 + `N시간 전 기준` | 없음 |

**`Error:` 접두사, 예외 문자열, 상태 코드를 노출하지 않는다.**

## 7. 덱이 짧은 날

개수를 그대로 표시한다. 숨기거나 지속 신호로 채우지 않는다. 3장 미만이면 `오늘은 조용한 곳이 적었어요`.

## 8. 완료 기준

1. 빈 헤더가 화면 어디에도 없다
2. 자기모순 문구가 없다
3. 섹터가 신뢰 불가일 때 표시되지 않는다
4. 결손 시 카드·섹션 높이가 실제로 줄어든다
5. 스켈레톤이 동작하고 스피너가 없다
6. 오류 문구에 기술 용어가 없다
7. `아직 못 찾았어요`(미확보)와 `없어요`(부재)가 구분되어 쓰인다
8. 덱이 짧은 날 개수가 그대로 표시된다

| 6. 오류 문구 | ✅ `연결이 끊겼어요`(offline) / `잠시 후 다시 열어주세요`(server) 구분 + `다시 시도`. 기술 용어 스캔 테스트 |

### 섹터 오류 — 원인 두 개를 찾았다

**① 섹터 자리에 "테마"를 넣고 있었다.**

```ts
// apps/web/lib/quiet-pick.ts#companyIdentity — 종전 1순위
const theme = front.signals.themeLabel?.trim();
if (theme && HANGUL.test(theme)) return theme;   // ← 회사 섹터가 아니라 오늘의 테마
```

`themeLabel` 은 테마 커버리지 엔진이 붙이는 **오늘의 테마 소속**이다(코인 테마·환율 테마…).
그래서 한화투자증권이 `코인` 이 됐다. **이 소스를 섹터에서 제거했다.**

**② 산업분류 매핑 순서가 뒤집혀 있었다.**

`Rubber & Plastics Footwear`(신발)가 `plastics` 패턴에 먼저 걸려 `화학` 이 됐다 — On Holding 사례.
신발·의류 규칙을 화학보다 **앞으로** 옮겼다. 순서가 규칙이라는 것을 테스트로 고정했다
(`apps/web/__tests__/lib/sector-mapping.test.ts`).

**③ 폴백 라벨을 없앴다.** `기타 업종`·`미국주식` 은 섹터가 아니다. 매핑이 없으면 빈 문자열이고,
화면은 섹터 줄을 그리지 않는다. `dataQuality.identity` 가 그 사실을 그대로 보고한다(발행은 막지 않는다).

**④ 클라이언트 게이트** — payload 는 하루 한 번 구워지므로 다음 배치까지 테마 라벨이 내려온다.
`trustedSector()` 가 테마·거시 라벨(코인·환율·금리·유가…)과 폴백 라벨을 걸러 **섹터 줄을 통째로 뺀다.**

### 종목명 축약 (§4-2)

`On Holding AG` → `On` 이었다. `Holdings?` 를 법인 접미와 같이 취급해 지웠기 때문이다.
사업어(`Holdings`·`Group`·`Trust`·`Partners`·`Company`)는 **지운 뒤에도 이름이 회사를 특정할 때만**
지운다(두 단어 이상 또는 5자 이상). 결과: `On Holding AG` → `On Holding`,
`Gbank Financial Holdings Inc.` → `Gbank Financial`.

## 10. 미해결

1. **오늘 화면의 `화학` 은 다음 배치까지 남는다.** 서버 매핑을 고쳤지만 payload 는 하루 한 번 구워진다. 클라이언트 게이트는 **테마 라벨**만 거를 수 있다 — `화학` 은 형태상 정상 섹터라 종목별 정답을 모른 채 막을 수 없다.
2. **섹터 전수 조사(§4-1 ①)는 관측된 것만 했다.** 실측에서 드러난 두 케이스(테마 오염·신발→화학)를 고쳤고, 나머지는 매핑 규칙 테스트로 회귀만 막는다. KR 은 큐레이션 사전(`sectorOf`)이라 상대적으로 안전하다.
3. **단위 표기(§4-2)** — `formatShares` 는 1만주 이상을 `만주` 로 쓴다(`919주` / `47만주`). 규칙은 이미 하나지만, 금액 표기(`$2.8M` vs `4.6억원`)는 통화별로 다른 관례를 따른다. 통일 여부는 결정 대기.
4. **로고** — 카드·상세에서 제거된 상태다(DS-01). 되살릴 때 품질 편차 처리(이니셜 폴백)를 별도 스펙으로.
5. **레거시 화면** — `FeedView`·`KeywordDepthPage` 는 아직 `불러오지 못했어요` 같은 옛 문구를 쓴다. DS 정본이 없어 손대지 않았고, DS 화면만 §6 문구로 통일했다.
