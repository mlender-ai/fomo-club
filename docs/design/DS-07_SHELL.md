# DS-07 — 카드 껍데기와 넘김 흐름 (구현 계약)

| 항목 | 값 |
|---|---|
| 선행 | DS-00(토큰), DS-01(메인 카드), DS-02(덱) |
| 원칙 | **모양은 종류마다 다를 수 있어도, 손가락이 닿는 자리는 하나다.** |
| 상태 | v1 정본 (2026-08-31 등재·구현) |
| 권위 | 카드 껍데기·CTA·상세 하단 바·덱 넘김 흐름은 **이 문서가 최상위**. 안쪽 내용은 DS-01(종목 카드)·각 카드 모듈이, 토큰은 DS-00 이 정한다 |

---

## 0. 왜 이 문서가 생겼나

DS-01 은 **종목 카드 한 종류**를 전제로 쓰였다. 그 뒤 덱에 두 종류가 더 들어왔다.

| 종류 | 컴포넌트 | 안에 무엇이 있나 |
|---|---|---|
| 종목 | `QuietPickCard` | 결론 · 종목 · 근거 · 우리 성적 |
| 업종 흐름 | `FlowCard` | 빠진 업종 → 들어온 업종 |
| 거시 뉴스 | `MacroCard` | 지표 한 줄 + 연결된 종목 |

세 종류가 각자 자기 마크업으로 자랐다. 결과는 2026-08-31 에 지적받은 그대로다 —
**"카드 크기가 제각각"**. 넘길 때마다 무대 높이가 바뀌고, CTA 가 어떤 카드에선 pill 이고
어떤 카드에선 사각형이고, 같은 손가락 위치를 두 번 못 쓴다.

고칠 방법은 두 가지였다. ① 세 컴포넌트에 같은 클래스 문자열을 복사한다 ② 껍데기를 하나
만들고 셋이 그것을 통과한다. ①은 다음 카드 종류가 생기는 순간 다시 갈라진다. ②를 골랐다.

**앞으로 새 카드 종류를 만들 때 `CardShell` 을 쓰지 않는 선택지는 없다.**

---

## 1. `CardShell` — 모든 카드는 이걸 통과한다

`apps/fomo-web/components/CardShell.tsx`

```tsx
<CardShell kind="flow" testId="flow-card" eyebrow={...} cta={<CardCta ... />}>
  {본문}
</CardShell>
```

| 항목 | 스펙 |
|---|---|
| 레이아웃 | `flex flex-col` |
| 최소 높이 | `CARD_MIN_HEIGHT = 460` — **이 상수 한 곳에서만 정의한다** |
| 배경 | `surface-1` |
| 라운드 | `rounded-card` |
| 안 여백 | `p-s4` |
| 본문 | `flex-1 min-h-0` — 남는 자리를 먹는다 |
| CTA | `shrink-0`, 위 `mt-s5` — **항상 카드 아래끝** |
| 마크 | `data-card-type={kind}`, `data-testid={testId}` |

### 460 은 어디서 왔나

전 블록을 채운 종목 카드 실측 404px(DS-01 §7) 위에, CTA 를 아래끝으로 밀 여유를 더한
값이다. 감으로 정하지 않았다. 내용이 460 을 넘으면 카드는 늘어난다 — **상한은 없다.**

### 고정 높이가 결손을 숨기는 것 아닌가

아니다. 결손은 여전히 DS-05 규칙대로 **문장으로 말한다.** 고정하는 것은 결손 표시가 아니라
**넘기는 동작의 좌표**다. 둘을 섞지 않는다.

## 2. `CardCta` — 카드 안의 유일한 진행 버튼

| 항목 | 스펙 |
|---|---|
| 높이 | `h-touch` (44px) |
| 라운드 | `rounded-block` |
| 배경 | `surface-2` + 0.5px `border` |
| 텍스트 | `body` 14/500, `text-1` |
| 폭 | 카드 폭 전체 |
| 개수 | 카드당 **하나** |

**pill(48px / radius 999px)을 버렸다.** 미감이 아니라 산술이다 — 세 종류 중 둘이 이미
`h-touch` + `rounded-block` 이었다. 하나로 줄이려면 다수를 따른다.

관심(즐겨찾기) 버튼 44×44 는 CTA 가 아니다. 카드 안 버튼은 그래서 최대 둘이다.

## 3. `StepBar` — 상세의 하단 고정 바

`apps/fomo-web/components/DepthSteps.tsx`

상세는 4걸음(신호 → 왜 지금 → 어떤 회사 → 즐겨찾기)이고, **진행 버튼은 걸음 안에 있지
않다.** 화면 아래에 고정된 바 하나가 걸음에 따라 내용을 바꾼다.

| 항목 | 스펙 |
|---|---|
| 위치 | `fixed inset-x-0 bottom-0`, `z-[80]` |
| 배경 | `bg` + 위쪽 0.5px `border` |
| 세이프 | `pb-[env(safe-area-inset-bottom)]` |
| 안쪽 | `max-w-[480px]`, `px-gutter py-s3` |
| 마크 | `data-testid="depth-bar"` |

| 걸음 | 바 내용 | 바 높이 |
|---|---|---|
| 신호 · 왜 지금 · 어떤 회사 | `StepNext` 하나 | 같다 |
| 즐겨찾기 | 즐겨찾기(44px) + 나가기 링크(36px) | **더 높다** |

마지막 걸음만 바가 높다. **위끝이 올라가는 것은 정상**이고, 지켜야 하는 것은 아래끝이
화면 아래끝에 붙어 있는가다. 넘김 버튼만 담은 세 걸음끼리는 위끝도 같아야 한다 — 손가락이
`다음`을 세 번 누르는 동안 자리가 바뀌면 안 된다.

진입 애니메이션(`ds-sheet-up`, 300ms) 동안은 시트에 `transform` 이 걸려 바도 시트를 따라
올라온다. **버그가 아니다** — 바는 시트의 일부로 같이 들어와야 한다. 자리를 재는 테스트는
애니메이션이 끝나기를 기다린 뒤에 잰다.

본문은 `BOTTOM_PAD = pb-[calc(112px+env(safe-area-inset-bottom))]` 로 바 높이만큼 비운다.
**바 뒤로 마지막 줄이 숨는 것은 버그다** — 걸음을 추가하면 이 값을 같이 확인한다.

### 왜 걸음 안에서 뺐나

버튼이 본문 끝에 있으면 걸음마다 다른 높이에 나타나고, 긴 걸음에서는 **스크롤을 끝까지
내려야 다음으로 갈 수 있다.** 읽기를 끝낸 사람만 넘어가게 만드는 장치가 아니라 그냥 방해다.

## 4. 넘김 흐름

### 4-1. 덱은 순환한다

마지막 장에서 다음 → 첫 장. 첫 장에서 이전 → 마지막 장. 끝이 없다 (DS-02 §4-2).

- 한 바퀴를 **처음** 돈 순간에만 `deck_complete` 를 한 번 기록한다 (`completedRef`)
- 덱이 비면 순환하지 않는다. 인덱스 0 고정, DS-05 빈 상태

### 4-2. 상세를 닫으면 다음 장으로 간다

```ts
onClose={() => { setSelected(null); move("next"); }}
```

방금 읽은 카드로 되돌아가면 사용자가 스스로 한 번 더 넘겨야 한다. 읽었다는 사실을 화면이
이미 아는데 되묻는 셈이다.

### 4-3. 한 번 연 카드는 다음부터 종목명을 보여준다

`lib/cardReveal.ts` — `reveal()` 은 상세를 여는 순간, `isRevealed()` 는 카드 앞면에서.

가림은 무명주를 궁금하게 만드는 장치다. 그런데 **이미 아는 회사를 계속 가리면 장치가 아니라
방해**가 된다. 그래서 해제는 되돌아가지 않는다(로컬 저장, 상한 500).

---

## 5. 완료 기준

1. 세 종류 카드의 높이가 같다 (내용이 460 을 넘지 않는 한)
2. 세 종류 카드의 CTA 가 카드 아래끝에서 같은 거리에 있다
3. CTA 높이가 세 종류 모두 44px 다
4. 덱 타이틀에 개수가 없고, 진행 인디케이터가 없다
5. 마지막 장에서 넘기면 첫 장이 나온다
6. 상세를 닫으면 다음 장이 나온다
7. 한 번 연 카드는 앞면에 종목명이 보인다
8. 상세 하단 바가 어느 걸음에서든 같은 자리에 있고, 본문 마지막 줄을 가리지 않는다

| 기준 | 테스트 |
|---|---|

| 4 | `e2e/quiet-deck.spec.ts` — 「덱 타이틀이 개수를 말하지 않는다」 + `__tests__/cardShellDs07.test.ts` §3 |
| 5 · 6 · 7 | `e2e/deck-flow.spec.ts` — **덱을 실제로 넘겨본다**(응답을 가로채 3장 덱을 세우고 진짜 포인터로 스와이프). 소스 계약은 `__tests__/cardShellDs07.test.ts` §4 |
| 8 | `e2e/quiet-depth.spec.ts` — 「[DS-07 §3] 하단 바가 아래끝에 붙어 있고 본문을 가리지 않는다」 |
| 계약 자체 | `__tests__/cardShellDs07.test.ts` §1·§2 — **새 카드가 껍데기를 우회하면 여기서 걸린다** |

이 표를 처음 쓸 때 두 번 걸렸다. 한 번은 **없는 테스트 이름**을 적었고, 한 번은 순환·닫으면
다음 장을 **소스 검사만으로** 통과시켜 놨다. 소스에 `move("next")` 가 있는 것과 손가락이
움직였을 때 카드가 바뀌는 것은 다른 얘기다 — 실제로 `move` 는 이탈 애니메이션이 끝난 뒤에야
`idx` 를 올린다.

**문서에 테스트를 적을 때는 그 테스트가 그 값을 실제로 재는지 열어서 확인한다.** 이름만
맞는 표는 통과했다는 착각을 만든다.

`cardShellDs07.test.ts` 상단의 `CARDS` 배열에 **새 카드 종류를 추가하는 것까지가 구현이다.**
빠뜨리면 그 카드만 계약 밖에 남고, 이 문서가 생긴 이유가 그대로 반복된다.

**프리뷰 라우트에서 실제로 재고 판정한다.** 소스만 보고 통과시키지 않는다 — DS-01 §7 이
그렇게 했고, 그 방식이 이 문서를 만든 문제를 미리 못 잡았다.
