### 왜 FCE 레포를 안 건드렸나

지시서는 "FCE 쪽에 업로드 스크립트 하나만 붙인다" 였는데, **FCE API 가 이 맥에서
열려 있어서 읽는 쪽을 이 레포에 두면 건드릴 레포가 하나 적다.** 같은 결과다.

## 4. 값을 어디서 가져오나

| 화면 값 | FCE 출처 |
|---|---|
| 크립토 자본·N·승률·PF·MDD | `/api/paper/dashboard` → `scoreboard.engine` |
| 크립토 보유 포지션 | 같은 응답 `open_trades` |
| 고래 추종 성적 | `/api/onchain/follow/trades` → `performance.buckets.follow` |
| 지연·드리프트 분포 | 같은 곳 `latency` · `drift` |
| 지갑 자격 | `/api/onchain/follow/eligibility` |
| 주식 US·KR | `/api/stock-paper/dashboard` → `tracks[]` (`nav`·`engine_return_pct`·`halt`) |
| 폴리마켓 | `/api/poly-paper/dashboard` |

**계산하지 않는다.** 예: 주식 자본은 `nav` 를 그대로 쓴다 — 현금에서 다시 계산하면
두 화면이 다른 말을 한다. `nav_complete` 가 아니면 **아예 안 올린다.**

**모르는 값은 null 로 간다.** 폴리마켓 평가액이 그렇다(451 로 NAV 미산출).
0 으로 채우면 자본이 틀리게 계산된다.

## 7. 거래 이력 — `/trades`

전광판은 트랙 단위 요약이다. 요약만 보면 "승률 32%" 가 **어떤 거래들이었는지** 알 수
없고, **비용이 성과를 얼마나 먹었는지는 아예 안 보인다.**

`/api/paper/trades` 를 받아 `FceTrade` 에 쌓는다.

| | |
|---|---|
| 출처 | `/api/paper/trades?limit=1000` |
| 주기 | 러너의 `fce` 잡과 같이 15분 |
| 갱신 방식 | **지우지 않고 id 로 덮어쓴다** |

### 포지션과 반대로 지우지 않는다

`FcePosition` 은 업로드마다 지우고 다시 넣는다 — 닫힌 것이 표에 남으면 안 되니까.
`FceTrade` 는 **반대다.** 닫힌 거래는 사실이고, FCE 가 보관 기간을 줄이거나 리셋해도
랩에는 남아야 한다. 같은 id 로 다시 오면 값만 갱신한다(FCE 가 사후에 비용을 정정한다).

### 목표가·손절선은 받아오지도 않는다

FCE 응답에는 `take_profit_price` · `stop_price` · `invalidation_price` · `target_plan`
이 들어 있다. **랩 스키마에 칸이 없다.** 화면에서 가리는 게 아니라 아예 안 받는다 —
`LAB-08` 이 막은 값이고, DB 에 들어온 값은 언젠가 샌다. 업로더가 `...t` 로 펼치지 않고
**칸 이름을 하나씩 적는** 이유가 이것이다.

`exit_reason` 은 받는다. 닫힌 거래가 왜 끝났는지는 **과거의 사실**이고, 그게 없으면
이력이 "얼마 벌었다" 뿐인 표가 된다.

### 화면이 말하는 것

| | 왜 |
|---|---|
| 비용 전 · 비용 · 비용 후를 **따로** | `net` 만 보이면 수수료·펀딩비가 얼마나 먹었는지 안 보인다. 무기한 선물에서 작은 항이 아니다 |
| 비용이 총손익 규모의 몇 % 인지 | 숫자 셋을 나란히 놔도 사람이 안 나눈다 |
| "비용 전엔 벌고 비용 후엔 잃음" 경고 | 전략이 아니라 **비용이 결과를 정한** 경우다 |
| 합계는 **표에 보이는 줄이 아니라 전부** | 표는 60줄. 보이는 것만 더하면 화면이 거짓말한다 |
| 0원 거래를 승·패에서 분리 | 어느 쪽에 넣어도 승률이 틀어진다 |
