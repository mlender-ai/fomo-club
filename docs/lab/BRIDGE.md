
**랩은 엔진을 갖지 않는다.** 숫자는 전부 FCE 가 낸 것이고, 랩이 계산하는 것은
`마지막 갱신 이후 경과 시간` 과 `끊김 구간` 둘뿐이다 — 그건 FCE 가 알 수 없다.

## 1. 업로더를 돌린다 — **이게 없으면 화면이 과거를 보여준다**

```bash
npm run lab:fce-upload -- --watch     # 15분마다. 이 맥에서 계속 떠 있어야 한다
npm run lab:fce-upload                # 한 번만
npm run lab:fce-upload -- --dry       # 올리지 않고 무엇을 올릴지만
```

`LAB_INGEST_TOKEN` 이 필요하다. Vercel 프로덕션에 같은 값이 들어 있다.

| 환경변수 | 기본값 |
|---|---|
| `FCE_BASE_URL` | `http://127.0.0.1:8875` |
| `LAB_BASE_URL` | 정규 도메인 |
| `LAB_INGEST_TOKEN` | (없으면 올리지 못한다) |

### 왜 FCE 레포를 안 건드렸나

지시서는 "FCE 쪽에 업로드 스크립트 하나만 붙인다" 였는데, **FCE API 가 이 맥에서
열려 있어서 읽는 쪽을 이 레포에 두면 건드릴 레포가 하나 적다.** 같은 결과다.

## 2. 호스트가 자면 끊긴다 (PART B-4)

업로더는 이 맥에서 돈다. 맥이 자면 업로드가 멈추고 **화면은 멈춘 시각의 숫자를
계속 보여준다.** 그래서 화면이 먼저 말하게 해뒀다:

| 신호 | 어디에 |
|---|---|
| `FCE 끊김` | 모든 탭 헤더 오른쪽 |
| 마지막 스냅샷 시각 + 경과 | 전광판 표 위 빨간 줄 |
| 끊김 구간 목록 | 전광판 표 위 |
| 마지막 실패 사유 | 전광판 표 위 |

판정선은 **35분**(주기 15분을 두 번 거른 값)이다.

```bash
caffeinate -dimsu &        # 절전 방지. pmset -g 로 확인된다
```

## 3. 화면 넷

| 경로 | 무엇 |
|---|---|
| `/live` | **첫 화면.** FCE 5트랙 · 보유 포지션 · 갱신·끊김 |
| `/whale` | 지갑 자격 · 두 승률 · 원인 축별 실측 |
| `/data` | 랩이 직접 수집하는 크립토 봉 상태 |
| `/` | **백테스트 보관함** — 끝난 실험이다. `BACKTEST_LOG.md` 가 판정을 갖는다 |

### 화면이 숨기지 않는 것

| | 왜 |
|---|---|
| 레버리지 | MDD 가 배수에서 나온 숫자다 |
| 정지·보류 사유 + 증거 메모 | 사유 없는 정지는 이유를 못 말한다 |
| `⚠ 청산 수준` (손익 ≤ −90%) | **FCE 에 청산 모델이 없다** |
| 끊김 구간 | 메우지 않는다 |
| 두 승률을 **빼지 않는 것** | 다른 모집단이다 |

트랙 순서는 **고정**이다(크립토·고래·US·KR·폴리). 성적순이면 멈춘 트랙이 아래로
밀려 안 보인다.

## 4. 값을 어디서 가져오나

| 화면 값 | FCE 출처 |
|---|---|
| 크립토 자본·N·승률·PF·MDD | `/api/paper/dashboard` → `scoreboard.engine` |
| 크립토 보유 포지션 | 같은 응답 `open_trades` |
| 고래 추종 성적 | `/api/onchain/follow/trades` → `performance.buckets.follow` |
| 지연·드리프트 분포 | 같은 곳 `latency` · `drift` |
| 지갑 자격 | `/api/onchain/follow/eligibility` |
| 주식 US·KR | `/api/stock-paper/dashboard` → `tracks[]` (`nav`·`engine_return_pct`·`halt`) |
| 폴리마켓 | `/api/poly-paper/dashboard` |

**계산하지 않는다.** 예: 주식 자본은 `nav` 를 그대로 쓴다 — 현금에서 다시 계산하면
두 화면이 다른 말을 한다. `nav_complete` 가 아니면 **아예 안 올린다.**

**모르는 값은 null 로 간다.** 폴리마켓 평가액이 그렇다(451 로 NAV 미산출).
0 으로 채우면 자본이 틀리게 계산된다.

## 5. 만들면서 밟은 것 셋 — 같은 실수를 다시 하지 않도록

| # | 무엇 | 왜 그랬나 |
|---|---|---|
| 1 | 폴리마켓 N 에 `resolution_count`(12,774) | **시장 정산 건수**지 우리 거래 수가 아니다. 표본 1만 건짜리 트랙으로 보였다 |
| 2 | 지갑 탈락 사유에 `POPULATION 82` | 퍼널 전체를 훑었다. 탈락 사유는 `funnel.rejected` 안에만 있다 |
| 3 | 주식 자본을 현금에서 재계산 | FCE 에 `nav` 가 이미 있었다 |

셋 다 **FCE 가 이미 낸 값을 안 찾고 랩이 만들어낸** 경우다.
