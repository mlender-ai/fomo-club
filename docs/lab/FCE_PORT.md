### 그 수정이 고친 것 — 셋 다 가져왔다

| 결함 | 원본의 처리 | 여기 | 테스트 |
|---|---|---|---|
| 손절 거리가 극히 작으면 **수량이 발산**한다. "상한이 없으면 한 건이 계좌를 지운다" | `max_notional_usdt` 상한 | `maxNotionalMultiple` (자본 대비 배수) | "손절이 극히 가까우면 명목 상한이 막는다" |
| 상한·하한에 걸리면 **실제 리스크가 예산과 다르다** | `planned_risk_usdt` 에 예산이 아니라 **실제**를 적는다 | `plannedRisk = stopDistance × qty` | "상한에 걸리면 **실제** 리스크를 적는다" |
| 손절 거리가 0 이면 나눌 수 없다 | `fallback:no_stop_distance` 로 기존 경로 복귀 | **거절한다**(`rejected:no_stop_distance`) | "손절 거리가 0 이면 거절한다" |

마지막 항목은 **의도적으로 다르게 했다.** FCE 는 고정 명목으로 되돌리는데, 랩은
`stop_pct` 가 정의에 **필수**라(LAB-02 완료확인 4) 손절 없는 진입 경로 자체를 두지 않는다.
조용히 다른 사이징으로 넘어가면 그 거래가 무슨 규칙으로 들어간 것인지 알 수 없다.

### 원본 주석의 실측을 그대로 가져왔다

> 같은 확정봉 안에서 청산하고 곧바로 같은 가격·같은 방향으로 다시 들어가는 일이
> 실측 **9건** 있었다. 새 판단이 아니라 왕복이다 — gross 우위가 **−0.914R** 이면서
> 비용만 **1.127R** 을 낸다.

그리고 **잠금을 넓힐수록 좋아지는 관계가 아니다**:

> 4시간 간격(1봉) 재진입 3건은 gross 우위가 **+1.608R** 로 양수였다 — 함께 막으면
> 성적이 나빠진다. 그래서 채택값은 `same_bar` 이고, 더 긴 잠금은 표본 33건에서
> 잡음에 적합된 결과로 본다.

**기본값을 `same_bar` 로 뒀다.** FCE 의 기본은 `off`(옵트인)인데, 거기는 운영 중인
페이퍼라 기존 동작을 지켜야 했고 랩은 처음부터 짓는 것이라 **측정된 값**으로 시작한다.
`bars` 모드도 배선은 해뒀다 — 표본이 쌓이면 다시 판정할 수 있게.

## 이식 3 — 체결 판정

**출처** `backend/app/backtest/outcomes.py` `score_event_outcome`
**여기** `packages/lab/src/engine/fills.ts` `exitDecision`

|---|---|---|

### 원본 주석 두 줄이 핵심이다

```python
# Same-candle stop/target is intentionally conservative: loss first.
```

같은 봉에서 손절과 목표가 다 닿으면 **손절로 친다.** 봉 안의 순서를 모르기 때문이다.
목표로 치면 백테스트가 실제보다 좋게 나오고, **좋게 나온 백테스트는 판단 근거가 못 된다.**

```python
# 목표/스탑 미도달 타임아웃 — 최종 종가 마크(net). 피크(MFE) 기준은 낙관 편향.
```

시간 청산은 **최종 종가**로 마크한다. 보유 중 최고가(MFE)로 마크하면 실제로는
팔지 않은 가격에 판 것이 된다.

두 규칙 다 `engine-fills.test.ts` 가 검사한다.

### 원본에 없어서 새로 만든 것 — 갭 처리

FCE 의 `score_event_outcome` 은 `candle.low <= stop` 이면 손절로 치고 **손절가를 쓴다.**
시가가 이미 손절선 아래인 경우(갭 하락)를 따로 보지 않는다 — R 단위 채점기라
체결가를 정확히 낼 필요가 없었기 때문이다.

랩은 자산곡선을 내야 하므로 갭을 갈랐다(PART D · 완료확인 7):

```
갭 하락  시가가 이미 손절선 너머  →  시가로 체결  (손절선보다 나쁜 가격)
그 외    저가가 손절선을 통과      →  손절가로 체결
```

`verify-engine.ts` G-3 이 실데이터에서 확인한다 — 체결 18,401 vs 손절선 23,659.

## 재작성하며 생긴 결함 — 검증이 잡은 것 셋

`LAB-00` §5 가 경고한 것이 정확히 이거다. **옮기는 것 자체가 결함이 들어오는 경로다.**

| # | 결함 | 무엇이 잡았나 | 증상 |
|---|---|---|---|
| 1 | 실행기가 **전략 정의의 `sizing`·`leverage`·`max_positions` 를 무시**하고 config 기본값을 썼다 | **G-1 매수후보유** | 매수후보유가 자본의 2%만 태워 193% 가 **3.91%** 로 나왔다 |
| 2 | 명목 100% 전략이 수수료 때문에 **한 번도 진입하지 못했다** | G-1 ("비용을 물리면 더 낮다" 가 **0.00% 로** 참이 됐다) | 맞는 이유로 참이 아니었다. 실제 브로커처럼 수량을 줄여 들어가게 고쳤고, 줄인 사실을 `blocked` 에 기록한다 |
| 3 | `max_hold_days` 를 **일이 아니라 봉 수**로 썼다 | 실제 백테스트 (평균 보유 24.9h) | 1시간봉에서 30일이 **30시간**이 됐다 |
| 4 | 청산 **신호**로 닫힌 거래가 `exitReason: TIME` 으로 찍혔다 | 실제 백테스트 (청산 59건이 전부 TIME) | `exit_reason` 이 있는 이유가 왜 닫혔는지 아는 것인데 그걸 틀리게 적고 있었다 |

1·2 번은 **합성 데이터 단위 테스트로는 안 잡혔다.** 매수후보유를 실제 3년치로 돌려야
숫자가 안 맞는 게 보인다. 3·4 번은 **DB 에 적재된 결과를 눈으로 봐야** 보였다.

### G-2 의 한계를 적어둔다

절단 불변성은 **경계 부근의 누출**을 잡는다. 깊이 1짜리 누출은 잘린 마지막 봉에서만
값이 달라지는데 그 봉에서는 체결이 없어(체결은 다음 봉 시가) 안 걸린다.
그래서 **여러 지점에서 자른다** — 34개 중 10곳에서 걸렸다. 누출이 어디 있든
어느 지점에는 걸린다는 것이 이 검사의 주장이고, 한 지점만 보면 그 주장이 약해진다.
