```

Supabase pg_cron  ── 5분 ──▶  GET /api/lab/cron/watch       판정 → 알림 · 복구 · 유효일 칸 · 평가 점 · 연구 03(매시)

                                        │

```

**맥 밖에서 판정한다.** 맥이 죽으면 심장박동이 끊기고, 그걸 DB 서버의 크론이 본다.

- **Vercel 크론이 아니다** — 이 계정은 Hobby 라 크론이 하루 1회뿐이다(`lab-collect.yml` 머리 주석)
- **GitHub Actions 도 아니다** — `*/5` 스케줄이 실측 몇 시간씩 건너뛴다(09-28: 15:56 → 15:14 → 12:47 → 07:37)
- **Supabase `pg_cron` + `pg_net`** — DB 서버 안에서 분 단위로 돈다. 마이그레이션 `20260929000100_ops03_pg_cron`
- 엔드포인트는 멱등이다 — 알림은 상태가 바뀔 때만, 아침 리포트는 그날 보낸 기록이 있으면 안 보낸다

## PART A — 심장박동 기준

| 대상 | 틱 (FCE 가 준 시각) | 기준 |
|---|---|---|
| 맥 · 러너 | 심장박동 받은 시각(서버) | 10분 |
| 러너 업로드 | 성공한 FCE 업로드 | 30분 |
| FCE 데몬 | `heartbeat` 잡 | 10분 + 주기 |
| 크립토 | `paper_engine` | 30분 + 주기 |
| 고래 추종 | `whale_follow_engine` | 30분 + 주기 |
| 주식 KR · US | 트랙 관측 시각 — **정규장에만** · 정지면 바로 | 30분 |
| 시세 수집 | `refresh_market_data` | 10분 + 주기 · 🟠 |

- **주기를 더한다** — `refresh_market_data` 는 실측 10분마다 돈다. 마지막 틱 10분으로 쟀더니 첫 가동에서 바로 울렸다(`#1320`)
- **윗단이 멈추면 아래는 판정하지 않는다** — 맥이 죽으면 알림 **하나**(맥 · 러너). FCE 가 죽으면 FCE 하나
- **장외 주식은 판정하지 않는다** — 장 시간 · 휴장일은 랩이 안다(`lib/lab/market-hours.ts` · FCE 확정 휴장일과 같은 날짜 ·
  US 서머타임 · 조기 폐장). FCE `market_state` 만 믿으면 FCE 가 멈춘 순간의 `closed` 로 굳어 멈춤을 못 잡는다
- 문구(A-3) — `🔴 크립토 트랙 42분째 멈춤` / `마지막 틱 10:18 · FCE 는 살아 있음` / `→ FCE 워커 확인: …` · 복구 `🟢 … 복구 · 멈춤 51분`
- 보낸 것 · 못 보낸 것 전부 `LabNotice` — `GET /api/lab/watch` 로 누구나 본다

## A-5 — 시험

**감지 · 복구 경로는 시험했다. 텔레그램 도착은 아직이다** — Vercel 에 `TELEGRAM_BOT_TOKEN` · `TELEGRAM_CHAT_ID` 가 없다.
알림은 만들어져 `LabNotice` 에 `sent: false · 토큰 없음` 으로 남았다. 자격 증명이 들어오면 같은 시험을 한 번 더 한다(15분).

| 단계 | 시각 (UTC) | |
|---|---|---|
| 러너 멈춤 (`launchctl bootout`) | 16:56:24 | 마지막 심장박동 16:56:00 |
| 17:05 판정 | — | 9분 — 기준(10분) 안 · 울리지 않음 |
| **🔴 알림** | **17:10:00** | 멈춘 뒤 13분 36초 — `🔴 맥 · 러너 14분째 멈춤 / 마지막 틱 01:56 / → 맥이 켜져 있나 · scripts/ops/check-24h.sh` |
| 러너 다시 올림 (`launchctl bootstrap`) | 17:10:01 | |
| **🟢 복구** | **17:15:00** | `🟢 맥 · 러너 복구 · 멈춤 19분` |

같은 5분 사이 FCE · 크립토 · 고래 · 주식은 **울리지 않았다** — 윗단(맥 · 러너)이 멈추면 아래는 판정하지 않는다.

첫 가동에서 나온 알림도 남긴다: `🟠 시세 수집 13분째 멈춤`(16:40) → `🟢 복구`(16:45). FCE 시세 잡이 실측 10분 주기라서였다 —
기준을 **자기 주기 + 기준**으로 고쳤다(#1320).

### 시험하다 찾은 것 — FCE 가 연결을 끊고 있었다

재기동한 러너의 심장박동에 `fce: fetch failed` 가 섞였다. `/health` 를 24번 두드리니 **21번 연결 리셋**.
launchd 의 기본 파일 한도가 **256** 인데 FCE 백엔드가 200개를 열고 있었다 — 순간 부하에 새 연결을 못 받았다.
OPS-01 에서 FCE 를 launchd 로 옮기며 생긴 퇴행이다(nohup 때는 부모 셸의 큰 한도를 물려받았다).
등록 파일에 `NumberOfFiles 65536` → 다시 올린 뒤 **24/24**(#1324). 감시가 없었으면 "가끔 업로드가 실패한다" 로 묻혔을 것이다.

## PART C — 유효일

5분 칸(`LabTickSlot`) — 감시가 칸마다 "그 트랙에 틱이 있었나" 를 적는다. 크립토 · 고래는 24시간, 주식은 정규장 · 휴장 제외.
하루 커버리지 = 산 칸 ÷ 있어야 했던 칸(감시 시작 뒤 · 오늘은 지금까지) · **유효일 = 90% 이상**.
맥이 죽은 칸은 죽은 칸이다 — 맥 밖에서 세니까 절전도 유실로 잡힌다.

연구 03 — 한 시간마다 "맥 밖 감시 N일 — 크립토 유효 a/n · 고래 … · 연속 k일" 한 줄을 갈아 끼운다.
크립토 · 고래가 **30일 연속 유효**면 `닫을 수 있다` 로 바뀐다(닫기는 사람이 md 에 결정을 쓴다 — 결정 없는 닫힘은 파서가 거절한다).

## PART D — 평가 자산

| | |
|---|---|
| Hero · 수익률 | **실현 그대로** (FCE 와 같다 — `fce-match.test.ts`) |
| Hero 아래 | `지금 평가 $46,608.73 (미실현 −$5.90)` — 30초 |
| 차트 | 실현(굵은 파랑 · 계단) · 평가(옅고 얇은 파랑) — 평가 점은 감시가 5분마다 |
| 포지션 탭 | `오늘 +$0.41` — 크립토 · 고래 USDT 원래 금액의 오늘(KST) 평가 변화. 환산값과 섞지 않는다 |

미실현 = FCE 가 업로드 때 낸 값(비용 반영) + **그 뒤 가격 움직임만**(수량 × (Bitget 지금가 − FCE 표시가) × 방향).
주식은 FCE 트랙 미실현 그대로. 비용을 랩이 다시 계산하지 않는다.
