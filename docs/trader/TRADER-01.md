## 1. 🧑 광혁이 할 일

### 1-1. 키 — 조회 전용

FCE 는 이미 Bitget 키로 실계좌 체결을 읽고 있다(`FCE_BITGET_API_*`, FCE `backend/.env`). **그 키가 조회 전용이면 그대로 쓴다.** 아니면 새로 만든다:

- Bitget → API 관리 → 새 키: **읽기(Read-only)만** 켠다. 거래 · 이체 · 출금 **끔**
- 가능하면 IP 를 맥 공인 IP 로 묶는다
- 값은 FCE `backend/.env` 에 넣는다 — 에이전트는 값을 보지도 옮기지도 않는다

### 1-2. 돌리기

```bash
cd <맥의 fomo-club 레포> && git pull
# 1) 키 권한 확인 — 쓰기 권한이 보이면 여기서 멈춘다
python3 scripts/trader/trader01.py check-key --env-file ~/fce/backend/.env
#    기계 판정이 "확인 필요" 면: 거래소 API 관리 화면에서 읽기만 켜진 걸 보고
python3 scripts/trader/trader01.py check-key --env-file ~/fce/backend/.env --confirm-readonly
# 2) 전부: 수집 → 봉 · 펀딩 → 묶기 · 시장 상태 → 보고
python3 scripts/trader/trader01.py all --env-file ~/fce/backend/.env --app-30d-pnl <앱의 30D PnL 숫자>
```

- FCE DB 는 `~/fce/backend/fomo_control_engine.db` 를 **읽기 전용**으로 연다. 다른 자리면 `--fce-db`
- 중간에 끊겨도 단계별로 다시 돌릴 수 있다: `collect` → `market` → `build` → `report`
- 첫 실행은 봉을 받느라 수십 분 걸릴 수 있다(종목 수 × 1H·4H·1D + 거래별 잔 봉)

### 1-3. 보고

보고서는 화면에 찍히고 `~/.fomo/trader/TRADER-01-report.md` 에 남는다. **채팅에 붙여 주면** 에이전트가 읽고 TRADER-02 로 넘어갈지 본다. 레포 · 공개 사이트에는 올리지 않는다.

`report` 가 **종료 코드 4** 로 끝나면 E-1(재구성 손익 = 거래소 손익 ±1%)이 안 맞은 것이다 — 지시서대로 **다음으로 안 간다.**

## 2. 무엇을 어디서 받나 (PART A)

**FCE 가 가진 것부터.** FCE 는 2분마다 최근 89일 체결을 받아 `user_account_fills` 에 **쌓아 왔다** — 지운 적이 없으니 FCE 가 오래 돌았으면 거래소 보관 기간(90일)보다 길다.

| 항목 | 출처 | 보관 |
|---|---|---|
| 체결 | FCE `user_account_fills` + Bitget `/api/v2/mix/order/fill-history` | 거래소 90일 · FCE 는 쌓인 만큼 |
| 주문 (지정가 · 시장가 · 손절/익절 · 레버리지) | Bitget `/api/v2/mix/order/orders-history` | 90일 |
| 포지션 이력 | Bitget `/api/v2/mix/position/history-position` | 90일 |
| 수수료 | 체결 `feeDetail` · 장부 `fee` | — |
| 펀딩 · 입출금 · 이체 | Bitget 장부 `/api/v2/mix/account/bill` | 90일 |
| 레버리지 | 주문 기록의 `leverage` (따로 "변경 이력" API 는 없다) | 90일 |

같은 체결이 양쪽에 있으면 **거래소 원본이 이긴다.** 7일씩 끊어 조회하되 **보관 경계(89일 전)에서 한 번 끊는다** — 경계를 걸친 구간은 거래소가 통째로 거절해 며칠이 빈다. 실패한 구간은 `fetch_log` 에 남겨 보고서 "누락" 에 나온다. 장부는 USDT 줄만 쓴다.

## 3. 거래로 묶기 (PART B)

체결을 열기/닫기 · 롱/숏으로 보는 판정은 **FCE `user_fills.py` 를 그대로** 옮겼다(헤지 · 원웨이 · 강제청산 · ADL). 다른 점:

- 진입 · 청산을 **주문 단위 다리(leg)** 로 남긴다 — 한 주문이 체결 다섯 건으로 나뉜 건 분할이 아니다
- 청산 다리마다 `물량 % · 그 순간 평균 진입가 대비 수익률 · 손익 · 방식`
- 청산 방식 = 주문의 `orderSource`/`orderType`: 손절 주문 · 익절 주문 · 지정가 · 시장가 · 강제청산 · 모름(주문 기록 없음 = 90일 밖)
- 실현 손익 = 거래소가 체결마다 준 `profit` 합(수수료 전) → 장부 청산 금액과 같은 정의라 E-1 이 사과 대 사과
- 펀딩은 그 시각 열려 있던 거래에 붙인다(헤지로 롱 · 숏이 같이 열려 있으면 반씩)

## 4. 시장 상태 (PART C)

| 시점 | 내용 | 출처 |
|---|---|---|
| 진입 · 청산 | 1H·4H·1D 마다 가격 vs MA20·60·200 · RSI14 · 거래량 배수 · 직전 20봉 고점/저점까지 % | Bitget 과거 봉(없으면 Binance 선물 봉 — 봉마다 출처 기록) |
| | BTC 같은 시각 — 4H·1D 이평 위치 · 24시간 수익률 · 상승/하락/혼조 | 봉 |
| | 펀딩비(직전 정산) | Bitget 펀딩 이력 |
| | 미결제약정 · 24시간 변화 | FCE `deriv_metrics` / `derivative_snapshots` |
| | 고래 추적군 분포(롱/숏 지갑 수 · 금액 · 24시간 이벤트 수) | FCE `whale_events` 를 그 시각까지 되짚음 |
| | 패턴 판정(주기별 `reason_codes` · `scores`) | FCE `market_snapshots` |
| | 시간대 · 요일(KST) | — |
| 보유 | MFE · MAE · 언제 나왔나 · 잡은 몫(실현 ÷ MFE) | 보유 시간에 맞춘 잔 봉(1m~4H) |
| 청산 | 위와 같음 + **진입 뒤 바뀐 것 · 청산 직전 4시간 사이 바뀐 것**(이평 위/아래 뒤집힘 · RSI 70/30) | 봉 |
| 청산 후 | 24시간 · 7일 수익률(+ = 들고 있었으면 더 벌었다) · 24시간 안 최대 유리 | 1H 봉 |

**미래를 보지 않는다** — 시각 t 의 지표는 t 이전에 닫힌 봉만 쓴다.

## 5. 계좌 지표 · 대조 (PART D · E)

- **시간가중수익률**: 장부의 이체 줄마다 끊어 구간 수익률을 곱한다. 잔고는 장부 `balance`(지갑 = 실현) — **미실현 제외**라 오래 들고 간 포지션의 MDD 는 작게 나올 수 있다
- **비용 비중** = 비용 ÷ |비용 전 총손익| — 랩 ENG-02 와 같은 정의(엔진 크립토 85% 와 견준다)
- **E-1** = 재구성 실현 손익 합 vs 장부 청산 금액 합. 장부를 받은 구간 안에서 진입한 거래만 견준다 — 그 전 거래(FCE 사본에만 있는 옛 거래)는 **"대조 불가 N건"** 으로 따로 센다
- **E-2** = 최근 30일 잔고 손익(이체 제외) vs `--app-30d-pnl`
- **E-3** = 거래 수 · 기간 · 청산 장부와 청산 체결이 어긋난 날 · 조회 실패 구간
- **월별** — 거래 합 · 장부 · 시간가중 · PF · 승률 · 전체 대비 비중 → 한 달만 좋았는지

| # | 한계 | 영향 | 막히면 |
|---|---|---|---|

| 2 | E-1 은 장부가 있는 90일 안쪽만 | 옛 거래는 "대조 불가" | 위와 같음 |
| 3 | 통합 계좌(UTA)면 v2 경로가 거절될 수 있다 | 수집 0건 · 오류 코드가 보고서에 남는다 | v3 경로 추가(다음 작업) |
| 4 | 권한 코드 이름이 문서마다 다르다 | `check-key` 판정은 1차 | 거래소 화면에서 눈으로 보고 `--confirm-readonly` (쓰기 권한이 보인 키는 확인으로 덮을 수 없다) |
| 7 | 장부 수수료 부호 | 거꾸로 읽으면 순손익이 수수료 두 배만큼 틀어진다 | 보고서 "장부 자기 검증" 줄이 잡는다(잔고 변화 = 금액 + 수수료) |
| 5 | 고래 · 패턴 · OI 는 FCE 가 기록을 시작한 뒤만 | 옛 거래는 빈칸(메우지 않는다) | — |
| 6 | 예비 봉(Binance)은 Bitget 과 몇 bp 다르다 | MFE·MAE 가 그만큼 흔들린다 | 출처는 `candles.source` 에 있다 |

## 7. 데이터 모양 (TRADER-02 가 읽는 것)

비공개 DB `~/.fomo/trader/trader.db`:

| 테이블 | 내용 |
|---|---|
| `raw_fills` · `raw_orders` · `raw_positions` · `raw_bills` | 거래소 / FCE 원본 JSON 그대로 |
| `candles` · `funding` | 공개 시장 자료 |
| `fetch_log` | 구간별 조회 성공/실패 |
| `trades` | 거래 1건 = 1줄. `legs.entries[]` · `legs.exits[]` 에 분할 |
| `trade_context` | 거래별 `entry` · `hold` · `exit` · `after` |
| `reports` | 보고서(JSON + 마크다운) |
