## 1. 순서 — 코드가 막는다

```
init-stated → 🧑 답 쓰기 → seal-stated → split → analyze → build-rules → 🧑 광혁-말 확인 → freeze → validate → paper-start → paper-tick(매시)
```

| 지시서 | 막는 방법 |
|---|---|
| A "광혁이 먼저 쓰고 그다음 데이터" | 진술을 **봉인**(시각 · sha256)하기 전엔 `split` · `analyze` 가 거부한다. 봉인 뒤 파일이 바뀌면 거부. 다시 봉인(`--force`)은 기록에 남는다 |
| B-1 "70/30 먼저 고정" | `split` 은 한 번만. 다시 자르면(`--force`) 기록에 남는다. 분할 출력은 **건수 · 날짜만**(손익 없음) |
| B "뒤 30% 를 보지 않는다" | 분석은 `train_trades()` 로만 거래를 받는다. 뒤 30% 를 주는 `test_trades()` 는 **규칙 동결 뒤에만** 열린다 |
| "뒤 30% 를 보면서 다듬지 말 것" | 검증 뒤 규칙 파일이 바뀌면 지문이 달라져 검증이 거부된다. 다시 동결하면 **모든 보고서 머리에 '검증 후 규칙 수정 N회'** |
| "데이터를 먼저 보여주고 쓰게 하지 말 것" | TRADER-01 보고서에서 매매 습관(분할 · MFE · 청산 방식)을 **뺐다.** 계좌 손익 · 승률은 TRADER-01 이 요구해서 남아 있다 — 진술 전에 그 보고서를 만들었으면 그 사실도 기록된다 |

`python3 scripts/trader/trader02.py status` — 지금까지 단계와 시각, 경고, 다음 할 일.

### 2-1. 먼저 쓴다 — **TRADER-01 보고서를 열기 전이 가장 깨끗하다**


### 2-3. `광혁-말` 진입 조건 — 에이전트가 옮기고 광혁이 확인

진입 조건(A-2 "반드시 확인하는 것")은 서술이라 기계가 못 옮긴다 → `_todo`. 광혁 서술을 에이전트에게 주면 **서술만 보고** 랩 지표 이름으로 옮긴다. 광혁이 맞는지 확인하고 `_todo_list` 를 지운다. 그다음:


## 3. 무엇을 어떻게 재나

### B-2 기술 통계 (앞 70%)
진입 특징(1H·4H·1D 이평 거리 · RSI · 거래량 배수 · 고저점 거리 · BTC · 펀딩 · 고래 · OI · 시각/요일)을 **이긴 거래 vs 진 거래**로. MFE · MAE · 잡은 몫(실현÷MFE) · 보유 시간 · 분할(다리별 물량 · 수익) · 레버리지 · 증거금 % · 동시 보유 · 청산 방식 · **연패 뒤 행동**(다음 진입까지 간격 · 크기 변화, 이긴 뒤와 비교).

### B-3 진입 규칙 후보
- 격자: 앞 70% 에 거래한 종목 × 1시간봉. 지표 값은 **랩 엔진의 `featureSeries`**(실행기가 쓰는 바로 그 `indicatorValue`) — 후보 점수와 엔진 재생이 같은 것을 잰다
- 양성: 그 봉이 닫힌 뒤 1시간 안에 광혁이 같은 방향으로 들어갔다(엔진은 신호 다음 봉 시가에 들어간다 — 같은 창). 광혁이 이미 들고 있던 봉은 "안 들어갔다" 로 세지 않는다
- 임계: 광혁 진입 봉 값의 분위수(10 · 25 · 75 · 90%)에서만. 조건 1개 → 상위 10개로 2개 → 3개
- **재현율 · 정밀도 · 올림(정밀도 ÷ 기준)** 을 다 낸다. 고르는 기준은 F1(둘의 조화평균) — 재현율만 보면 아무 때나 들어가는 규칙이 이긴다. F1 이 0.02 안이면 **조건이 적은 쪽**(단순한 것부터)
- 롱 · 숏 따로. 진입 10건 미만인 방향은 후보를 안 만든다
- 엔진 지표가 아닌 것(BTC 추세 · 펀딩 · OI · FCE 패턴)은 B-2 에는 있고 **규칙 후보에선 빠진다** — 보고서에 그렇게 적힌다

### B-4 청산 · B-5 사이징 · 쉬기
| 규칙 | 근거 |
|---|---|
| 손절 | 이긴 거래 MAE 하위 10% — "이보다 불리해진 뒤 이긴 건 10% 뿐" |
| 분할 | 이긴 거래 40% 이상이 분할 청산이면: 첫 다리 수익 · 비율 중앙값, 남은 몫은 추적(MFE 에서 내준 폭 중앙값). 뒷 다리가 25% 이상 진입가 ±0.15% 에서 나갔으면 본절 |
| 목표 | 분할이 습관이 아니면 이긴 거래 수익 중앙값 |
| 최대 보유 | 보유 시간 p90 |
| 크기 | 레버리지 · 증거금 % 중앙값. 변동폭 · 직전 연패 · 진입 조건 충족 수와의 순위상관(|rho| ≥ 0.3 이면 보고 — 엔진은 고정 크기뿐) |
| 동시 보유 | 진입 순간 열린 포지션 수 p90 |
| 쉬기 | k(2~4)연패 뒤 다음 진입까지 간격 중앙값이 이긴 뒤의 2배 이상이고 5번 이상 → `pause` |

### C 말한 것 vs 실제
숫자 칸끼리만 기계가 '일치'(상대 차이 25% 안) · '부분'(60% 안) · '불일치'. 서술은 **광혁 판단**. 마지막 칸(말이 맞다 / 실제가 맞다)은 광혁이 채운다.

### D 스키마 (`packages/lab/src/strategy-definition.ts`) — 더한 것
| 키 | 뜻 |
|---|---|
| `side` | `long`(기본) · `short` · `both`(+ `entry_short`) |
| `exit.scale_out` | `[{at_pct, size}…, {trail: {pct, activate_pct}, size}]` — 합 1, 목표는 커지는 순, 추적은 맨 끝 하나 |
| `exit.breakeven_after_first` | 첫 분할 뒤 손절을 진입가로 |
| `pause` | `{after_consecutive_losses, minutes}` |
| 조건 `tf` | `1h` · `4h` · `1d` … 로 묶어서 본다(마지막 묶음은 지금 봉까지 — 미래 안 봄) |
| 지표 `hour_utc` · `whale_net` | 시간대 · 고래 순포지션 |

**새 키가 없으면 예전과 똑같이 돈다** — 기존 엔진 시험 165개가 그대로 통과. 분할 청산 한 봉 순서: 시가(갭 손절 · 청산 신호) → 봉 안 손절(**목표보다 먼저**, 보수적) → 목표 다리 → 추적 다리(기준 고점은 **이전 봉까지**) → 시간. DB 의 청산 사유는 그대로(추적 손절 = STOP, 분할 목표 = TARGET) — 스키마 변경(DDL) 없음.

### E 검증 (뒤 30%)
- 두 규칙을 랩 엔진으로 재생. 앞 기간 봉은 **지표 창만 채우고 거래하지 않는다**
- 자본 = 자른 시각의 지갑 잔고, 수수료율 = 광혁 앞 70% 실평균
- 엔진은 증거금 모델이 없다 → 자본 × 레버리지로 굴려 **명목 · USDT 손익을 광혁과 맞춘다**(% 분모만 다르다 — %는 비교에 안 쓴다)
- 표: 거래 수 · 순손익 · PF · 승률 · 평균 이익/손실 · 손익비 · 최대 일손실 · 이긴 날/진 날 · 재현율 · 정밀도(같은 종목 · 방향 · 규칙 진입 ≤ 광혁 진입 < +1시간)
- **따라가나**: ① 순손익 부호 같음 ② PF 차이 ≤ 30% ③ 손익비 차이 ≤ 30% ④ 최대 일손실이 실계좌 1.5배 안 → 넷 = 따라간다 · 둘~셋 = 일부만 · 그 아래 = 못 따라간다(TRADER-00 의 세 답)
- **재량 거래**(E-2): `광혁-데이터` 가 못 잡은 광혁 거래 — 건수 · 손익 · 순손익 중 비중 · 이익 중 비중. `t2_discretionary` 에 표시만 하고 **지우지 않는다**. 이익의 절반 이상이면 보고서가 그렇게 말한다

### F 페이퍼
비공개 DB 에 상태를 두고 매시간 새 봉으로 이어 돈다(랩 페이퍼와 같은 `execute` · `reviveState`). 실계좌 새 거래도 같이 받아 **같은 기간을 나란히**(`paper-status.md`). 랩 DB · 공개 사이트에는 쓰지 않는다 — 화면은 TRADER-03.
