## 1. 트랙 합산 — 트랙당 $10,000

`apps/web/lib/lab/portfolio.ts` · 테스트 `apps/web/__tests__/portfolio.test.ts`

```
환산 자산 = $10,000 × (현재 자산 ÷ 시작 자본)
```

**환율이 필요 없다 — 비율만 쓴다.** 원래 금액은 각 행에 병기한다.

### 그대로 더하면 안 되는 이유

| 트랙 | 시작 |
|---|---|
| 크립토 | 500 USDT |
| 주식 KR | 100,000,000 KRW |

크립토가 −30% 나도 총합에서는 **−0.0002%** 로 보인다.

### 테스트가 지키는 것

| | |
|---|---|
| 정지 트랙도 넣는다 | 빼면 −40% 가 −30% 로 **좋아 보인다** |
| 평가액 모르는 트랙을 `0` 으로 채우지 않는다 | 채우면 전액 손실로 합산된다 |
| 시작 자본 0 이면 `null` | `Infinity` 로 총합을 망치지 않는다 |
| 벤치마크도 **같은 방식**으로 환산 | 다른 축으로 그리면 비교가 안 된다 |

> 테스트가 내 예시 하나를 잡았다. 정지 트랙을 −10% 로 뒀는데 크립토 −30% 보다
> 나아서 방향이 뒤집혔다. 규칙은 "빼면 좋아진다" 가 아니라 **"빼지 않는다"** 이다.

## 2. 자본 시계열 — **되만든 값이다**

FCE 에 이력이 없다(`DATA_SOURCES.md` §3). 거래 이력의 **실현 손익을 누적**한다.

| | |
|---|---|
| 해상도 | 하루 |
| 시작점 | 첫 청산일 **하루 전** — 그래야 곡선이 시작 자본에서 출발한다 |
| `source` | `reconstructed` — **화면이 이걸 띄운다** |

### 실측과 다른 점

```
미실현이 빠진다      실현 손익만 누적한다
계단이 된다          거래가 닫히는 순간에만 값이 변한다
거래 없는 날은 평평   실제 자산은 그 사이에도 움직였다
```

### 벤치마크는 랩이 가진 봉으로 세운다

FCE 는 벤치마크를 **현재값 한 점**으로만 준다. 크립토·고래의 기준인 `BTC 보유` 는
랩이 D1 봉을 갖고 있어 같은 기간을 그린다. **주식 벤치마크(S&P·KOSPI)는 랩에 없다** —
`null` 이고 차트가 "벤치마크 없음 — 이 수익률이 좋은지 알 수 없다" 고 말한다.

### 언제 다시 만드나

`POST /api/lab/fce` 에서 **거래가 실제로 바뀐 때만**. 매번 돌리면 아무것도 안 바뀐
날에도 왕복이 늘고, 이 라우트는 왕복 한 번이 ~1초다.

## 3. 연구 노트 — 랩이 갖는 유일한 데이터

**파일이 정본이다.** `docs/lab/research/*.md` → `npm run lab:research-seed`

| 규칙 | 왜 |
|---|---|
| 닫힌 항목에 `verdict` 가 없으면 **시드가 거부한다** | 답 없이 닫으면 기록이 "끝났다" 고만 말한다 |
| 파일에서 사라져도 DB 에서 **안 지운다** | 실수로 파일을 지웠을 때 기록까지 날아가면 안 된다 |
| `inconclusive` 를 쓴다 | 모르는 걸 `no` 로 닫으면 기록이 거짓이 된다 |

초기 7개는 이 프로젝트에서 실제로 나온 질문이다. `05`(1배 vs 3배)가
`inconclusive` 인 이유는 답이 "같다" 가 아니라 **"지금 도구로는 못 잰다"** 이기 때문이다.

## 4. API 9개

| 경로 | 가장 큰 숫자 |
|---|---|
| `GET /api/lab/overview` | 총 자산 |
| `GET /api/lab/strategies` | 1위 수익/낙폭 (또는 "기준선 넘은 전략 없음") |
| `GET /api/lab/positions` | 미실현 손익 합계 |
| `GET /api/lab/positions/{id}` | — |
| `GET /api/lab/whales` | 갭 |
| `GET /api/lab/research` | 열린 질문 수 |
| `GET /api/lab/research/{no}` | — |
| `GET /api/lab/journal` | 누적 실현 손익 |
| `GET /api/lab/status` | 동기화 상태 |

**모든 응답에 `sync` 가 붙는다.** 어느 화면이든 끊김 띠를 띄울 수 있어야 한다(G).
응답에 `ms` 와 `builtAt` 도 실어, 얼마나 걸렸는지와 **언제 조립된 것인지**를 화면에서
바로 볼 수 있게 했다.

### 한 요청 = 쿼리 한 번 (F-1)

정규 도메인에서 재고 나서 구조를 바꿨다:

| | 처음 | 지금 |
|---|---|---|
| `status` | 2.0s (쿼리 2개) | **1개** |
| `overview` | **11.9s** (쿼리 ~11개) | **1개** |
| `journal` | 7.2s | **1개** |

**응답 시간은 로직이 아니라 왕복 수가 정한다.**

```
쿼리 2개  →  1,793ms
쿼리 1개  →    904ms
```

`Promise.all` 로 감싸도 줄지 않는다 — 한 커넥션에서 차례로 간다. 그래서 여섯 탭을
**업로드가 끝난 뒤 통째로 조립해 `LabSnapshot` 에 넣고**, 라우트는 그 한 줄만 읽는다.

동기화 상태도 조립본에 싣는다(안 그러면 모든 API 가 쿼리 두 개가 된다). 다만 **시각만**
싣고 경과 시간은 요청 시점에 센다 — 굳혀두면 화면이 항상 "2분 전" 이라고 말하게 된다.

### p95 500ms 는 지금 코드로 닿을 수 없다

왕복 한 번이 **~900ms** 다. 쿼리를 하나로 줄여도 그게 바닥이다. 남은 것은 코드가
아니라 연결이다:

| 할 수 있는 것 | |
|---|---|
| Supabase 커넥션 풀러(6543) | 매 호출의 연결 수립 비용을 없앤다 — **가장 큰 한 방** |
| DB 리전을 `icn1` 옆으로 | 왕복 거리 자체를 줄인다 |
| Prisma Accelerate | 풀링 + 캐시 |

`DATABASE_URL` 은 Vercel 이 암호화해 내려주지 않아 **내가 바꿀 수 없다.**

### API 가 지키는 것

| API | |
|---|---|
| `whales` | 두 승률을 **빼서 주지 않는다.** `subtractable: false` 를 박아 보낸다 |
| `positions` | 청산 수준과 한계 문구를 그대로 싣는다 |
| `positions/{id}` | **아직 안 올라온 것을 `missing` 에 적는다.** 없는 걸 있는 척하지 않는다 |
| `strategies` | 표본 30 미만·기준선 미달을 플래그로 낸다 — 화면이 순위를 못 매기게 |
| `journal` | 전광판 N 과 다를 때 왜 다른지 문구를 같이 낸다 |
