## 1. 숫자는 전부 한 기준이다 — "시작 자본 + 실현 손익"

FCE 가 다섯 트랙 모두에 이 기준의 자본을 준다(`capital.tracks.*`, `current_capital_basis:
realized`). 전에는 업로더가 주식은 NAV, 폴리는 `null` 로 따로 올렸다 — 통일했다.

| 트랙 | 출처 |
|---|---|
| 크립토 · 주식 US·KR · 폴리마켓 | FCE `capital.tracks` |
| 고래 추종 | FCE 에 `capital` 블록이 없다 → **같은 정의**를 버킷 `net_usdt` 에 (500 + net) |

## 2. 곡선 — FCE 곡선을 쓰지 않은 이유

FCE 는 `scoreboard.equity_curve.engine` 을 계산해 낸다. 그런데 **검증 창(07-18~) 안의 거래만** 센
곡선이라 끝이 356.05 이고, 전체 거래 기준 자본은 352.51 이다. 141 vs 146 과 같은 모집단 함정이다.

그래서 **FCE 거래별 순손익을 전부 누적**한다. 곡선 끝이 Hero 와 정확히 같다(테스트가 찌른다).
고래는 추종 자격(`qualification: follow`) 83건만 — FCE 버킷과 같은 모집단이다.

주식·폴리마켓은 실현 시점을 아직 안 받아 **마지막 점에서만** 반영된다. 금액이 작다(합 +$0.31).

## 3. 선을 끊는 곳과 칠하는 곳 (C-2)

| | 무엇 | 출처 |
|---|---|---|
| 회색 띠 | 관측 유실일(커버리지 < 90%) | FCE `/api/system/paper/diagnosis` |
| 선 끊김 | 값이 정말 없는 곳(BTC 봉 구멍) | 랩 봉 |

크립토 78일 중 49일이 유실일인데 **커버리지 0% 인 날은 0일**이다. 포트폴리오 선은 실현 기준이라
호스트가 자는 동안에도 값이 확정돼 있다 — 거기서 끊으면 "데이터가 없다" 는 거짓말이 된다.

## 4. 운용중 2 / 5 — 주식 KR 은 보류다

FCE 는 KR 을 `running` 으로 준다. 그러나 설정(`stock_paper_hold_queued_orders`, 기본 켜짐) 때문에
대기 주문을 안 내보낸다 — 마지막 체결 08-05, 대기 13,940건. FCE 자기 일일 리포트는 이걸 **보류**로
말한다(`notify/daily_report_source.py`). API 로는 안 나와서 업로더가 같은 쿼리로 FCE DB 를
**읽기 전용**으로 본다.

## 5. 전략 경쟁 — 같은 기간 · 같은 방법

기준선은 **같은 기간**(07-12~) BTC 보유의 수익 ÷ 낙폭이다. 3년 백테스트의 0.70 을 73일 트랙 옆에
두면 기간이 다른 두 수를 비교하게 된다. 트랙도 BTC 도 실현 곡선에서 잰다.

| | 수익 | 낙폭 | 수익 ÷ 낙폭 |
|---|---|---|---|
| BTC 보유 | +31.66% | −7.71% | **4.11** |
| 크립토 | −29.50% | −35.70% | −0.83 |
| 고래 추종 | −6.00% | −7.44% | −0.81 |
