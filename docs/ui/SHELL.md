## 1. 탭이 왜 안 눌렸나 (PART A)

지시서가 확인하라고 한 네 가지부터 봤다:

| | 결과 |
|---|---|
| 탭이 `<a>` 인가 `<span>` 인가 | **`<a>`** — `next/link` |
| `href` 가 있나 | **있다** |
| 라우트가 실제로 있나 | **있다** |
| 클릭을 무언가 가로채나 | **아니다** |

**넷 다 정상이었다.** 그래서 실제로 눌러서 쟀다 — 정규 도메인, 클릭부터 URL·내용이
바뀌기까지:

| 탭 | 화면이 바뀌기까지 |
|---|---|
| 고래 | 5.1s |
| 거래 | 6.0s |
| 데이터 | 6.2s |
| 백테스트(`/`) | **12.8s** |
| 전광판 | 4.2s |

> **탭은 눌리고 있었다. 다만 4~12.8초 동안 URL 도 내용도 안 바뀌었다.**
> 누른 사람에게는 아무 일도 안 일어난 것과 같다.

### 원인 둘이 겹쳤다

**① 공유 레이아웃 아래에 로딩 경계가 없었다.**
`app/loading.tsx` 는 있었지만 **루트**에 있었다. 탭끼리 이동할 때는 `(lab)/layout.tsx` 를
공유하므로 그 **아래**의 경계가 필요한데 없었다. 그래서 Next.js 가 새 화면의 서버 렌더가
끝날 때까지 **URL 도 안 바꾸고 기다렸다.**

**② 화면이 렌더 중에 DB 를 여러 번 왕복했다.**
원격 DB 왕복 한 번이 ~900ms 다(UI-02 실측). 백테스트 화면은 수십 번을 했다.
레이아웃도 헤더 상태 때문에 매번 DB 를 기다렸다.

### 고침

| | 전 | 후 |
|---|---|---|
| 화면 | 서버 렌더 중 DB 여러 번 | **틀은 즉시** · 브라우저가 API 한 번 |
| 레이아웃 | 헤더 상태로 DB 대기 | **DB 안 부름** · 헤더가 `/api/lab/status` 를 1분마다 |
| 로딩 경계 | 루트에만 | `(lab)/loading.tsx` 안전망 추가 |

화면을 누르는 순간 URL 이 바뀌고 스켈레톤이 뜬다. 데이터는 쿼리 한 번짜리 API
(UI-02 조립본)로 ~1초 뒤에 채워진다.

## 4. 세 상태 (PART E)

`components/shell/useLab.ts` 가 API 를 부르고 `LabView` 가 상태를 그린다. **화면마다 따로
짜지 않는다.**

| 상태 | 그리는 것 |
|---|---|
| 로딩 | 화면이 넘긴 스켈레톤 — **실제 레이아웃과 같은 모양** |
| 조립본 없음(503) | "아직 받은 데이터가 없어요" + `npm run lab:runner` |
| 오류 | 한 줄 + 원인 + **다시 시도** |
| 빈 데이터 | 화면이 `Empty` — 왜 비었는지 + 할 일 |

**조립본 없음과 오류를 가른다.** 둘 다 빈 화면이지만 할 일이 다르다 — 하나는 러너를 켜야
하고, 하나는 다시 눌러보면 된다.

빈 화면은 동기화가 끊겨 있으면 **그 사실을 이유로 같이 댄다**(`useSyncHint`). 포지션이 없는
게 FCE 가 진입을 안 해서인지, 동기화가 끊겨서인지 화면이 구분해준다.

## 5. 같이 걷어낸 것

UI-01 에서 옛 토큰 **이름**을 별칭으로 남겨뒀다 — 옛 화면 다섯이 쓰고 있었기 때문이다.
이번에 그 화면들을 새로 만들면서 같이 지웠다:

| | |
|---|---|
| 옛 화면 | `/live` · `/whale` · `/trades` · `/data` · `/strategy/[id]` · 백테스트 보관함 |
| 옛 부품 | `EquityCurve` · `LiveBoard` · `LabEmpty` · `paper-pulse` |
| `globals.css` | **1,020 → 233줄** — `.lab-*` 규칙 전부 |
| 토큰 별칭 | `--surface` · `--text` · `--accent` · `--mono` … 전부 |

로그인 화면이 별칭을 쓰고 있어서 새 토큰으로 옮겼다. 404 화면이 "랩 라우트는 `/` · `/live` ·
`/strategy/[id]` 셋뿐이다" 라고 **틀린 안내**를 하고 있어서 여섯 탭 링크로 바꿨다.

### 안 지운 것

`/api/lab/live` · `lib/lab/live-board.ts` · `scripts/lab/verify-live.ts` 는 남긴다. 화면은
없어졌지만 **LAB-08 의 누설 방지 장치**(`FORBIDDEN_LIVE_KEYS` — 목표가·손절선이 밖으로
나가지 않게)와 그 검증이다. 화면과 무관하게 규칙이 살아 있어야 한다.

## 6. 배포하고 나서 밟은 것 — **조립본은 배포보다 오래 산다**

UI-03 을 배포하고 정규 도메인에서 탭을 눌렀더니 **`/whales` 가 통째로 터졌다.** 그리고
헤더까지 사라져서 다른 탭으로 갈 수도 없었다.

| | |
|---|---|
| 터진 이유 | DB 에 남은 조립본이 **이전 배포의 코드**가 만든 것이었다. `causes[].measured` 가 문자열이 아니라 객체였고, 새 화면이 그걸 글자로 그리려다 멈췄다. 전략 조립본에는 새 전략 상세가 찾는 `series` 도 없었다 |
| 헤더가 사라진 이유 | 받은 경계가 루트 `app/error.tsx` 였다. 루트는 `(lab)` 레이아웃 **바깥**이라 헤더까지 덮었다 |

세 겹으로 막았다:

| | |
|---|---|
| `SNAPSHOT_VERSION` | 조립본에 형식 번호를 박는다. 번호가 다르면 API 가 옛 모양을 넘기지 않고 **"다시 만드는 중"(503)** 으로 답한다. **조립본 모양을 바꾸면 반드시 올린다** |
| `(lab)/error.tsx` | 탭 안에 경계를 하나 더 둔다. 무너져도 본문만 무너지고 **헤더는 남는다** |
| `POST /api/lab/snapshot` | 조립본을 **랩 DB 만으로** 즉시 다시 만든다. 러너가 30분마다 부른다 — FCE 가 죽어 있어도 배포 뒤 화면이 옛 형식에 갇히지 않게 |

## 7. 데이터 상태는 헤더로 (PART B)

`/data` 를 없애면서 시세·수집 잡 상태를 보여줄 곳이 사라질 뻔했다. 처음 "끊김" 을
발견한 게 그 화면이었다. `GET /api/lab/status` 가 이제 둘을 낸다:

| | |
|---|---|
| `sync` | FCE 스냅샷이 언제 올라왔나 |
| `collect` | 시세가 끊긴 종목 · 마지막 실행이 실패한 수집 잡 |

헤더 점은 **더 나쁜 쪽**을 따른다 — FCE 가 살아 있어도 시세가 끊겼으면 끊김이다. 무엇이
실패 중인지는 상태에 마우스를 올리면 보인다(한 줄에 다 넣으면 폰에서 넘친다). 시세가 끊기면
띠가 "로컬 수집 러너를 확인하세요" 라고 말한다 — 시세는 이 맥의 러너가 넣기 때문이다.
