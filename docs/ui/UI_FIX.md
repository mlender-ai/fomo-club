## 1. 깨진 것 (PART B)

### B-2 · 포지션 손익이 전부 −0.27% — **3번: 잘못된 필드를 읽었다**

| 질문 | 답 |
|---|---|
| 1 · FCE 가 준 값이 이미 같은가 | **그 필드는 같다.** 보유 중인 거래의 `net_return_pct` 는 진입할 때 `−entry_cost / margin` 으로 한 번 적히고(FCE `paper/policy.py:503`) **부분 청산 때만 바뀐다.** 증거금 100 · 3배면 진입 비용 비율이 모두 같다 → −0.27% |
| 2 · 업로드가 덮나 | 아니다. 그대로 옮겼다 |
| 3 · 잘못된 필드를 읽나 | **그렇다.** 현재가 기준 손익은 FCE 가 `exit_monitor.mark_net_return_pct` 에 따로 싣는다(`paper/service.py` `paper_exit_monitor`) |

증거: 정규 도메인 실측 넷 중 **부분 청산을 안 한 둘(XRP·MRVL)만 −0.27** 이고, 부분 청산한 둘(BNB +1.71 · BABA +2.52)은
달랐다. FCE 자기 페이퍼 화면(`engine-trading-shell.tsx` `PaperPositionCard`)도 같은 칸을 읽어 같은 값을 보여준다.

고침: 업로더가 `exit_monitor.mark_net_return_pct` 를 읽는다(`lib/lab/fce-payload.ts` `positionFromOpenTrade`). 현재가를
모르면 **null** — 진입 비용을 손익인 척 올리지 않는다. 테스트: `__tests__/fce-payload.test.ts`.

> ⚠ **화면에 반영되려면 Mac 의 업로더가 한 번 돌아야 한다.** 조립본은 업로드가 만든다. 이 세션은 FCE(127.0.0.1)에 닿지 못한다.

### B-3 · 건강도가 전부 `—` — **FCE 페이퍼 거래에는 건강도가 없다**

FCE 로컬 UI 의 건강도 게이지는 **계좌 포지션**(`/api/live/positions` → `state.health_score`, `live-position-cockpit.tsx`)의
것이다. 페이퍼 거래(`PaperTrade` 모델)에는 그 칸 자체가 없다. 계좌 포지션 값을 심볼로 페이퍼 거래에 붙이면 **다른 포지션의 판정**이
되므로 붙이지 않았다.

그래서 지시서의 둘째 갈래를 따른다 — **값이 없으면 칸째 숨긴다.** 목록 행·상세 통계 칸 모두. FCE 가 페이퍼에 `health_score` 를
싣는 날 업로더가 그대로 받는다(칸은 이미 있다).

### B-4 · 기준선 — **한 곳에서 잰다**

`lib/lab/overview.ts` `competition.rows[].baseline` 한 곳. 전략 탭(`buildStrategyRows`)은 그 값을 **그대로 읽는다.**

| | 전 | 후 |
|---|---|---|
| Overview | 모든 트랙에 07-12~ BTC 기준선 하나 | **트랙마다 그 트랙 시작일부터** |
| 전략 탭 | FCE 트랙 행의 `benchmarkReturnPct`(크립토엔 없음) → "기준선 없음" | Overview 와 같은 값 |

고래 추종은 08-24 에 시작했다. 07-12 부터 잰 BTC 와 비교하면 기간이 다른 두 수를 견준다. 테스트가 두 화면 값이 같은지 찌른다.

### B-5 · 거래 수 246 vs 248 — **원장 하나를 센다**

| | 세던 것 |
|---|---|
| Overview 누적 거래 | 트랙 N 의 합 = 크립토 **FCE 채점판 N**(검증 창 07-18~ 안에서 닫힌 것만) + 고래 + **주식 US 체결 3** |
| 복기 | 랩 원장(`FceTrade`) 전부 |

**차이 2건의 정체 = (+5) − (3):**

- **+5** — 크립토가 검증 창 **이전**(07-13 ~ 07-17)에 닫은 거래. 원장에는 있고 채점판 N 에는 없다
- **−3** — 주식 US 체결 3건. 채점판 합에는 있고, 주식은 거래 이력을 안 올리니 원장에는 없다

오늘 실측(04:06 조립본)도 247 vs 249 로 같은 2건이다(크립토 채점판 157 · 원장 162).

**원장이 맞다고 정했다.** 자본·곡선·낙폭이 이미 원장 전부로 재고 있었다 — 한 행 안에서 수익률은 162건, N·승률은 157건이었다.
FCE 도 같은 원칙을 쓴다(`paper/service.py` "모집단은 하나다"). 거래 수·승률·손익비를 원장에서 FCE 와 **같은 공식**으로 잰다
(`ledgerStats` — 승 ÷ 전체, 이익 합 ÷ 손실 합). Overview · 전략 탭 · 복기가 같은 행을 센다. 복기의 해명 문단(`countNote`)은 지웠다.

> 부수 발견 (고치지 않음): 원장에 `MRVLUSDT 09-16 08:00 → 09-17 08:00` 거래가 **id 만 다르고 가격·손익이 같은 두 줄**로 있다
> (`holdingBars` 5 vs 2). FCE 쪽 기록 그대로다. FCE 중복 억제(`duplicate_bootstrap_suppressed`)를 빠져나간 건인지 확인이 필요하다.

### B-1 · B-6 · 전략 탭 세로 쪼개짐

## 6. 폰 390px 확인 (PART D)

`npx tsx scripts/ui/capture-phone.ts` — 로컬 `next dev` 의 `/api/lab/*` 를 견본 조립본으로 가로채 찍고 재고, ⓘ 를 눌러 시트를 확인한다.

```
overview   가로스크롤 없음 · 잘림 0 · 이름 쪼개짐 0/5 · 두 줄 넘는 행 0 · ⓘ 4 → 시트 "자산 추이"
strategies 가로스크롤 없음 · 잘림 0 · 이름 쪼개짐 0/5 · 두 줄 넘는 행 0 · ⓘ 1 → 시트 "전략"
positions  가로스크롤 없음 · 잘림 0 · 이름 쪼개짐 0/4 · 두 줄 넘는 행 0 · ⓘ 1 → 시트 "포지션"
whales     가로스크롤 없음 · 잘림 0 · 이름 쪼개짐 0/5 · 두 줄 넘는 행 0 · ⓘ 3 → 시트 "두 승률은 다른 것을 잰다"
research   가로스크롤 없음 · 잘림 0 · 이름 쪼개짐 0/1 · 두 줄 넘는 행 0 · ⓘ 1 → 시트 "연구"
journal    가로스크롤 없음 · 잘림 0 · 이름 쪼개짐 0/60 · 두 줄 넘는 행 0 · ⓘ 2 → 시트 "복기"
```

**견본이지 정규 도메인이 아니다.** 이 세션의 네트워크가 정규 도메인을 막는다. 견본은 정규 도메인 API 실측(09-25 04:06)에서 옮겼고,
두 가지만 만든 값이다 — 거래 원장(일별 자본을 거래로 나눈 것 · 곡선 끝은 실측과 같다. 그래서 크립토 승률 48.1% 는 견본 값이다)과
포지션 손익(실측이 버그 값이라). **정규 도메인 캡처는 배포 + 업로드 한 바퀴 뒤에 다시 찍어야 한다.**
