# DETAIL-02 — 「실적을 냈어요」를 실제 숫자로

> 정본은 이 문서다. 코드(`packages/fomo-core/src/keyword-cards/disclosure-figures.ts`)와
> 함께 바꾼다. 문안·규칙이 코드에만 있으면 사람이 검토할 수 없다.

## 0. 무엇이 문제였나

바이오니아 상세 「왜 지금 사는가」 전문이다.

```
8월 14일   반년 치 실적을 냈어요   [원문]
9월 1일    그 다음부터 시장을 앞서기 시작했어요
```

**`실적을 냈어요` 는 정보가 아니다.** 좋았는지 나빴는지, 매출이 늘었는지, 흑자인지
하나도 알 수 없다. 공시가 있었다는 사실만 주고 내용을 안 준다. 그러면 사용자는
"그래서 뭐?" 로 끝난다.

원문 링크는 해결책이 아니다 — 아무도 안 누르고, 눌러도 DART 원문은 읽기 어렵다.
**우리가 읽어서 숫자로 준다.**

## 1. 공시 감지와 재무 수치는 연결돼 있었나 — **아니다**

| 갖고 있던 것 | 어디 | 무엇을 |
|---|---|---|
| 공시 목록 | `disclosure-collect.ts` → `FeedContentCache` | 날짜 · 제목 · 종류 · 링크 (**본문 없음**) |
| 분기 재무 | 팩트시트 `fiscal.quarters` | `period` · `filed_at` · 매출 · 영업이익 · 순이익 |

둘은 **`filed_at` 이라는 같은 날짜를 들고 있었는데 아무도 잇지 않았다.**
유일한 접점이 `earningsTurnEvent`(영업이익 흑자/적자 **전환**만 별도 줄로) 하나였고,
공시 줄 자체는 `disclosurePhrase(title)` — **제목만 보는 순수 함수** — 가 만들었다.
그래서 제목 번역 이상을 할 수 없었다.

**이 작업이 그 조인이다. 새로 수집하는 것은 없다.**

## 2. 조인 규칙 — `filed_at` 으로 잇지 않는다

**처음에 `filed_at` 을 조인 키로 썼는데 그것이 국내에서 확보율 0 을 만든다.**

네이버 재무표에는 **공시일이 없다.** 파이프라인이 법정 제출기한을 보수적 상한으로 써 넣고
`filed_at_source: "statutory_deadline"` 으로 표시한다(`naver-fundamentals.ts:251`).
즉 국내 종목의 `filed_at` 은 **우리가 계산한 추정치**다. 그걸 조인 키로 쓰면 둘 중 하나다 —
추정 위에 숫자를 얹거나(위험), 추정을 배제해서 국내 전부를 버리거나(무용).
그리고 **프로덕션 실적 공시 8건은 전부 국내다**(§8 실측). 무용 쪽이었다.

그래서 **실측 두 개만** 쓴다.

| 규칙 | 왜 |
|---|---|
| DART 가 준 **공시일**과 재무 레코드의 **기간말**(`period_end`) 사이 간격으로 잇는다 | 둘 다 소스가 실제로 관측한 값이다. 추정치가 개입하지 않는다 |
| 간격 창 **10~100일** | 상한 100 = 법정기한(분기·반기 45일, 사업보고서 90일)에 지연·정정을 얹은 값. 하한 10 = 기간이 끝난 지 열흘 안에 나오는 정기보고서는 없다 |
| 창 안에 여럿이면 **기간말이 가장 늦은** 분기 | 보고서는 가장 최근에 끝난 기간을 보고한다 |
| 비교는 **전년 동기**(같은 분기, 연도 −1) | 다른 분기와 비교하면 계절성이 증감으로 둔갑한다 |
| `period` 가 `2026Q2` 형식이 아니면 **숫자를 안 붙인다** | 어느 기간인지 못 말하면 숫자도 못 쓴다(아래 3번). 분기 목록에 섞여 들어오는 연간 레코드(`2026FY`)도 여기서 걸린다 |

전년 동기가 확보되는가: 네이버 분기표는 5개를 준다 → 2026Q2 보고서 시점에 2025Q2 가 있다.
`disclosure-figures.test.ts` 「국내 팩트시트 모양으로 실제 조인된다」가 그 모양 그대로 검사한다.

## 3. 어느 기간의 숫자인지 반드시 말한다

우리가 가진 것은 **분기** 레코드다. 반기보고서 제목 아래에 분기 숫자를 기간 표시 없이
놓으면 사용자가 반기 실적으로 읽는다 — 틀린 값을 보여준 것과 같다. 그래서 화면은
숫자 위에 `2026년 2분기` 를 놓고, 증감 문장도 `작년 2분기보다` 로 기간을 다시 말한다.

반기 합산(Q1+Q2)은 하지 않았다 — 4개 분기가 모두 정확해야 성립하고, 그 조건이
깨질 때 조용히 틀린 숫자가 나가는 쪽이 더 나쁘다.

## 4. 항목과 표현

| 항목 | 매출 · 영업이익 · 순이익 (**확보된 것만**) |
|---|---|
| 비교 | 반드시 전년 동기 대비 |
| 표현 | 증감률 + 방향 |
| 흑자·적자 전환 | 별도 문장 (증감률로 쓸 수 없다 — `-14 → 92` 는 %가 성립하지 않는다) |
| 확보 실패 | 그 항목의 **줄이 없다.** 세 항목 다 없으면 블록 자체가 없다 |

### 전환·적자 문장

| 상황 | 문장 |
|---|---|
| 적자 → 흑자 | `작년 2분기 -14억에서 흑자로` |
| 흑자 → 적자 | `작년 2분기 92억에서 적자로` |
| 적자 축소 | `적자가 -140억에서 -14억으로 줄었어요` |
| 적자 확대 | `적자가 -14억에서 -140억으로 늘었어요` |

**흑자·적자는 이익에만 있는 개념이다.** 매출에는 쓰지 않는다 —
`매출이 흑자로 돌아섰어요` 는 뜻이 없는 말이다. 매출은 증감률만 쓰고,
전년 동기 매출이 0 이하면 그 줄이 아예 없다.

### 한 줄 해석 — 사실 요약만

| 매출 | 영업이익 | 한 줄 |
|---|---|---|
| ↑ | ↑ | 매출과 영업이익이 함께 늘었어요 |
| ↑ | ↓ | 매출은 늘었는데 영업이익은 줄었어요 |
| ↓ | ↑ | 매출은 줄었는데 영업이익은 늘었어요 |
| ↓ | ↓ | 매출과 영업이익이 함께 줄었어요 |
| ↑ | 적자→흑자 | 매출 늘고 영업이익 흑자로 돌아섰어요 |
| ↓ | 적자→흑자 | 매출은 줄었는데 영업이익은 흑자로 돌아섰어요 |
| ↑ | 흑자→적자 | 매출 늘고 영업이익은 적자로 돌아섰어요 |
| ↓ | 흑자→적자 | 매출 줄고 영업이익은 적자로 돌아섰어요 |
| ↑ | 적자 축소 | 매출 늘고 영업이익 적자가 줄었어요 |
| ↓ | 적자 축소 | 매출 줄고 영업이익 적자가 줄었어요 |
| ↑ | 적자 확대 | 매출은 늘었는데 영업이익 적자가 늘었어요 |
| ↓ | 적자 확대 | 매출 줄고 영업이익 적자가 늘었어요 |

**금지**: `좋았어요` · `호실적` · `개선됐어요` → 평가다.
**허용**: `늘었어요` · `줄었어요` · `흑자로 돌아섰어요` → 사실이다.

매출·영업이익이 **둘 다** 있을 때만 만든다. 하나만 갖고 "함께 늘었어요" 를 쓰면
없는 항목을 있는 것처럼 말하는 것이다.

**`이익` 이라고 뭉개지 않는다**(규제검토 BLOCKED-3). WO 원안은 계속흑자 4개를 `이익` 으로
적었는데, 이 해석은 **영업이익 방향 하나로만** 만들면서 같은 블록이 순이익 줄도 그린다.
영업이익↑·순이익↓ 인 분기(일회성 손실·금융비용)에 `이익이 함께 늘었어요` 를 쓰면
바로 아래 자기 숫자에게 반박당한다. 그래서 12개 문안 전부 `영업이익` 으로 통일했다.

### 증감률을 쓰지 않는 세 경우

| 경우 | 대신 쓰는 것 | 왜 |
|---|---|---|
| 전년 동기 ≤ 0 | 그 줄이 없다 | 퍼센트가 성립하지 않는다 |
| 반올림 0% | `작년 2분기와 비슷해요` | **해석도 같은 임계값을 쓴다** — 1,000억→1,002억 에서 항목은 `비슷해요` 인데 해석이 `늘었어요` 면 한 블록 안에서 어긋난다(규제검토 RISK-2) |
| 적자↔적자, **표기가 같다** | `작년 2분기와 비슷한 적자예요` | 원 단위로 비교하면 동액(-14억→-14억)이 `늘었어요` 로 나가고(거짓), -140.4억→-139.6억 은 둘 다 `-140억` 으로 표기되는데 문장은 `줄었어요` 가 된다. **판별 기준을 표기로** 두면 화면과 문장이 어긋나지 않는다(RISK-7) |
| \|증감률\| > 300% | `작년 2분기 3,000만에서 20억으로` | 3,000만 → 20억은 `+6,567%` 다. 숫자는 맞지만 크기가 전달되지 않고 과장으로 읽힌다 — `폭등` 을 금칙어로 막아 놓고 그 뜻을 숫자로 통과시키는 셈이다(RISK-3) |

**0 은 흑자도 적자도 아니다**(손익분기). `<= 0` 으로 잡으면 정확히 0 인 분기를 `적자로` 라고
부르게 된다 — 0 은 증감률 경로로 내려보낸다(RISK-5). 표기도 `0만` 이 아니라 `0원` 이다.

## 5. 금액은 규모 대비로 (PART C)

```
320억               →  아무 감이 안 옴
320억 · 연매출의 26%  →  크구나
```

금액 자체는 제목이 들고 온 것을 `disclosurePhrase` 가 이미 붙인다
(`큰 계약을 따냈어요 · 계약금액 320억`). 이 작업이 더하는 것은 **비율**이다.

| 공시 | 무엇 대비 | 분모 |
|---|---|---|
| 수주 · 공급계약 | 최근 1년 매출 | `fiscal.ttm.revenue` |
| 자사주 · 주식소각 | 시가총액 | `market_data.market_cap` |
| 유상·무상증자 · 전환사채 · 신주인수권부사채 · 교환사채 · 사채발행 | 시가총액 | `market_data.market_cap` |
| 담보 제공 · 채무보증 · 금전대여 | 자기자본 | `balance.total_equity` |
| 타법인 취득·처분 · 시설투자 · 유형자산처분 · 영업양수도 | 자기자본 | `balance.total_equity` |

### 분모를 `연매출` 이라 부르지 않는다 · 수주는 분자를 말한다 (규제검토 BLOCKED-2)

WO 원안은 `320억 · 매출의 26%` 였는데 두 곳이 틀린다.

1. 분모는 `fiscal.ttm.revenue` — **최근 4분기**다. `연매출` 이라 쓰면 사용자는 "작년 연매출"로
   읽고 그건 다른 숫자다. → `최근 1년 매출`
2. 단일판매·공급계약의 금액은 **계약 총액**이고 계약기간이 여러 해일 수 있다(그 기간은 서식
   본문에 있고 우리는 본문을 저장하지 않는다). 3년 320억을 1년 매출로 나눈 26% 를 아무 말 없이
   놓으면 **연간 기여를 세 배로 부풀린 것**이 된다. 크기를 전달하려는 숫자가 크기를 과장하면
   계산 실수가 아니라 오해유발 표시다. → `계약금액이 최근 1년 매출의 26%`

`계약금액이` 가 앞에 붙으면 `매출이 26% 는다` 로 읽히지 않는다. 계약기간까지 반영하려면
본문 수집이 선행이다(§8 다음 작업). 시가총액·자기자본 계열은 분자·분모가 같은 시점이라
문장 그대로 안전하다 — 담보제공·채무보증은 DART 서식 자체가 `자기자본대비(%)` 를 공시한다.

**`해지`·`철회`·`취소`·`중단` 은 환산하지 않는다** — 없어진 금액이다.
`/공급계약/` 이 `단일판매ㆍ공급계약해지` 도 잡고 있었다.

- 분모가 없으면(`null`·0) **아무 말도 하지 않는다.** 0 으로 메우면 근거 없는 비율이 나온다.
- 표기: 10% 이상은 정수, 그 아래는 소수 한 자리. **0.1% 미만은 쓰지 않는다** — 환산해도 감이 안 온다.
- 금액 파싱은 **단위가 붙은 숫자만** 읽는다(`억`·`조`·`만`·`원`). 연도(`2025.12`)·비율(`30%`)·
  주식수(`1,000,000주`)를 금액으로 읽으면 그 뒤 환산이 전부 거짓이 된다.

## 5-1. 왜 콜백으로 넣는가 (번들 격리)

`disclosure-figures` 를 `why-now.ts` 가 **값으로** 임포트하고 배럴(`keyword-cards/index.ts`)에
내보내자 조회 라우트 세 개의 전이 모듈이 각각 **+1** 됐다(`perf-regression-gate` 실측:
128→129 · 146→147 · 167→168). AGENTS.md 「번들 격리」가 막는 바로 그것이고, 504 사고의 원인이다.

그래서:

| 조치 | 결과 |
|---|---|
| 배럴에서 뺐다 | 쓰는 쪽이 경로로 직접 — `@fomo/core/keyword-cards/disclosure-figures` |
| `why-now.ts` 는 **타입만** 임포트 | 타입 전용 임포트는 지워지므로 번들에 안 들어온다 |
| 숫자 생성은 `WhyNowTimelineInput.figuresFor` **콜백**으로 굽는 경로가 넣는다 | `why-now.ts` 는 자리만 만든다 |

실측: 조회 128 / 146 / 167 — **증가 없음.** 굽는 경로(`cron:quiet-pick`)만 이 모듈을 갖는다.

## 5-2. 투자조언 면책 (규제검토 BLOCKED-1)

**이 화면에 면책이 없었다.** 있던 것은 인과 면책 하나뿐이고
(`WHY_NOW_TIMELINE_DISCLAIMER` — "왜 샀는지는 확인할 수 없어요"), 그건 "투자 조언이 아니다" 와
다른 말이다. 원래부터 있던 구멍이지만, DETAIL-02 가 이 화면을 「공시 제목 목록」에서
**분기 실적 수치·증감률·규모 환산을 제시하는 화면**으로 바꿨으므로 노출도가 달라졌다.

**문안은 새로 정하지 않았다.** `StockCardFeed.tsx:166` · `VoiceFeed.tsx:56` 이 쓰는
**기존 승인 문장 그대로** 옮겼다 — `투자 조언이 아니에요.` 앞 절(`지난 흐름을 친구처럼…`)은
한마디 코멘트용이라 실적 수치 화면에 맞지 않아 가져오지 않았다.

즉 이것은 카피 결정이 아니라 **이미 내려진 결정을 빠진 화면에 적용한 정합성 수정**이다
(AGENTS.md 3원칙 1 — 카피는 광혁 몫). 이 화면에 맞는 문안을 새로 정할지는 광혁 판단으로 남긴다.

**걸음 밖(스크롤 본문 끝)에 둔다.** 네 걸음은 **상호 배타 렌더**이고 재무 수치가 나오는 것은
2걸음(`why`)이다. 4걸음 안에 두면 **수치를 읽고 나가는 경로에 면책이 한 번도 걸리지 않는다** —
오버레이는 어느 걸음에서든 닫을 수 있다. `StepBar` 안이 아니라 본문 끝이라 바 높이도
건드리지 않는다(DS-07 §3).

`data-testid="depth-disclaimer"` · e2e 가 **네 걸음 전부**에서 존재와 문구를 확인하고,
2걸음에서는 `depth-why-now-figures` 와 같은 화면에 있는지까지 본다.

## 6. 원문 링크 위치 (PART D)

```
전   8월 14일  반년 치 실적을 냈어요 [원문]     ← 제목 옆
후   8월 14일  반년 치 실적을 냈어요
               매출 늘고 영업이익 흑자로 돌아섰어요
               2026년 2분기
               매출      1,240억   작년 2분기보다 +18%
               영업이익     92억   작년 2분기 -14억에서 흑자로
               순이익       71억   작년 2분기보다 +230%
               공시 원문 →                      ← 맨 아래, 작게·회색
```

링크는 보조다. 내용을 먼저 보여준다. e2e 가 링크의 `y` 좌표가 숫자 블록 **아래**임을 검사한다.

**기간 라벨은 해석보다 위에 둔다**(규제검토 RISK-1). 왼쪽 열은 공시일이라 기간 앵커가 아니고,
반기 제목 아래에 분기 숫자를 놓으므로, 오독에 가장 약한 문장(`흑자로 돌아섰어요`)이 라벨보다
앞서면 라벨이 하는 일이 없다. e2e 가 `y` 좌표로 순서를 고정한다.

## 8. 확보율 (PART E-2)

페이로드 `qualification.disclosureFigures` 로 계측한다.

```
{ total, figures, scale, byKind: { 실적: {total, figures, scale}, 수주: {...}, ... } }
```

| 필드 | 뜻 |
|---|---|
| `total` | 화면에 나간 공시 건수(창 안 + 3건 상한 안) |
| `figures` | 실적 수치가 붙은 건수 |
| `scale` | 금액이 규모 대비로 환산된 건수 |
| `byKind` | 위 셋을 `DisclosureKind` 별로 |

**전체 비율 하나가 아니라 종류별로 센다** — 확보율이 낮은 종류가 다음 작업 대상이기 때문이다.

### 실측 (2026-09-03, 프로덕션 페이로드 `disclosurePhrases`/`picks[].whyNow`)

```
화면에 나간 공시 항목            26건
  그중 실적 서식                  8건 (30.8%) — 전부 `반년 치 실적을 냈어요`, 전부 국내
  그중 제목이 금액을 들고 온 건    0건 (0.0%)
```

**금액 0건이 핵심 사실이다.** DART 목록 API 의 `report_nm` 은 서식 이름만 준다 —
`단일판매ㆍ공급계약체결 · 계약금액 320억` 같은 형태는 번역표 문서의 예시였고 **실제 수집물에는
없다**. 그래서 PART C(규모 대비 환산)는 구현·테스트가 끝났지만 **본문 파싱 없이는 프로덕션
확보율이 0 이다.** 지어내지 않으므로 그 줄은 나오지 않는다.

반대로 PART A·B(실적 숫자)는 팩트시트에서 오므로 **제목과 무관하게 8건 전부가 대상**이다.
그 8건이 지금 `실적을 냈어요` 로 끝나던 줄이고, 이 작업이 고치려던 바로 그것이다.

### 구조적으로 확보 못 하는 것과 그 이유

| 종류 | 확보 | 왜 |
|---|---|---|
| 실적(반기·분기·사업보고서, 손익구조 30% 변동, 영업(잠정)실적) | **가능** | 팩트시트 분기와 `filed_at` 로 조인된다 |
| `결산실적공시예고` | 불가 | **예고**라서 숫자가 아직 없다 |
| 수주·자사주·증자·담보·타법인 취득 | **제목에 금액이 있을 때만 = 실측 0/26** | 본문을 저장하지 않는다(WO-RESET-02 하지 말 것 1번). DART 목록 API 의 `report_nm` 은 서식 이름만 준다 |
| 지분 5% 신고 | 불가 | 지분율·보유목적이 **본문에만** 있다 |
| 그 외 전부 | 불가 | 같은 이유 — 제목에 없는 숫자는 없다 |

**본문 파싱을 하면 수주·자사주·증자·담보의 확보율이 크게 오른다.** 그것이 다음 작업이고,
`byKind` 가 어느 종류부터 할지 알려준다.

### 확보율을 좌우한 것은 코드가 아니라 **팩트시트 신선도**였다

배포 직후 `figures` 는 **0** 이었다. 원인을 실측으로 잡았다 — `네패스` 의 프로덕션
`companyRead` 가 `매출 +3.6% · 영업이익 +199.0%` 인데, 네이버 현재 데이터로 2026Q2 대비를
계산하면 `+17.4% · +82.5%` 다. **저장된 팩트시트의 최신 분기가 2026Q1** 이었다는 뜻이고,
8월 14일 반기보고서(2026Q2 보고)는 조인 창 밖이라 숫자를 안 붙였다(지어내지 않는다).

낡은 원인은 구조적이다 — `fundamentals-backfill.yml` 헤더가 적어 뒀듯 Vercel 크론이 하루
1회 12종목만 처리해 **전수 갱신에 24일**이 걸린다. 마지막 전수 백필은 **2026-08-06**,
네이버가 Q2 를 올리기 전이다.

`only=` 로 8종목을 targeted 갱신(`universe 760 → 8`, 1라운드 ~130초)한 뒤 리베이크하니
5종목에 숫자가 붙었다. 나머지 3종목(신성이엔지·에이치브이엠·효성티앤씨)은 그 라운드에서
처리되지 않았다(`processed=4`) — 갱신되면 붙는다.

**따라서 `figures 6/57` 은 이 기능의 한계가 아니라 그날 팩트시트가 최신인 종목 수다.**
전수 갱신 처리량은 별건이다(#1206 이 확인을 싸게 만들었을 뿐 처리량은 그대로다).

### 원문과 어긋난 값 1건 — 열어 둔다

E1 영업이익 증감률이 **+17%** 인데 네이버 현재 값으로는 **+15.4%**
(`(1,179−1,022)/1,022`). 매출 `+94%` 는 정확히 일치한다(`(44,028−22,656)/22,656 = +94.3%`).
네패스·시프트업은 매출·영업이익 네 값 모두 정확히 일치한다.

즉 **저장된 E1 의 전년 동기 영업이익이 ~1,008억**이고 네이버가 지금 주는 1,022억과 다르다 —
소스 수정(restatement) 또는 수집 시점 차이다. 조인·계산 로직 문제는 아니다(같은 로직이
다른 종목에서 정확히 맞는다). 팩트시트에 저장된 분기값을 들여다볼 조회 경로가 없어서
여기서 원인을 특정하지 못했다. **다음 작업 후보**: 저장된 분기값 감사 라우트.
