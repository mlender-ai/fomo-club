# 공시 제목 번역표 — 사람 검토용

> **이 문서가 정본이다.** 코드(`packages/fomo-core/src/keyword-cards/disclosure-phrase.ts`)와
> 함께 바꾼다. 코드에만 있으면 검토할 수 없다. (WO-RESET-05 §3-1 · 완료 확인 5)

## 무엇을 하는 표인가

상세의 「왜 지금 사는가」에 공시 제목이 **원문 그대로** 올라가고 있었다:

```
임원ㆍ주요주주특정증권등소유상황보고서
주식등의대량보유상황보고서(일반)
타인에대한담보제공결정
```

이건 근거가 아니라 **금융감독원 서식 이름**이다. 읽는 사람은 무슨 일이 있었는지 모른다.

## 지킨 규칙

| 규칙 | 왜 |
|---|---|
| **번역이지 요약이 아니다** | 한 서식은 한 사건을 뜻한다(그래서 서식이 나뉘어 있다). 그 사건을 우리말로 옮기는 것은 해석이 아니다 |
| **제목에 없는 것은 안 넣는다** | 금액·평가·전망 금지. 본문을 저장하지 않으므로 넣을 재료도 없다 |
| **제목이 들고 있던 숫자는 남긴다** | `계약금액 320억` 을 떨어뜨리면 번역이 아니라 손실이다 |
| **평가어 금지** | `좋은`·`유망`·`저평가`·`호재` 를 쓰지 않는다. 테스트로 막았다 |
| **표에 없으면 원문 그대로** | 억지로 비슷한 칸에 밀어 넣지 않는다. 틀린 우리말보다 원문이 정직하다 |
| **정정은 종류가 아니라 상태** | 원 종류를 물려받고 `(정정)` 을 뒤에 붙인다 |

## 검토가 필요한 곳

읽으면서 **"이 말이 저 서식을 정확히 옮긴 게 맞나"** 만 봐주면 된다. 특히:

- 반대 사건이 섞이지 않았나 (자기주식 **취득/처분/소각/신탁**은 서로 다른 일이다)
- 너무 세게 말하지 않았나 (`문제가 생겼어요` 가 사실보다 무겁지 않은지)
- 더 쉬운 말이 있나

## 일부러 **안 넣은** 서식

| 서식 | 왜 안 넣었나 |
|---|---|
| `투자판단관련주요경영사항` | 무엇이든 담을 수 있다. 한 문장으로 옮기면 반드시 틀린다 |
| `주요사항보고서` | 상위 묶음이라 실제 사건이 제목에 없다 |
| `기타경영사항` | 이름 그대로 기타다 |

이런 것은 **원문 그대로** 나간다. 그게 정직하다.

## 실측 커버리지 (2026-08-27 프로덕션)

```
화면에 나간 공시 항목 24건 중 번역 19건 = 79.2%
원문 그대로 나간 5건은 전부 이 표에 추가했다:
  자기주식취득결과보고서 · 주주명부폐쇄기간또는기준일설정
  기업설명회(IR)개최 · 기업가치제고계획예고
```

**원문으로 나가는 것이 실패는 아니다** — 그게 정직한 기본값이다. 다만 자주 나오는 것은
채우는 게 낫고, 계수기가 무엇을 채울지 알려준다.

## 커버리지

화면에 나간 공시 항목 중 번역표에 없어 원문이 그대로 나간 비율은 페이로드의
`qualification.disclosurePhrases`(`total` / `raw`)로 계측한다. 이 비율이 보고 대상이다
(WO-RESET-05 보고할 것 3번).

## 제목 번역만으로는 부족했다 → DETAIL-02

이 표는 서식 이름을 우리말로 옮기는 데까지다. 그래서 `반년 치 실적을 냈어요` 는
**옮기기는 성공했는데 정보가 아니다** — 실적이 좋았는지 나빴는지 알 수 없다.

제목 아래에 **실제 숫자**(매출·영업이익·순이익 + 전년 동기 대비)와 **금액의 규모 대비
환산**을 붙이는 것은 `docs/wo/DETAIL-02-earnings-figures.md` 가 정본이고 구현은
`packages/fomo-core/src/keyword-cards/disclosure-figures.ts` 다.

**이 표의 규칙은 그대로다** — 제목에 없는 것을 제목 줄에 넣지 않는다. 숫자는 제목이 아니라
**팩트시트 분기 재무**에서 오고, 별도 블록으로 아래에 놓인다.
