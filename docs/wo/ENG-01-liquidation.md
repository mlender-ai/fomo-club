# ENG-01 — 강제청산 모델

| 항목 | 값 |
|---|---|
| 선행 | OPS-01 |
| 마감 | 수요일 |
| 완료 | 페이퍼가 거래소와 같은 규칙으로 청산되고, 과거 거래가 재채점된다 |
| 연결 | 연구 02 — **실매매 차단 항목** |

---

## 0. 왜

지금 페이퍼는 **증거금이 바닥나도 포지션이 살아 있다.**

```
3배 레버리지 → 가격이 약 −33% 움직이면 거래소는 청산한다
페이퍼는 청산 안 함 → 버티다 반등하면 이익으로 기록
```

**페이퍼가 실제보다 무조건 좋게 나온다.** 이게 없으면 페이퍼 성과를 믿을 수 없다.

연구 05에서 확인한 것도 같은 뿌리다 — 1배와 3배 PF가 소수점까지 같았다. 청산이 없으면 레버리지는 그냥 배율이다.

---

## PART A — 청산가 계산

### A-1. 거래소 규칙을 따른다

FCE가 쓰는 거래소(Bitget·Hyperliquid 등)의 공식 규칙을 확인한다. **감으로 공식 만들지 않는다.**

```
필요한 것
  유지증거금률 (종목·포지션 크기별 단계가 있을 수 있음)
  청산 수수료
  격리 / 교차 마진 — FCE가 어느 쪽인가
```

### A-2. 대략

```
롱 청산가 ≈ 진입가 × (1 − 1/레버리지 + 유지증거금률)
숏 청산가 ≈ 진입가 × (1 + 1/레버리지 − 유지증거금률)
```

**이건 참고용이다.** 실제 구현은 거래소 문서 기준.

### A-3. 펀딩비

누적 펀딩비가 증거금을 깎는다 → 청산가가 진입가 쪽으로 다가온다. **매 펀딩마다 청산가를 다시 계산한다.**

---

## PART B — 청산 체결

```
봉 저가(롱) 또는 고가(숏)가 청산가를 건드리면
  → 그 봉에서 청산
  → 청산가 또는 그보다 나쁜 가격으로 체결
  → 증거금 전액 손실 + 청산 수수료
  → 청산 사유: liquidation
```

### B-1. 갭

```
봉 시가가 이미 청산가 너머면 → 시가로 청산 (청산가보다 나쁨)
```

### B-2. 손절과의 순서

```
같은 봉에서 손절선과 청산가를 둘 다 건드리면
  → 손절선이 청산가보다 진입가에 가까우면 손절 먼저
  → 아니면 청산
```

---

## PART C — invariant 추가

```
PnL은 증거금 대비 −100% 아래로 갈 수 없다
포지션 손실이 증거금을 넘으면 그 전에 청산됐어야 한다
```

**위반하면 트랙 정지.** 다른 invariant와 같이 다룬다.

---

## PART D — 과거 재채점

**이게 연구 02의 답이다.**

```
1  지금까지의 모든 거래를 청산 모델을 넣고 다시 돌린다
2  청산됐어야 했는데 살아남은 거래가 몇 건인가
3  그 거래들의 기록 손익과 재채점 손익 차이
4  트랙별 N · 승률 · PF · MDD 가 어떻게 바뀌나
```

### D-1. 기록을 덮어쓰지 않는다

```
기존 기록   그대로 둔다
재채점      별도로 저장 (rescored_with_liquidation)
화면        둘 다 보여준다 — 재채점을 기본으로
```

### D-2. 1배 · 3배 다시 비교

연구 05를 다시 연다.

```
청산 모델 넣고 1배 · 3배를 재채점
→ 이제 달라져야 한다
→ 3배에서 청산되고 1배에서 산 거래가 몇 건인가
```

---

## PART E — 이후 운용

청산 모델이 들어간 뒤부터 **모든 페이퍼 거래는 청산 규칙을 따른다.**

- 포지션 탭 가격 레일에 **청산가** 표시 (무효화선보다 바깥)
- 청산가까지 거리가 가까우면 경고 (UI-06에 이미 있는 청산 위험 알약과 연결)

---

## 완료 확인

1. 거래소 청산 규칙 출처가 문서에 있다
2. 청산가 계산이 구현됐고 펀딩비에 따라 갱신된다
3. 청산 체결 · 갭 · 손절 순서 규칙이 있다
4. `PnL < −100%` invariant가 있다
5. **과거 거래 재채점 결과가 있다** — 청산됐어야 할 거래 수 · 손익 차이
6. 기존 기록을 덮어쓰지 않았다
7. 1배 · 3배 재비교 결과 · 연구 05 갱신
8. 연구 02 닫기 (결정 포함)
9. 포지션 레일에 청산가가 보인다

---

## 하지 말 것

- 청산 공식을 감으로 만들지 말 것
- 기존 기록을 덮어쓰지 말 것
- 재채점 결과가 나쁘다고 숨기지 말 것
