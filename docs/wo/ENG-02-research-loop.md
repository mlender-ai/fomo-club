# ENG-02 — 자체 연구 루프

| 항목 | 값 |
|---|---|
| 선행 | OPS-01 · ENG-01 |
| 마감 | 금요일 |
| 완료 | 엔진이 스스로 개선안을 만들어 그림자로 돌리고, 판정 결과를 연구 노트로 올린다 |

---

## 0. 목표와 가장 큰 위험

### 0-1. 목표

```
지금     광혁이 문제를 보고 → 지시서 → 에이전트가 고침
바뀌면   엔진이 자기 성과를 보고 → 개선안 → 스스로 검증 → 광혁은 승인만
```

### 0-2. 가장 큰 위험 — 스스로를 속이는 기계

**엔진이 개선안을 많이 시도할수록 그중 하나는 우연히 좋아 보인다.**

이미 겪었다. 후보 12개에서 1위가 우연일 확률 99%.

자동으로 시도하고 자동으로 적용하면, **운 좋은 파라미터를 계속 채택하는 기계**가 된다. 페이퍼에선 좋아 보이고 실매매에서 무너진다.

**그래서 규칙이 셋이다.**

```
1  한 번에 하나만 바꾼다
2  판정 기준은 시작 전에 고정한다
3  적용은 사람이 승인한다
```

---

## PART A — 루프

```
관측 ─▶ 가설 ─▶ 그림자 운용 ─▶ 판정 ─▶ 연구 노트 ─▶ 🧑 승인 ─▶ 새 버전
  ▲                                                              │
  └──────────────────────────────────────────────────────────────┘
```

---

## PART B — 관측 · 가설

### B-1. 어디서 가설이 나오나

**데이터에서 약점을 찾는다.** 매일 한 번.

| 관측 | 가설 예 |
|---|---|
| 비용이 총손익의 85% | 거래를 줄이면 비용 후 손익이 나아진다 |
| 손절 후 7일 반등 비율이 높다 | 손절이 너무 빡빡하다 |
| 익절 후 더 오른 비율이 높다 | 익절이 너무 이르다 |
| 고래 체결 → 우리 진입 지연이 길다 | 진입을 앞당기면 승률이 오른다 |
| 특정 시간대 · 종목 손실 집중 | 그 조건을 걸러낸다 |
| 트랙이 기준선 미달 | — (가설이 아니라 사실) |

### B-2. 가설 형식

```
관측     비용이 총손익 규모의 85%다 (복기 · 264건)
가설     진입 최소 기대 이익을 비용의 3배로 올리면 비용 후 손익이 개선된다
바꿀 것  entry.min_expected_edge   1.0× → 3.0× 비용
그대로   나머지 전부
```

**바꿀 것이 둘 이상이면 가설을 쪼갠다.**

### B-3. LLM 사용

가설 **문장**을 쓰는 데만 쓴다. **파라미터 값은 데이터로 정한다.** LLM이 숫자를 고르지 않는다.

---

## PART C — 그림자 운용

### C-1. 그림자란

```
본 트랙과 같은 신호를 받는다
딱 하나만 다르게 한다
자본은 본 트랙과 같다
결과는 따로 기록한다
본 트랙에는 아무 영향이 없다
```

### C-2. 제한

| 규칙 | 값 |
|---|---|
| 동시 그림자 | **최대 3개** |
| 그림자당 바꿀 것 | **1개** |
| 백테스트만으로 판정 | **금지.** 반드시 페이퍼 그림자 기간을 거친다 |

### C-3. 백테스트는 거르는 데만

```
가설 → 백테스트 → 본 트랙보다 명백히 나쁘면 버린다
                → 아니면 그림자로 올린다
```

**백테스트를 통과했다고 좋은 게 아니다.** 떨어뜨리는 용도다.

---

## PART D — 판정 (시작 전에 고정)

### D-1. 사전 등록

그림자를 시작할 때 **판정 기준을 기록하고 잠근다.** 중간에 바꾸면 그 그림자는 무효.

```
그림자 #07
시작        2026-10-02
가설        진입 최소 기대 이익 3배
판정 시점   거래 30건 이상 AND 14일 이상
통과 조건   수익÷낙폭이 본 트랙보다 높다
            AND 다중 비교 보정 후 우연 확률 < 20%
            AND 비용 후 손익이 본 트랙보다 좋다
잠금        ✅
```

### D-2. 다중 비교 — 누적으로 센다

```
우연 확률 계산에 넣는 시도 수 = 지금까지 돌린 그림자 전부
```

**이번 주 3개만 세면 안 된다.** 지금까지 20개를 돌렸으면 20개로 센다. 시도할수록 통과가 어려워지는 게 맞다.

누적 시도 수를 연구 탭에 항상 보여준다.

### D-3. 결과

| 결과 | 처리 |
|---|---|
| 통과 | 승격 후보 → 연구 노트 → 🧑 승인 대기 |
| 실패 | 연구 노트에 "없음"으로 닫음. **지우지 않는다** |
| 판단 불가 | 기간 연장 **1회만** (기준은 그대로) |

---

## PART E — 연구 노트 자동 작성

판정이 나면 연구 탭에 노트가 생긴다. UI-08 규칙 그대로.

```
08                                          [승인 대기]
진입 문턱을 올리면 비용 후 손익이 나아지나

그림자 #07 · 14일 · 거래 34
본 트랙   수익÷낙폭 −0.82 · 비용 후 −$174
그림자    수익÷낙폭 −0.31 · 비용 후 −$61
우연 확률 14% (누적 시도 7)

결정 → [승인] [기각]
```

---

## PART F — 🧑 승인

```
승인  → 본 트랙 새 버전으로 반영
        옛 버전은 보관 (성적 그대로)
        반영 시각 기록
기각  → 노트에 사유 기록하고 닫음
```

**승인 버튼은 사이트에 두되 로그인 뒤로.** 공개 페이지에서 누구나 누르면 안 된다. 로그인이 없으면 **지금은 텔레그램으로 승인한다** (`/approve 07`).

### F-1. 자동 승인 금지

아무리 결과가 좋아도 엔진이 스스로 본 트랙을 바꾸지 않는다.

---

## PART G — 첫 실험 후보

지금 데이터에서 바로 나오는 것. **이 중 3개만 먼저.**

| # | 가설 | 근거 |
|---|---|---|
| 1 | 진입 문턱을 비용의 N배로 올리면 비용 후 손익이 나아진다 | 비용이 총손익의 85% |
| 2 | 손절을 넓히면 손절 후 반등 손실이 준다 | 복기 청산 품질 (값 확인 필요) |
| 3 | 크립토 자본을 늘리면 수수료 비중이 준다 | 500 USDT · 3배로 포지션이 작다 |
| 4 | 고래 진입 지연을 줄이면 승률이 오른다 | 연구 01 |

**3번은 파라미터가 아니라 자본 설정이다.** 광혁 결정이 필요하다 — 판정 결과만 보고한다.

---

## PART H — 화면

연구 탭에 섹션 추가.

```
실험 중                                  누적 시도 7

#07  진입 문턱 3배         9일 · 거래 21/30    ━━━━━━━░░░
#08  손절 −8% → −12%      4일 · 거래 8/30     ━━░░░░░░░░
#09  크립토 자본 2,000     2일 · 거래 3/30     ░░░░░░░░░░
```

- 누르면 본 트랙과 그림자 곡선 겹쳐 보기
- 판정 시점까지 진행 막대
- **판정 전에는 결과 숫자를 크게 보여주지 않는다** — 중간에 보고 흔들리지 않게

---

## 완료 확인

1. 매일 관측 → 가설 생성이 돈다
2. 그림자가 본 트랙과 격리돼 돈다 (본 트랙 영향 0 확인)
3. 동시 그림자 ≤ 3 · 그림자당 변경 1개가 코드로 강제된다
4. **판정 기준이 시작 시 잠기고, 잠긴 뒤 수정이 막힌다**
5. **다중 비교가 누적 시도 수로 계산된다**
6. 판정 결과가 연구 노트로 자동 작성된다
7. 승인 없이 본 트랙이 바뀌지 않는다 (시험)
8. 텔레그램 승인이 동작한다
9. 첫 실험 3개가 돌고 있다
10. 연구 탭에 실험 중 섹션과 누적 시도 수가 있다

## 하지 말 것

- 자동 승격하지 말 것
- 판정 기준을 중간에 바꾸지 말 것
- 한 그림자에서 두 개 이상 바꾸지 말 것
- 누적 시도 수를 리셋하지 말 것
- 실패한 실험을 지우지 말 것
- LLM에게 파라미터 값을 고르게 하지 말 것
