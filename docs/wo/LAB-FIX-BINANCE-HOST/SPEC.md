# SPEC: GitHub 러너 공개 시세 수집 복구

## 1. 문제
- 사용자가 실제로 겪는 문제: DB 복구 뒤에도 실시간 시세가 stale이라 페이퍼 신규 진입이 막힌다.
- 현재 제품에서 보이는 증상: `/data`와 `/live`가 BTC·ETH·SOL 시세 끊김을 표시한다.
- 근본 원인: GitHub-hosted runner에서 `api.binance.com`이 HTTP 451을 반환한다.

## 2. 목표
- Binance가 공식 권장하는 공개 시장데이터 전용 호스트로 현물 시세·봉·벤치마크 호출을 옮긴다.
- GitHub-hosted runner의 `latest`와 `candles`가 성공한다.
- 성공 지표: 수동 Actions 실행 성공, `LatestPrice` 3행 갱신, 증분 봉 품질 검사 통과.

## 3. 절대 제약
- 공식 Binance 공개 시장데이터 엔드포인트만 사용한다.
- 데이터 모양·검증·저장 규칙은 바꾸지 않는다.
- 펀딩비는 현물 API로 대체하지 않는다. 다른 시장의 값을 섞지 않는다.
- 실패를 빈 배열로 숨기지 않는다.

## 4. 비범위
- 상주 워커 도입.
- 펀딩비 공급자 교체.
- 전략·파라미터·성과 계산 변경.

## 5. 검증
- 단위 테스트로 시세·봉 요청 호스트를 고정한다.
- 타입체크·전체 테스트·빌드를 통과한다.
- GitHub Actions `latest`·`candles` 수동 실행을 확인한다.
