## PART A — 실적 숫자

### A-1. 숫자를 어디서 가져오나 (지시서의 첫 질문)

```
경로 B (있었다)   팩트시트 분기 재무 × 공시일 조인 — earningsFigures()
경로 A (없었다)   공시 본문 파싱 — 아무도 본문을 읽고 있지 않았다
```

**조인은 이미 있었다.** 「둘을 안 잇고 있다」는 지시서의 추정은 반만 맞다 — 이어져 있었고,
그 조인이 **네 개의 문턱**에서 떨어진다. 그런데 어느 문턱에서 떨어지는지 아무도 세지 않았다.

그래서 사유를 세는 판을 만들었다(`earningsFiguresDetail`):

| 사유 | 뜻 | 해야 할 일 |
|---|---|---|
| `not-earnings-form` | 실적을 담는 서식이 아니다 | **분모에서 빼야 한다** — 지분 5% 보고에 실적이 있을 수 없다 |
| `no-quarters` | 팩트시트에 분기 재무가 없다 | 팩트시트 수집 확장 |
| `no-join` | 분기는 있는데 공시일과 이어지는 기간(10~100일)이 없다 | 창 조정 |
| `no-prior-year` | 그 분기는 있는데 **작년 같은 분기**가 없다 | 분기 보관 기간 확장 |
| `no-fields` | 두 분기 다 있는데 값이 비어 있다 | 소스 품질 |

배포 후 `qualification.earningsFigureReasons` 가 이 분포를 답한다. **이게 완료 확인 1이다.**

### A-2. 경로 A 를 새로 만들었다 — 본문에 전년동기까지 있다

잠정실적 공시 본문을 실제로 읽어 보니 이렇다(빅텍, 2026-08-07):

```
구분(단위 : 백만원, %)  당기실적  전기실적  전기대비  전년동기실적  전년동기대비
매출액    당해실적  22,574  20,943   7.8  -  14,661   54.0  -
영업이익  당해실적     624     195  220.0  -     861  -27.5  -
당기순이익 당해실적    -567    -419  -35.3  -   1,232     -  적자전환
```

**팩트시트 조인이 필요 없다.** 당기와 전년동기가 같은 표에 있고 단위도 적혀 있다.
조인이 실패하는 날에도 이 경로가 숫자를 낸다.

두 경로가 **서로 다른 서식**을 맡는다:

| 서식 | 담당 |
|---|---|
| 잠정실적·손익구조 30% 변동 | 본문 파싱(경로 A) — 그 공시가 스스로 낸 숫자다 |
| 반기·분기·사업보고서 | 팩트시트 조인(경로 B) — 재무제표 전체가 들어 있어 7열 표 파서로는 못 읽는다 |

지어내지 않는 규칙 셋을 파서에 박았다.

- **열이 다 있어야 읽는다**(7열). 표가 밀리면 자리로 읽는 파서는 조용히 틀린다 —
  전년동기 자리에 전기 값이 들어가면 증감률이 통째로 거짓이 된다.
- **단위(`단위 : 백만원`)를 못 읽으면 안 읽는다.** 자릿수를 모르는 숫자는 숫자가 아니다.
- **기간은 `당기실적` 날짜에서 읽는다.** 처음엔 헤더의 `(26년2분기)` 를 읽었는데,
  같은 표에 전년동기 헤더 `(25년2분기)` 도 있어서 **첫 괄호를 집으면 작년 분기를 이 공시의
  기간이라고 말한다.** 테스트가 그 버그를 잡았다. 괄호와 날짜가 어긋나면 아예 안 읽는다.

### A-4. 미국

SEC XBRL 어댑터는 이미 있다(`fundamentals/sec-xbrl.ts`, WO-SUB-01). 미국 픽이 덱에 올라오는
날 경로 B 가 그대로 작동한다 — 새로 만들 것이 없다.

## PART B — 공시 금액 0%

### B-1. 왜 0이었나 — **제목만 읽고 있었다**

```
disclosureScaleNote({ title, scale })   ← 제목에서 금액을 파싱한다
```

실측: **프로덕션 공시 27건 중 제목에 금액 표기가 있는 건이 0건.** 규모 환산 기계(분모 규칙 ·
제외 규칙 · 최소 비율)는 **다 만들어져 있었고 분자가 없었다.**

금액은 본문에 있다. 그리고 본문은 **열쇠 없이** 읽을 수 있다.

### 본문을 읽는 두 홉

```
① dsaf001/main.do?rcpNo=…   뷰어 껍데기 — 실측 523자, 금액 0건
     viewDoc("20260807900376", "11514220", …)   ← 여기서 dcmNo 를 캔다
② report/viewer.do?rcpNo=…&dcmNo=…             ← 여기에 본문이 있다
```

종전 코드(`fetchDartReportText`)는 ①만 읽었다. 본문을 읽는다고 하면서 **껍데기 메뉴 글자만**
보고 있었다.

**인코딩이 결과를 갈랐다.** 문서는 `utf-8` 을 선언하면서 손상된 바이트를 섞어 보낸다.
거기서 cp949 로 넘어가면 라벨(`계약금액`)까지 깨져 아무것도 못 읽는다 — 실측에서 그 한 줄
때문에 4건이 2건이 됐다. 선언을 먼저 읽고 손실을 허용해 디코딩하면 라벨이 살아남는다.

### 실측 — 본문에서 실제로 뽑힌 것

```
공시 27건 · 본문 읽힘 27/27

✓ 단일판매ㆍ공급계약체결      계약금액(원) 40,480,580,000  → 405억
✓ 단일판매ㆍ공급계약체결      계약금액(원) 22,712,250,000  → 227억
✓ 자기주식취득신탁계약체결    계약금액(?��) 10,000,000,000  → 100억  (괄호가 깨져 온다)
✓ 연결재무제표기준영업(잠정)실적  실적 3줄 (매출·영업이익·순이익)
- 유상증자결정               금액 서식인데 못 뽑음 — 필드가 `신주수 × 발행가액` 이다
- 자기주식처분결정·결과       라벨이 손상돼 `보통주식` 으로 읽힌다
```

### 위험 하나를 실측에서 잡았다

라벨만 보고 본문을 뒤지면 **반기보고서 각주의 `배당금액(USD, 천) 24,845`** 가 잡힌다.
그걸 이 공시의 금액이라고 말하면 거짓이다. 그래서 **금액이 그 공시의 주제인 서식에서만**
찾는다(`AMOUNT_FORMS` — 지시서 §B-2 의 8종). 정기보고서는 그 목록에 없다.

### B-3. 금액만 쓰지 않는다

```
disclosureAmountLine() →  "계약금액 405억 · 최근 1년 매출의 26%"
                          "100억 · 시가총액의 1.2%"
```

**비율을 못 만들면 금액도 쓰지 않는다**(지시서 「금액만 쓰고 비율 안 붙이지 말 것」).
분모 이름은 우리가 나눈 것을 그대로 말한다 — TTM 을 `연매출` 이라 부르지 않는다.

### 분모를 바로잡아야 한다

지시서의 목표는 「공시 금액 40%」인데, 그 분모가 **전체 공시**면 도달 불가다.
오늘 27건의 구성:

| 금액이 있을 서식 | 6건 | 공급계약 2 · 자기주식취득 1 · 유상증자 1 · 자기주식처분 2 |
| 금액이 없는 서식 | 21건 | 지분 5% 보고 7 · 대규모기업집단현황 5 · 임원 보유변동 2 · 주주총회결과 · IR 등 |

지분 5% 보고에 계약금액이 있을 수 없다. **금액 서식 기준**으로 재야 한다 —
오늘 표본에서 3/6(50%)이 이미 뽑히고, 유상증자·자기주식처분을 더하면 5/6(83%)이다.

### §C 미국 설명 — 두 가지가 뒤집혔다

```
universe 95 · coverage 33.7% · cached 32 · filled 0 · noSource 0 · rejected 40
```

**① 0% 가 아니었다.** 이미 32/95 가 캐시에 있었다 — FIX-02 의 「0%」는 그날 덱에 미국 픽이
없어서 **화면 기준** 0% 였던 것이다. 심볼 수도 212 가 아니라 **95** 다.

**② 내가 넣은 검증이 40건을 전부 떨어뜨렸다.** 원인은 날조가 아니라 **단위 환산**이다 —
원문 `1.6 million members` 를 `1,580만 명` 으로 옮기면 그 숫자가 원문에 문자로 없어서
근거 검증이 막는다. **검증이 옳고 지시가 부족했다.**

고친 방식: 검증을 느슨하게 하지 않고 ① 단위 변환 금지 ② 그러니 `15.8 million 명` 이 나와서
`hasLatinUnitWord()` 로 막고 ③ 실패하면 **숫자 없이 한 번 더** 쓴다(심볼을 버리지 않는다).
로컬 실측 **5/5 통과**(1차 4 · 재시도 1).

진단 스크립트가 프롬프트 **사본**을 쓰고 있어 한 번 헛짚었다(사본 통과 · 실제 탈락) —
실제 함수를 부르게 바꿨다.

### §B 금액 — 서식은 11건, 줄은 0건

**네 지표 다 목표 미달이다.** 지시서의 마지막 금지가 「확보율이 낮은데 출시하지 말 것」이고,
그 판단의 근거를 매일 같은 자리에서 볼 수 있게 만든 것이 이 배치의 결론이다.

수치는 **덱 구성에 따라 흔들린다**(실적 35.7% → 31.3%, 「눈에 띄는 것」 51.5% → 54.1%).
하루치로 판정하지 말고 대시보드를 며칠 봐야 한다 — 본문 읽기가 남은 1,033건을 훑는 동안
금액·실적은 계속 오른다.

### ⚠️ 프로덕션 `AI_MODEL` 이 폐기된 모델을 가리킨다

```
HTTP 404 {"error":{"message":"The model `llama-3.3-70b-versatile` does not exist"}}
```

**미국 설명만의 문제가 아니다** — 프로덕션의 모든 LLM 경로가 404 를 받고 있다.
사람이 Vercel `AI_MODEL` 을 살아 있는 모델로 바꿔야 한다(로컬은 `openai/gpt-oss-120b`).

이 발견은 **사유를 세기 시작한 덕에** 나왔다: `rejected 40` → `llm-failed` →
`aiConfigured: true`(키는 있다) → 응답 본문의 모델 404. 세 번의 실측이 각각 한 겹을 벗겼다.
