# MACRO-01 — 거시 카드를 유가 하나에서 늘리기

| 항목 | 값 |
|---|---|
| 지시일 | 2026-09-01 |
| 상태 | 구현 완료 (PR #1197) |
| 완료 기준 | 거시 카드가 하루 1~3장 나오고, 데이터가 어제 것이다 |
| 근거 문서 | `docs/MACRO_THRESHOLDS.md`(임계·백테스트), `docs/design/DS-07_SHELL.md`(카드 껍데기) |

---

## 0. 무엇이 문제였나

```
국제 유가 · 2026-08-25 기준     ← 6일 전 데이터
국제 유가가 3일째 내리고 있어요
```

| 문제 | 내용 |
|---|---|
| 갱신 안 됨 | 8월 31일인데 8월 25일 기준 |
| 유가 하나뿐 | 5종을 정의해 두고 사실상 유가만 카드가 됐다 |

---

## 1. 왜 6일 전이었나 — 크론 문제가 아니었다

크론은 딱 한 번 돌았고(2026-08-31 00:48 UTC) **성공**했다. 원인은 소스다.

FRED 의 `DCOILWTICO` 는 EIA 발표 주기를 따라가므로 구조적으로 늦는다. **크론을 더 자주
돌려도 안 고쳐진다.** 그리고 FRED 에는 코스피·코스닥·국고채·회사채가 아예 없는데, 우리
종목은 대부분 국내였다.

| 지표 | FRED | 원본 |
|---|---|---|
| WTI 유가 | 08-25 $83.90 | **08-31 $85.76** (네이버) |
| 미 국채 10년 | 08-28 4.73 | **08-31 4.75** (재무부) |
| S&P 500 | 08-28 | **08-31** (네이버 해외지수) |

**FRED 를 전부 걷어내고 원본으로 갔다.** 옮겨 실은 것을 받을 이유가 없다.

> 다만 `scripts/macro-calibrate.ts` 는 **측정용으로만** FRED 를 계속 쓴다 — 임계는 분포를
> 보는 것이라 지연이 상관없고, 2년치를 한 번에 주는 편이 낫다. 의도된 차이다.

## 2. 지표 5종 → 15종

| 분류 | 지표 | 소스 |
|---|---|---|
| 환율 | `usdkrw` `jpykrw` | 네이버 `marketIndex/prices` |
| 금리 | `ktb3y` | 네이버 `interestDailyQuote` (`IRR_GOVT03Y`) |
| | `ust10y` `ust2y` | 미 재무부 일별 CSV |
| | `yieldcurve` | **계산** (10년 − 2년) |
| 신용 | `corp3y` | 네이버 (`IRR_CORP03Y`) |
| | `creditspread` | **계산** (회사채 − 국고채) |
| 지수 | `kospi` `kosdaq` | 네이버 `index/{code}/price` |
| | `sp500` `nasdaq` `vix` | 네이버 해외지수 |
| 원자재 | `oil` `gold` | 네이버 `worldDailyQuote` · `goldDailyQuote` |

### 못 넣은 것

| 지표 | 왜 |
|---|---|
| 미 기준금리 | 월간 시리즈(2년에 23관측) — 표본도 신선도도 안 된다 |
| D램 현물가 | 키 없이 일별로 주는 공개 소스를 못 찾았다 |
| 구리 | 네이버 `metals` 에 일별 시세표가 없고 FRED 는 월간 |
| 달러인덱스 | 코드(`FX_USDX`)는 있는데 일별 시세 표가 안 열린다 |

**자리만 만들어 두지 않는다**(DS-00 §1-1). 소스를 찾으면 그때 넣는다.

---

## 3. 신선도 — 자를 둘 쓴다

**거래일 2일 AND 달력 3일**을 넘게 묵으면 카드를 안 만든다.

| 자 | 막는 것 |
|---|---|
| 거래일 ≤ 2 | 소스가 실제로 며칠 밀린 경우 |
| 달력일 ≤ 3 | 화면에 `4일 전 기준` 이 뜨는 경우 |

거래일만 세면 금요일 값이 화요일까지 통과하는데 화면엔 `4일 전 기준` 이라 뜬다 — 지적받은
것과 같은 불쾌함이다. 달력일만 세면 **월요일마다 거시 카드가 전멸한다**(금요일 종가가 달력
3일). 둘 다 봐야 한다.

**장중 값을 종가로 쓰지 않는다.** 굽는 09:10 KST 엔 오늘 장이 10분 지났고, 그 10분치로
카드가 하루에도 몇 번 뒤집힌다(실측: 원엔 누적 -1.607% ↔ -1.29%).

**2일 연속 수집 실패면** 워크플로가 더 크게 운다(`macro:health` 가 연속 실패를 센다).

## 4. 임계 — 목표에서 거꾸로 풀었다

정본은 `docs/MACRO_THRESHOLDS.md` 이고 `scripts/macro-calibrate.ts` 가 생성한다.

- `movePct` = 연속 3일 이상인 날의 누적 변동률 **P50**
- `spikePct` = 하루 변동률 **P97**

P90/P97 로 시작했더니 하루 0.71건이었다. "카드가 적으니 임계를 낮추자"는 금지이므로, **목표
후보 수를 먼저 정하고 그걸 만족하는 가장 엄격한 백분위**를 찾았다. 백분위별 후보 수 표를
문서에 그대로 남겼다.

**급변은 따로 P97 로 못 박았다.** 후보 수를 맞추느라 같이 내렸더니 P79 가 나왔고, 그러면
닷새에 하루가 「급변」이 된다 — `하루에 0.7% 올랐어요` 를 급변이라 쓰는 건 거짓말에 가깝다.

손으로 적었던 첫 값이 얼마나 틀렸는지: 코스피를 `3.4` 로 적었는데 실측 분포는 전혀 다른
자리였다.

## 5. 네 사건만 카드가 된다

| 종류 | 무엇 | 우선순위 |
|---|---|---|
| `inversion` | 장단기 금리차 부호 반전 | 1 |
| `level` | 심리적 기준선 통과 | 2 |
| `spike` | 하루에 크게 | 3 |
| `streak` | N일 연속 + 누적 변동률 | 4 |

역전이 일어난 날 그걸 「3일째 내리고 있어요」로 말하면 훨씬 작은 이야기가 된다.

하루 **3장**, 같은 분류 **2장**. 강한 순(임계 배수)으로 고른다. 후보를 다 모은 뒤에 고르는
이유는, 목록 순서대로 돌다 상한에 닿으면 멈추면 **목록 위쪽 지표가 언제나 이기기** 때문이다.

---

## 6. 지수는 업종으로 잇지 않는다

코스피가 내렸을 때 「우리 종목 중 9곳이 여기 닿아요」는 **국내 종목 전부**다. 다 해당하는
연결은 연결이 아니다 — 아무 정보도 더하지 않는다.

지수는 **시장 소속**으로 잇는다. 그 시장 픽이 2곳 미만이면 카드가 안 나온다.

---

## 7. 카드 형태

- `$89.8 → $83.9` 가 값 줄과 보조 줄에 두 번 나오던 것을 **한 번으로**
- 영향 설명을 **상세로 내렸다** — 긴 카드는 눌리지 않는다
- 그러려면 받을 곳이 필요해 **`MacroDepth` 를 만들었다**

### 그 전에 있던 더 큰 구멍

**흐름·거시 카드가 덱에서 `onDetail` 없이 그려져 CTA 가 아예 렌더되지 않았다.** DS-07 §1 은
「어느 카드든 버튼이 같은 자리」라고 적어 놨는데 실제로는 두 종류에 버튼이 없었다.
거시는 이 작업으로 메웠고, **흐름 카드 상세는 아직 없다**(WO-RESET-08 §C).

## 8. 검증

`scripts/macro-backtest.ts` — 70거래일 재생(각 날짜에서 그날까지만 본다).

| 항목 | 값 |
|---|---|
| 하루 평균 | **1.77장** |
| 1~3장인 날 | 58일 (83%) |
| 0장인 날 | 12일 (17%) |
| 상한 초과 | **0일** |
| 실제 등장 지표 | **11종** |

`inversion` 은 이 구간에 0회다 — 미 장단기 금리가 안 뒤집혔기 때문이고, 코드가 안 도는 게
아니다(단위 테스트가 그 경로를 따로 본다). **없는 사건을 만들지 않는다.**

### 0장인 날을 어떻게 볼 것인가

17% 는 낮지 않다. 그래도 **조건에 맞는 게 없으면 0장**이 맞다. 늘리고 싶으면 임계가 아니라
**지표를 더 늘린다** — §2 의 「못 넣은 것」이 그 목록이다.
