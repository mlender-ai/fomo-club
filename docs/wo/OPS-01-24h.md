## 0. 지금 왜 불안정한가

```
FCE          ~/Documents/Fomo club engine 에서 돈다
러너         Claude 세션 안(pid 45295) — 세션이 끝나면 죽는다
             macOS가 ~/Documents 접근을 막아 FCE를 직접 못 읽는다
사이드카     그래서 FCE 파일을 캐시로 복사 중 — nohup, 재부팅하면 죽는다
맥           자면 전부 멈춘다 — 크립토 78일 중 49일 유실
launchd      한 번 올렸는데 토큰 자리에 '…' 이 들어가 전부 실패했다
```

**고칠 것은 넷이다. 맥을 안 재우고 · FCE를 막힌 폴더에서 꺼내고 · 러너를 launchd로 올리고 · 재부팅으로 확인한다.**

---

## STEP 1 🧑 — 맥이 자지 않게

### 1-1. 전원 연결 시 절전 끔

```bash
sudo pmset -c sleep 0 disksleep 0 powernap 0
sudo pmset -c displaysleep 10
pmset -g
```

- `sleep 0` · `disksleep 0` 이 보이면 된다
- 화면은 10분 뒤 꺼져도 된다. 본체만 깨어 있으면 된다
- **`caffeinate` 는 터미널을 닫으면 풀린다.** pmset이 영구다

### 1-2. 맥북이면

- **전원 어댑터를 꽂아 둔다** (`-c` 는 전원 연결 시만 적용)
- **뚜껑을 닫지 않는다.** 외부 모니터 없이 닫으면 잔다

### 1-3. 자동 업데이트 재시동 막기

시스템 설정 → 일반 → 소프트웨어 업데이트 → 자동 업데이트 → **"macOS 업데이트 설치" 끔**

새벽 재시동이 엔진을 끊는다. STEP 4가 되면 재시동해도 살아나지만, 업데이트 중 몇십 분은 빈다.

---

## STEP 2 🤖 — FCE를 막힌 폴더에서 꺼낼지 판단

### 2-1. 왜

`~/Documents` 는 macOS가 보호하는 폴더다. launchd로 도는 프로세스는 권한이 없으면 못 읽는다. 지금 사이드카가 필요한 이유가 이거다.

### 2-2. 선택지

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. FCE를 `~/fce` 로 옮긴다** | 권한 문제가 사라진다. 경로에 공백도 없어진다 | FCE 설정·스크립트의 절대 경로를 바꿔야 할 수 있다 |
| B. node·python에 전체 디스크 접근 권한 | 옮길 필요 없음 | 권한이 넓다. OS 업데이트 때 풀리기도 한다 |

**A를 권장한다.** 에이전트가 먼저 확인한다.

```
1  FCE 안에서 절대 경로(/Users/cocteau/Documents/...)를 쓰는 곳을 전부 찾는다
2  FCE 데몬이 launchd에 이미 등록돼 있나 (launchctl list | grep -i fce)
3  옮겨도 되는지, 바꿀 곳이 몇 군데인지 보고한다
```

**FCE 레포 코드를 고치지 않는다.** 경로가 설정값이면 설정만, 코드에 박혀 있으면 B로 간다.

### 2-3. 🧑 옮기기 (A로 결정되면)

```bash
# FCE 데몬이 돌고 있으면 먼저 멈춘다 (에이전트가 명령을 줌)
mv "/Users/cocteau/Documents/Fomo club engine" ~/fce
```

---

## STEP 3 🤖 — FCE 데몬 상시화 확인

러너만 올려도 **FCE 자체가 안 돌면** 소용없다.

```
1  FCE 데몬이 launchd 에 등록돼 있나
2  없으면 등록 스크립트를 만든다 (KeepAlive · RunAtLoad)
3  로그 경로를 /tmp 가 아닌 ~/fce/logs 로 (재부팅에 안 지워지게)
```

---

## STEP 4 🧑 — 러너 launchd 등록 (진짜 토큰으로)

### 4-1. 토큰 찾기

Vercel → 백엔드 프로젝트 → Settings → Environment Variables → `LAB_INGEST_TOKEN` 값 복사

### 4-2. 등록

```bash
cd ~/<fomo-club 레포 경로>
LAB_INGEST_TOKEN='여기에_복사한_값' scripts/lab/launchd/install.sh
```

**`'여기에_복사한_값'` 을 실제 값으로 바꾼다.** 따옴표는 남긴다. 지난번 실패는 이 자리에 `…` 이 들어가서였다.

### 4-3. 확인

```bash
launchctl list | grep -i lab
tail -f /tmp/lab-runner.log
```

로그에 `fce ✅ candles ✅ whale ✅` 가 보이면 된다. 🤖 에이전트에게 로그를 보낸다.

---

## STEP 5 🤖 — 옛 프로세스 정리

**새 러너가 `fce ✅` 를 두 번 연속 올린 뒤에만.**

```
1  Claude 세션 러너 (pid 45295) 종료
2  사이드카 종료
3  두 개가 같이 돌아 업로드가 겹치지 않는지 확인
```

---

## STEP 6 🧑 — 재부팅 시험 (이게 진짜 완료 조건)

```
1  맥을 재시동한다
2  로그인만 하고 아무것도 실행하지 않는다
3  10분 기다린다
4  사이트 헤더 동기화 점이 초록인지 본다
5  에이전트에게 알린다
```

🤖 에이전트가 확인:

```
□  FCE 데몬 살아났나
□  러너 살아났나
□  첫 업로드 fce ✅
□  포지션 수가 재시동 전과 같나
□  재시동 동안 빈 구간이 차트에 회색으로 정직하게 표시되나
```

**재부팅 시험을 안 하면 완료가 아니다.** 지금까지 "돈다"고 보고된 게 전부 세션 안에서만 돌았다.

## 완료 확인

1. `pmset -g` 에 `sleep 0` · `disksleep 0`
2. FCE 위치 결정 (A 또는 B) · 이유 기록
3. FCE 데몬이 launchd에 있다
4. 러너가 launchd에 있다 · 진짜 토큰
5. 로그에 `fce ✅` 두 번 연속
6. 옛 러너 · 사이드카 종료
7. **재시동 후 10분 안에 사이트가 초록**
8. `docs/ops/RUNBOOK.md` 에 이 절차와 "멈췄을 때 다시 올리는 법" 이 있다

---

## 멈췄을 때 (RUNBOOK에 넣을 것)

```bash
launchctl list | grep -iE 'fce|lab'            # 살아 있나
tail -50 /tmp/lab-runner.log                    # 러너 로그
tail -50 ~/fce/logs/*.log                       # FCE 로그
launchctl kickstart -k gui/$(id -u)/<라벨>       # 다시 올리기
pmset -g                                        # 절전 설정 풀렸나
```
