# OPS-02 — 주식 트랙 복구

| 항목 | 값 |
|---|---|
| 선행 | OPS-01 |
| 마감 | **KR 월 09:00 · US 월 22:30 (KST)** |
| 완료 | 장이 열리고 첫 체결이 invariant를 통과해 기록된다 |

---

## 0. 상태

```
주식 US   ⛔ 정지    fill_price_outside_observed_range   N 3
주식 KR   ⚠ 보류    봉 불일치 정지 예방 · 대기 13,940건   N 0
```

연구 06 결론: **봉 불일치 하나가 US 정지와 KR 보류를 같이 만든다.**

→ 원인 하나를 고치면 둘 다 풀린다.

---

## PART A — 원인 규명 (먼저, 30분 제한)

### A-1. invariant가 말하는 것

`fill_price_outside_observed_range` = **체결가가 그 시각 봉의 고가~저가 범위 밖이다.**

체결가를 만든 가격 데이터와 봉 데이터가 서로 다른 세상을 보고 있다는 뜻이다.

### A-2. 흔한 원인 — 하나씩 배제

| 후보 | 확인 |
|---|---|
| **시간대** | 봉은 UTC, 체결은 KST(또는 ET)로 찍혀 한 칸 어긋남 |
| **장 시간 밖** | 장전·장후 가격으로 체결했는데 봉은 정규장만 |
| **수정주가** | 봉은 수정주가, 체결가는 원주가 (또는 반대) |
| **집계 차이** | 분봉 모아 만든 봉 vs 공급자 일봉 |
| **휴장일** | 휴장일에 봉이 없는데 체결이 찍힘 |
| **소스 불일치** | 체결가 공급자와 봉 공급자가 다름 |

**문제 체결 3건(US N=3)의 체결 시각 · 체결가 · 그 시각 봉을 나란히 놓으면 대부분 바로 보인다.**

### A-3. KR 대기 13,940건

같은 불일치를 invariant가 "정지 전에" 잡아 큐에 쌓은 것이다.

- 대기 주문의 생성 시각 분포를 본다 (언제부터 쌓였나)
- 몇 종목에 몰려 있나

### A-4. 30분 안에 못 찾으면

에이전트는 **추측으로 고치지 않는다.** 찾은 것까지 보고하고 멈춘다. KR은 월요일 오후로 미룬다.

---

## PART B — 고치기

### B-1. 원칙

- **invariant를 끄거나 느슨하게 하지 않는다.** 가격·봉 쪽을 맞춘다
- FCE 레포를 고쳐야 하면 **최소 범위**로, 무엇을 왜 바꿨는지 기록한다
- 고친 뒤 **과거 체결 전부에 invariant를 다시 돌려** 새 위반이 없는지 확인한다

### B-2. 거래일 캘린더

KR·US 휴장일을 엔진이 아는지 확인한다. 모르면 넣는다.

```
휴장일 → 신호 생성 안 함 · 주문 안 냄 · 커버리지 계산에서 제외
```

휴장일이 "관측 부족일"로 잡히면 유효일이 억울하게 깎인다.

---

## PART C — KR 대기 13,940건 처리

### C-1. **체결하지 않는다. 폐기한다.**

```
이 주문들은 과거 신호다.
지금 가격에 체결하면 과거 판단을 현재 가격으로 채점하게 된다.
성과가 오염된다.
```

### C-2. 폐기 방법

```
1  대기 주문 전체를 스냅샷으로 저장한다 (지우기 전에)
2  상태를 cancelled_stale 로 바꾼다 (삭제 아님)
3  사유 기록: "봉 불일치 수정 전 생성 · 체결 시 성과 오염"
4  폐기 건수와 종목 분포를 연구 06에 추기
```

### C-3. 재개 후

재개 이후 생긴 신호만 주문으로 간다.

---

## PART D — 재개 순서

```
1  원인 수정 배포
2  과거 체결 invariant 재검사 → 위반 0
3  KR 대기 주문 폐기
4  트랙 상태를 운용중으로
5  장 시작 → 첫 신호 → 첫 체결
6  첫 체결이 invariant 통과하는지 확인
7  사이트 전략 탭에 ● 운용중 표시 확인
```

### D-1. 장 시작 시각 (KST)

| 시장 | 정규장 |
|---|---|
| KR | 09:00 ~ 15:30 |
| US | 22:30 ~ 05:00 (서머타임 중 · 11월 초부터 23:30) |

**월요일이 휴장일인지 캘린더로 먼저 확인한다.** 휴장이면 다음 거래일이 마감이다.

### D-2. 첫날 감시

첫 거래일은 체결마다 로그를 본다. invariant 위반이 하나라도 나오면 **즉시 다시 정지**하고 보고.

---

## PART E — 자본 설정 확인

```
주식 US   100,000 USD
주식 KR   100,000,000 KRW
크립토    500 USDT
고래      500 USDT
```

**화면은 트랙당 $10,000로 환산하지만, 사이징은 원래 자본으로 된다.** 크립토 500 USDT는 3배로도 포지션이 작아서 수수료 비중이 커진다(비용 85%).

이 WO에서는 **바꾸지 않는다.** ENG-02 연구 루프의 첫 실험 후보로 넘긴다.

---

## 완료 확인

1. 원인이 문서에 있다 (US 3건 나란히 비교 포함)
2. invariant는 그대로다
3. 과거 체결 invariant 재검사 위반 0
4. 거래일 캘린더 반영
5. **KR 대기 주문이 폐기됐고 체결되지 않았다** · 스냅샷 보존
6. KR 장 시작 후 첫 체결이 invariant 통과
7. US 장 시작 후 첫 체결이 invariant 통과
8. 사이트에서 두 트랙이 ● 운용중
9. 연구 06에 결론 추기 · 닫을 수 있으면 닫는다

## 하지 말 것

- 대기 주문을 지금 가격에 체결하지 말 것
- 30분 안에 원인을 못 찾았는데 추측으로 고치지 말 것
- 자본 설정을 이 WO에서 바꾸지 말 것
