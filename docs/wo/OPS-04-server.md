## 0. 왜

OPS-01은 **응급처치**다. 맥이 켜져 있고, 업데이트가 없고, 정전이 없어야 돈다.

실매매 조건 1번이 **30일 연속 가동**이다. 맥으로는 보장이 안 된다.

---

## PART A — 어디에

### A-1. 조건

| 조건 | 이유 |
|---|---|
| **아시아 리전 (서울 권장)** | DB가 서울 · 거래소 API 지연 |
| 거래소 API가 막히지 않는 지역 | GitHub 러너(미국)에서 Binance 선물 451, 맥(한국)에서는 200이었다 |
| 상시 가동 | 서버리스 아님. FCE는 계속 떠 있는 프로세스다 |

### A-2. 먼저 확인

```
서버 후보 지역에서 FCE가 쓰는 모든 거래소·데이터 API를 한 번씩 호출해
200이 나오는지 확인한다. 하나라도 막히면 그 지역은 탈락.
```

**폴리마켓을 풀려고 지역을 고르지 않는다.** 폴리마켓은 제외 유지다.

**FCE 레포 코드는 그대로.** 설치·설정만.

---

## PART C — 키와 비밀

**가장 조심할 곳이다.**

### C-1. 거래소 키 분리

```
조회용 키    잔고·포지션 읽기만     ← 지금 필요한 것
주문용 키    주문 가능 · 출금 불가  ← 실매매 때
출금 권한    어떤 키에도 없다
```

**서버에 올리는 키는 조회 전용부터.** 페이퍼는 주문 키가 필요 없다.

### C-2. 🧑 키는 사람이 넣는다

에이전트는 비밀 저장 방식과 명령만 준다. 값을 다루지 않는다.

### C-3. 거래소 IP 화이트리스트

가능하면 서버 IP만 허용한다.

---

## PART D — 병행 운용 (맥 → 서버)

**한 번에 옮기지 않는다.**

```
1주차   맥: 운영 (업로드 O)
        서버: 그림자 (업로드 X · 로컬 기록만)
        → 매일 두 쪽 결과 대조

대조 항목
  같은 신호가 나왔나
  같은 시각에 체결했나
  같은 가격인가
  트랙별 N · 손익 차이
```

| 결과 | 처리 |
|---|---|
| 일치 | 서버를 운영으로 · 맥 러너 끔 |
| 불일치 | 원인 규명 · 맥이 계속 운영 |

**둘이 동시에 업로드하지 않는다.** 겹치면 원장이 오염된다.

## 완료 확인

1. 서버 지역에서 모든 API 200 확인
2. FCE · 러너가 systemd로 돈다
3. **서버에 조회 전용 키만 있다 · 출금 권한 0**
4. 1주 병행 대조 결과가 문서에 있다
5. 일치 확인 후 운영 전환
6. 맥을 끄고 24시간 동안 전 트랙 정상
7. 서버 재부팅 자동 기동 시험
8. 백업 복원 시험
