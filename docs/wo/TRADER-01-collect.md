## 0. 원칙

- **조회 전용 키.** 주문·출금 권한 없는 키만 쓴다. 🧑 광혁이 발급하고 넣는다
- **저장 위치는 비공개.** FCE 로컬 DB 또는 랩의 비공개 스키마. **레포에 거래 데이터 커밋 금지**
- FCE가 이미 실계좌를 읽고 있다. **FCE가 가진 것부터 쓰고, 모자란 것만 거래소에서 받는다**

## PART B — 거래 단위로 묶기

체결 여러 건 → 거래 1건.

```
거래
  id
  종목 · 방향
  진입 시각 · 평균 진입가 · 진입 체결 수 (분할 진입 여부)
  청산 시각 · 평균 청산가 · 청산 체결 수 (분할 청산 여부)
  최대 수량 · 명목 금액 · 증거금 · 레버리지
  실현 손익 · 수수료 · 펀딩
  보유 시간
  청산 방식   손절 주문 · 지정가 익절 · 시장가 · 청산(liquidation)
```

### B-1. 분할

**분할 진입·분할 청산을 반드시 살린다.** "절반 익절하고 나머지 끌고 간다" 같은 습관이 여기서 보인다.

```
분할 청산 1  30%  +2.1%   ← 첫 익절
분할 청산 2  30%  +5.4%
분할 청산 3  40%  +11.8%  ← 끌고 간 몫
```

---

## PART C — 거래마다 시장 상태 붙이기

**이게 TRADER-02의 재료다.** 진입·청산 시점에 시장이 어땠는지.

### C-1. 진입 시점

| 항목 | 출처 |
|---|---|
| 가격 vs 이동평균 (20·60·200, 1H·4H·1D) | 봉 |
| RSI · 거래량 배수 | 봉 |
| 직전 고점·저점까지 거리 | 봉 |
| BTC 추세 (같은 시각) | 봉 |
| 펀딩비 · 미결제약정 변화 | 거래소 |
| **고래 추적군 분포** | FCE |
| **패턴 판정 (시간봉별)** | FCE |
| 시간대 · 요일 | — |

### C-2. 보유 중

| 항목 | 뜻 |
|---|---|
| **MFE** (최대 유리 이동) | 들고 있는 동안 가장 좋았던 순간 |
| **MAE** (최대 불리 이동) | 들고 있는 동안 가장 나빴던 순간 |

**MFE·MAE가 매매법의 핵심 단서다.**

```
MFE +15% 에서 +4% 에 청산   → 일찍 판다
MAE −2% 를 넘긴 거래가 없음  → 손절이 −2% 근처
MFE를 거의 다 먹고 나옴      → 끌고 가는 기술이 있다
```

### C-3. 청산 시점

C-1과 같은 항목 + 청산 직전 무엇이 바뀌었나.

### C-4. 청산 후

청산 뒤 24시간 · 7일 가격. **판 뒤에 더 갔나, 판 게 맞았나.**

## PART D — 계좌 단위 지표

### D-1. 입출금 보정

```
기간 수익률 = 시간가중수익률 (입출금 시점마다 끊어서 곱한다)
```

**거래소 앱의 %는 쓰지 않는다.** 7일 +수백 % 같은 숫자는 입출금이 섞인 값이다. _(원문의 구체 숫자는 실계좌 화면 값일 수 있어 TRADER-00 원칙 1에 따라 뺐다.)_

### D-2. 계좌 지표

```
순손익 (USDT · 입출금 제외)
시간가중수익률
PF · 승률 · 평균 이익 / 평균 손실
일별 손익 분포 · 최대 일손실 · 최대 연속 손실일
MDD (시간가중 기준)
거래 수 / 일 · 비용 비중
```

## PART E — 확인

```
1  재구성한 거래의 실현 손익 합 = 거래소 기간 실현 손익 (오차 ±1%)
2  30일 합계가 앱의 30D PnL과 맞는지 (입출금 보정 전 기준)
3  거래 수 · 기간 · 누락 날짜
```

**1번이 안 맞으면 다음으로 안 간다.**

## 완료 확인

1. 조회 전용 키 · 출금 권한 없음 확인
2. 거래 데이터가 레포에 없다
3. 180일 이상 거래가 거래 단위로 묶였다
4. 분할 진입·청산이 살아 있다
5. 거래마다 진입·보유(MFE·MAE)·청산·청산 후 상태가 붙었다
6. 입출금 보정 시간가중수익률이 있다
7. **재구성 손익 = 거래소 손익 (±1%)**
