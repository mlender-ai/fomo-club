## 0. 왜 이 탭이 이 제품의 정체성인가

FCE는 **운용 도구**다. 포지션을 관제하고 성과를 보고한다.

이 탭이 더하는 건:

```
무엇이 궁금했나 → 어떻게 확인했나 → 무엇을 알았나 → 그래서 무엇을 하기로 했나
```

**틀린 걸 알아낸 것도 결과다.** "추세·평균회귀 진입에 우위 없음"은 실패가 아니라 **발견**이다.

### B-2. 예시 — 01

```
01                                                 [진행중]

고래는 65.8% 맞히는데
우리는 왜 32.4%인가

2026-09-17 열림 · 6일째 · 고래 추종 트랙


왜 궁금한가
────────────
고래를 따라가는 전략인데 절반밖에 못 맞힌다.
갭이 진짜라면 따라가는 방식에 문제가 있고,
갭이 가짜라면 숫자를 잘못 읽고 있는 것이다.


가설
────────────
1  두 승률은 모집단이 다르다 — 같은 기준이 아니다
2  진입이 늦다 — 고래 체결 후 우리 진입까지 지연
3  청산이 다르다 — 고래와 다른 시점에 나온다
4  지갑 선정이 틀렸다 — 통과한 2개가 좋은 지갑이 아니다


어떻게 확인하나
────────────
1  두 승률의 계산식을 나란히 놓는다
2  진입 지연 분포를 뽑는다
3  반사실 — 고래 청산을 그대로 따랐다면?
4  자격 기준을 바꿔 다시 뽑는다


지금까지 알아낸 것
────────────
✓  반사실: 고래 청산을 따라도 −49.58 (75건)
   → 청산은 원인이 아니다. 가설 3 기각.

·  모집단 비교: 진행중
·  진입 지연: 미착수
·  지갑 선정: 미착수


결정
────────────
아직 없음. 가설 1이 확인되기 전에는 전략을 바꾸지 않는다.


관련
────────────
트랙      고래 추종
문서      docs/lab/WHALE_GAP.md
```

## 완료 확인

1. 목록 hero가 열린 질문 수다
2. 필터 4개가 동작한다
3. 제목이 **전부 질문형**이다
4. 각 항목에 가장 중요한 숫자 한 줄이 있다
5. `실매매 차단` 상태가 따로 있다
6. 닫힌 항목에 결정이 있다
7. 상세에 질문·왜·가설·방법·알아낸 것·결정·관련이 있다
8. 알아낸 것에 ✓·✗·· 구분이 있다
9. **시드 7개가 실제 근거로 채워져 있다**
10. `실제 돈을 넣으려면` 블록이 있다
11. 파일로 관리되고 빌드 시 반영된다
12. 에디토리얼하게 보인다 (본문 폭 680 · 여백)
