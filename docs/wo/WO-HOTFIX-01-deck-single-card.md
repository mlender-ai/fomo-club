# WO-HOTFIX-01 — 덱이 1장만 나온다

| 항목 | 값 |
|---|---|
| 성격 | **긴급.** 다른 작업 전부 중단하고 이것부터 |
| 마감 | 2026-08-28 |
| 완료 | 덱이 10장 이상 나온다 |
| 원문 | 광혁 지시(HOTFIX-DECK). 채팅 원문을 규약대로 여기 옮긴다(AGENTS.md 세션 체크리스트 5) |

---

## 0. 현상

```
오늘의 조용한 돈  1곳
오늘은 새로 나온 곳이 적어요
16시간 전 기준
```

**15장 이상 나와야 하는데 1장이다.**

### 0-1. 화면이 주는 단서

| 단서 | 의미 |
|---|---|
| `오늘은 새로 나온 곳이 적어요` | 3장 미만일 때 뜨는 문구. **덱 구성 단계에서 잘렸다** |
| `16시간 전 기준` | 페이로드가 어제 것. 오늘 갱신이 안 됐거나 늦음 |

**후보를 못 찾은 게 아니라 만든 규칙이 잘라내고 있을 가능성이 크다.**

---

## PART A — 어디서 잘리는지 찾는다

**추측하지 말고 단계마다 숫자를 찍는다.** 파이프라인 각 단계에서 몇 개가 남는지 센다
(유니버스 → 데이터 → 신호 검출 → 기존 필터 → 3일 재노출 → 덱 구성 → 최종 덱).
**어느 단계에서 급격히 줄어드는지가 답이다.**

### A-2. 가장 의심되는 것

최근에 규칙을 세 개 겹쳐 걸었다.

| 규칙 | 출처 | 위험 |
|---|---|---|
| 3일 내 재노출 제외 | RESET-06 | 후보 대부분이 최근 3일에 나왔으면 전멸 |
| 신규(≤7일) 최소 60% | RESET-03 | 신규가 부족하면 **덱 크기를 줄이도록** 설계됨 |
| 유형 최대 50% | RESET-03 | 한 유형만 있으면 절반에서 잘림 |

**세 개가 곱해지면 1장이 될 수 있다.**

### A-3. 페이로드 갱신도 확인

오늘 프리웜/재생성이 성공했나 · 마지막 성공 시각 · 실패 로그.
**16시간 전이면 오늘 안 돌았을 수 있다.**

---

## PART B — 오늘 바로 고친다

A-1 결과에 따라 해당하는 것을 적용한다.

### B-1. 3일 규칙이 원인이면

3일 → 2일로 임시 완화한다. 그리고 규칙에 안전장치를 넣는다: 덱이 최소 장수(예: 8장)에
못 미치면 3일 규칙을 부분 해제한다. 단 해제로 들어온 카드는 "다시 나왔어요" 표시를 유지한다.

**규칙 때문에 덱이 비는 건 규칙이 잘못 설계된 것이다.** 안전장치가 없었다.

### B-2. 신규 60% 하한이 원인이면

하한을 비율이 아니라 "가능하면"으로 바꾼다.

```
전   신규가 60%에 못 미치면 덱 크기를 줄인다
후   신규를 우선 배치하되, 부족하면 지속 신호로 채운다
```

**덱을 줄이라고 한 건 내 지시였고, 그게 이 사고의 원인일 가능성이 크다.**
빈 덱보다 지속 신호라도 보이는 게 낫다.

### B-3. 유형 50% 상한이 원인이면

유형이 한 종류뿐이면 상한을 적용하지 않는다. 두 종류 이상일 때만 상한이 의미가 있다.

### B-4. 후보 자체가 적으면

D형·E형 임계 · 유니버스 크기 · 기존 필터 과잉을 확인한다.
이건 오늘 안 끝난다 — WO-RESET-04 PART D(유니버스 확대)로 이어진다.

### B-5. 페이로드가 안 돌았으면

재생성을 수동으로 한 번 돌리고, 왜 자동으로 안 돌았는지와 실패 알림이 왜 안 왔는지 확인한다.

---

## PART C — 다시 안 생기게

### C-1. 덱 최소 장수 안전장치

```
덱이 8장 미만이면:
  1  3일 재노출 규칙을 완화한다
  2  그래도 부족하면 신규 비율 하한을 푼다
  3  그래도 부족하면 유형 상한을 푼다
  4  그래도 부족하면 그대로 둔다 (진짜 후보가 없는 것)

푼 규칙이 무엇인지 로그에 남긴다.
```

**규칙은 품질을 위한 것이지 덱을 비우기 위한 게 아니다.**

### C-2. 알림

덱이 5장 미만이면 즉시 알림. **오늘 이걸 사용자가 화면 보고 알았다.**

### C-3. 단계별 숫자를 상시 기록

A-1의 단계별 통과 수를 **매일 자동으로 기록**한다.

---

## 완료 확인

1. 단계별로 몇 개가 남는지 숫자가 나왔다
2. **어느 단계에서 잘렸는지 특정됐다**
3. 원인 규칙을 고쳤다
4. **덱이 10장 이상 나온다** (실제 화면 확인)
5. 덱 최소 장수 안전장치가 들어갔다
6. 덱 5장 미만 알림이 걸렸다
7. 단계별 숫자가 매일 기록된다
8. 페이로드가 오늘 것으로 갱신됐다

## 하지 말 것

- 원인을 찾기 전에 규칙을 무작정 풀지 말 것. 그러면 이미 오른 종목이 섞인다
- 유니버스 확대를 오늘 하지 말 것. 별건이다
- 새 기능 만들지 말 것
