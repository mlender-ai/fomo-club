# WO-SYNC — 지시서·레포·에이전트 정합성 재정립

| 항목 | 값 |
|---|---|
| 성격 | 정합성 감사 + SSOT 단일화. **신규 기능 없음** |
| 마감 | 2일 |
| 후행 차단 | **이 WO 완료 전 CTX-01 이후 착수 금지** |
| 완료 | 다음 세션이 문서 한 곳만 읽고 현재 상태를 정확히 알 수 있는 것 |

---

## 0. 왜 필요한가 — 관측된 드리프트

| 사례 | 내용 |
|---|---|
| WO 문서가 레포에 없음 | 에이전트가 "02R 원문이 레포에 없어 지시 문장을 그대로 적용했다"고 보고 |
| 메모리 요약 오류 | "00~08 머지"로 잘못 요약돼 있었고 본문 실측은 "00·01·02·03 머지, 04~09 미착수" |
| **CTX 전제가 실측으로 뒤집힘** | 개인 수급 = 확보율 문제 ✕, **수집 미가동** ○ / 병목 = 요청 시점 계산 ✕, **콜드스타트·번들 10.15MB** ○ |
| 문서 간 문구 충돌 | CTX-00 "프로덕션 동작 변경 없음" vs 감사 라우트 배포 필요 |
| 배치 간 범위 중복 | CTX-05(카드 위계) ↔ WO-SUB-HOOK / CTX-06(검증실) ↔ WO-SUB-07 성적표 |
| 상태 문서 산재 | `AC_DEBT_LEDGER`·`BATCH_CLOSE`·`INCIDENT_*`·`SCOPE_kr_limitation`·`DECISION_*` |
| 버전 축 혼재 | 독트린 v1.0.0 / v1.2.0 / v1.4.0, 룰셋 버전, 파라미터 버전이 문서마다 다르게 인용됨 |
| 데이터와 표시 불일치 | `institution_streak` 카드 2장 모두 훅과 디테일의 연속일수가 어긋남 (26 vs 20, 6 vs 4) |

**드리프트의 근본 원인은 지시서가 채팅에만 있고 레포에 없다는 것이다.** 세션마다 인수인계 문서를 새로 쓰게 되고, 그 과정에서 사실이 조금씩 변형된다.

## PART A — 레포 실사

### A-1. 문서 인벤토리
`docs/` 전체를 나열하고 각각에 대해 적는다.

| 파일 | 최종 수정 | 내용이 현재 사실과 일치하는가 | 상위 문서 |
|---|---|---|---|

**"일치하는가"는 실측으로 확인한다.** 예: `SCOPE_kr_limitation.md`가 "KR 슬롯2·3 불가"라고 적고 있는데 DART가 열린 지금도 유효한가.

### A-2. 지시서 부재 확인
- `WO-SUB-*`, `WO-OPS-*`, `CTX-*` 중 레포에 커밋된 것이 몇 개인가
- 없다면 그것이 인수인계 문서로 대체돼 온 경위

### A-3. 코드와 문서 대조
| 대조 항목 | 확인 |
|---|---|
| 독트린 버전 | 코드의 실제 값 vs 문서 인용 |
| 룰셋·파라미터 버전 | 동일 |
| 아키타입 목록 | `doctrine.json` 실제 값 vs `DOCTRINE_archetype_frames.md` |
| 크론 배선 | `CRON_WIRING.md` vs 실제 워크플로·Vercel Cron |
| 활성 불변식 | `INVARIANTS.md` vs 실제 CI에서 도는 것 |

## PART B — 상태 재구성

### B-1. 단일 상태 문서 생성
`docs/STATUS.md` — **이 파일 하나만 읽으면 현재 상태를 알 수 있어야 한다.**

```markdown
# 현재 상태 (YYYY-MM-DD 기준)

## 배치별 진행
| 배치 | WO | 상태 | 미충족 AC | 차단 요인 |

## 차단 중인 것
| 항목 | 차단 요인 | 해제 조건 | 담당(사람/에이전트) |

## 프로덕션 실제 상태
- 정규 도메인 buildId / origin/main HEAD와의 차이
- 크론 가동 상태
- 데이터 커버리지 요약

## 알려진 결함
| 결함 | 영향 | 등재일 | 처리 예정 |
```

- 기존 산재 문서(`AC_DEBT_LEDGER`·`BATCH_CLOSE`·`SCOPE_*`)는 **상세 문서로 남기고 `STATUS.md`가 요약·링크**한다
- **매 WO 완료 시 `STATUS.md` 갱신을 완료 조건에 포함**한다

### B-2. 상태 확정 — 실측으로
문서 기록이 아니라 **코드·프로덕션 실측**으로 다음을 확정한다.

| 항목 | 확인 방법 |
|---|---|
| WO-SUB-00~09 실제 완료 상태 | AC별 대조 |
| 미완 AC 목록 | 실측 |
| 크론 가동 여부 | 최근 실행 이력 |
| 정규 도메인 반영 커밋 | `verify-production.ts` |
| 데이터 커버리지 | coverage 라우트 |

## PART C — CTX 배치 개정

실측으로 뒤집힌 전제를 반영한다. **개정 사항을 CTX 문서에 직접 반영하고 레포에 커밋한다.**

### C-1. CTX-00 개정
| 항목 | 수정 |
|---|---|
| "프로덕션 동작 변경 없음" | **"읽기 전용 감사 라우트 추가는 허용. 쓰기·크론 호출 금지"**로 변경 |
| 감사 인증 | `AUDIT_TOKEN` 별도 사용 명시. `CRON_SECRET` 재사용 금지 |
| A-1 표본 요건 | **200장 미달 시 확보 가능한 전수를 쓰고 그 사실을 기록**한다는 조항 추가 |
| PART C 결론 | 병목이 요청 시점 계산이 아니라 **콜드스타트·번들 크기**임을 반영 |

### C-2. CTX-01 개정 — 수집 선행 페이즈 추가
**개인 수급은 "확보율이 낮다"가 아니라 "수집이 돌지 않는다".** KIS 파서 호출처가 테스트뿐이고 크론 10개 중 수급 수집이 없다.

```
CTX-01 을 두 단계로 나눈다:

PHASE 1  수급 수집 가동
  - KIS 파서를 실제 배치에 배선
  - 크론 등록 + 스케줄 실행 연속 2회 성공
  - 소급 백필 가능 기간 확인
  - 커버리지 실측

PHASE 2  집계·파생 (기존 CTX-01 내용)
  - PHASE 1 커버리지 확보 후 착수
```

- **기관·외국인은 파서가 있으므로 "표출 문제"로 분류.** 별도 확인 항목으로 등재
- PHASE 1 커버리지가 낮으면 PHASE 2 범위를 축소한다

### C-3. 전 CTX 문서에 번들 격리 조건 추가
```
신규 모듈은 조회 경로 번들에 포함되지 않아야 한다.

- 계산을 배치로 빼도 무거운 의존성이 조회 번들에 들어가면 콜드스타트가 나빠진다
- 조회 경로 번들 크기를 CI에서 측정하고 임계 초과 시 실패
- 현재 10.15MB. 신규 모듈 추가 후에도 증가분이 임계 이내여야 한다
```

- `INV-C15`를 **"조회 경로에서 신규 모듈 미호출"에서 "미호출 + 번들 미포함"으로 확장**한다

### C-4. CTX-03 뉴스 분기 제거
**본문 금지·링크만으로 확정.** 조건부 분기를 삭제하고 단일 경로로 만든다.

### C-5. 범위 중복 해소
| 중복 | 처리 |
|---|---|
| CTX-05 ↔ WO-SUB-HOOK | WO-SUB-HOOK 미이행분(칩 축 중복·경고문 full 노출·회사설명 주력사업 누락 등)을 **CTX-05에 흡수**하고 WO-SUB-HOOK을 종료 처리 |
| CTX-06 ↔ WO-SUB-07 성적표 | 성적표 탭을 **검증실 탭으로 통합**할지, 별도로 둘지 결정하고 문서에 반영 |
| CTX-04 배경 후보 ↔ WO-SUB-06 리스크 | 둘 다 디테일에 들어간다. **섹션 순서와 중복 문구 방지 규칙**을 CTX-05에 명시 |

## PART E — 에이전트 컨텍스트 정렬

### E-1. 메모리 검증
에이전트 메모리에 기록된 사실 중 **현재와 어긋나는 것**을 목록화한다.

- 이미 확인된 오류: "00~08 머지" (실제 00·01·02·03)
- 배포 권한 관련 기록 ("권한 없음" → 실제로는 `workflow_dispatch` 가능)
- DART 관련 기록 ("Vercel에만 있음" → GitHub Secrets에도 등록됨)

**메모리 인덱스가 요약 과정에서 사실을 변형시킨 사례가 있다.** 요약이 아니라 `STATUS.md`를 참조하도록 유도한다.

### E-2. 세션 시작 체크리스트
`AGENTS.md`에 넣는다.

```
세션 시작 시:
1. docs/STATUS.md 를 읽는다
2. verify-production.ts 로 정규 도메인 상태를 확인한다
3. 스케줄 워크플로 최근 실행을 확인한다
4. 메모리와 STATUS.md 가 어긋나면 STATUS.md 를 신뢰하고 메모리 오류를 보고한다
```

## PART F — 즉시 수정 (신뢰 결함)

정합성 작업과 별개로, **화면에서 사실이 어긋나는 것**은 지금 고친다.

### F-1. 연속일수 불일치
`institution_streak` 카드 2장 모두 훅과 디테일의 연속일수가 다르다 (26 vs 20, 6 vs 4).

- 원인 규명: 계산 시점 차이인가, 다른 필드를 읽는가
- **같은 사실은 한 곳에서만 계산하고 양쪽이 그것을 읽도록** 수정
- 회귀 테스트로 고정

### F-2. 엔진 수치 소실
`QuietPickAnomalyFacts`의 `volumeVacuumRatio`·`pctAboveYearLow`·`volumePct`가 페이로드에서 문장으로만 남고 수치 필드가 0개다.

- **신규 수집 없이 발행 시점에 facts를 함께 박제**하면 회수된다
- CTX-05가 이 수치를 쓸 수 있도록 선행 처리
- 판단 원장에도 기록되어 사후 채점이 가능해진다

## 완료 조건

1. `docs/STATUS.md`가 존재하고 **실측 기반**으로 채워져 있다
2. A-3 대조에서 코드와 문서가 어긋나는 항목이 전부 해소되거나 등재돼 있다
3. CTX-00·01·03과 전 CTX 문서가 C절대로 개정되고 **레포에 커밋**돼 있다
4. `docs/wo/`에 CTX 배치와 미완 WO 지시서가 커밋돼 있다
5. `AGENTS.md`에 D-2·E-2 항목이 명시돼 있다
6. 에이전트 메모리 오류 목록이 보고돼 있다
7. **F-1 연속일수 불일치가 프로덕션 화면에서 해소**돼 있다
8. F-2 facts 박제가 적용돼 다음 발행부터 수치가 남는다
9. 범위 중복(C-5) 3건의 처리 방침이 문서에 있다

## 에이전트에게

- **문서 기록이 아니라 실측을 신뢰한다.** 문서가 "완료"라고 적혀 있어도 코드·프로덕션에서 확인한다
- 어긋나는 것을 발견하면 **문서를 사실에 맞춘다.** 사실을 문서에 맞추지 않는다
- 메모리와 실측이 다르면 실측이 이긴다. 메모리 오류를 목록으로 보고한다
- **`STATUS.md`가 이 WO의 본체다.** 다음 세션이 이 파일 하나로 현재 상태를 정확히 알 수 있는지를 기준으로 쓴다
