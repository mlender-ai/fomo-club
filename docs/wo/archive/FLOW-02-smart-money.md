## PART A — 카드가 어디서 만들어지나 (보고할 것 1번)

**소스에 있다.** 에이전트 보고(「소스 트리 전체에 없음」)는 틀렸다.

```
packages/fomo-core/src/keyword-cards/sector-flow.ts   flowHook() — 문장
apps/web/lib/quiet-pick.ts                            detectSectorFlows() — 집계·선별
apps/fomo-web/components/FlowCard.tsx                 카드
apps/fomo-web/components/FlowDepth.tsx                상세 다섯 걸음
```

| 확인 | 답 |
|---|---|
| LLM이 문구를 생성하나 | **아니다.** 순수 함수 템플릿이다(`flowHook`). 네트워크·시간·난수 0 |
| 다른 브랜치·배포에만 있나 | 아니다. `main` 에 있다 |
| 「그리고 지금은 아예 안 나온다」 | 나오고 있었다 — 2026-09-07 프로덕션 페이로드에 `flowCards: 1` |

2026-09-07 프로덕션 실측:

```
hook    "전기장비에서 돈이 빠지고\n무역으로 들어오고 있어요"
census  { rows: 20076, cards: 1, sectors: 71, unclassified: 137 }
```

즉 **없는 게 아니라 한 장 · 한 종류**였다. WO 가 요구한 것은 2~3장 · 3종류 이상이다.

## PART B — 업종명 (완료 확인 3·4)

표시명 표(`SECTOR_DISPLAY_NAMES`)와 라벨 위치는 **FLOW-01 에서 이미 했다.**
`반도체와반도체장비 → 반도체`, `전자장비와기기 → 전자부품`, 라벨은 막대 위 · 금액은 오른쪽 끝.
상한 7자를 넘는 표시명이 없음을 테스트가 지킨다(`overlongSectorNames`).

이번에 고친 것은 **화면이 짓던 문장**이다. 상세 헤더와 4걸음 제목이

```tsx
{fromName}에서 {toName}으로            // 표시명이 `반도체` 면 → 반도체으로
{toName}으로 돈이 들어온 지 얼마나 됐나요
```

로 조사를 박아 두고 있었다. 이 레포에서 **네 번째** 같은 실수다(`코스닥는`·`시장 대비이`·
`전자장비와기기으로`·`국제 유가이`). 업종 이름이 들어가는 줄을 전부 코어로 옮겼다 —
`flowDepthHeader` · `flowSinceTitle` · `flowSinceLine` · `flowVolumeTitle` · `flowVolumeNote` ·
`flowWatchTitle`. `josa()` 를 한 곳에서만 지키면 된다.

`josa-guard` 는 `packages/fomo-core/src` 만 훑는다 — 그래서 화면의 이 줄을 못 잡았다.
문장을 코어로 옮기면 가드 범위 안으로 들어온다.

## PART C — 종목 이름 (완료 확인 5·6·7)

### C-1. 카드에도 한 줄 — **이게 이 WO 의 핵심**

```
반도체에서 돈이 빠지고
전자부품으로 들어오고 있어요
[막대 셋 + 셋]
LG이노텍 · 삼성전기 등을 사고 있어요     ← 추가
최근 5거래일 · 외국인·기관 기준
```

`flowStockLine(stocks, direction)` — 대표 **둘**만. 순수 함수다.

| 규칙 | 이유 |
|---|---|
| 이름이 없으면 줄을 안 만든다 | 종목코드는 사람이 읽는 이름이 아니다 |
| 빠지는 카드는 `팔고 있어요` | 초점이 빠지는 쪽인 카드에 「사고 있어요」를 쓰면 거짓이다 |
| 종목 줄이 기준 줄보다 **위** | 기준은 확인하는 정보, 종목은 궁금해지는 정보다 |

### C-2. 상세 2걸음

DETAIL-01 에서 이미 만들었고 그대로 산다 — 판 종목 최대 5 · 산 종목 최대 5, 금액 순,
누르면 그 종목 상세로 간다(`resolveStock`). 이번에 바뀐 것은 **한 업종 이야기에서
상대편 목록이 빈다**는 점이다(없는 쪽을 지어내지 않는다).

## PART D — 막대 (완료 확인 8)

`FlowBar` 는 이미 D-1 을 지키고 있었다(같은 축 · 최대값 100% · 빠진 쪽 회색 · 들어온 쪽 라임).

바꾼 것은 **개수**다. 카드가 한 쌍만 그리고 있었다 — 상세 1걸음은 셋씩 그리는데
카드는 둘이었다. 카드도 `depth.outflows` · `depth.inflows` 를 그대로 써서 셋씩 그린다.
**같은 재료로 그리므로** 카드와 상세가 다른 숫자를 말할 수 없다.

재료가 없는 응답(오래된 페이로드)에서는 카드가 짚은 한 쌍으로 되돌아간다 — 빈 그림을
만들지 않는다.

## PART E — 카드 종류 (완료 확인 9·10)

**한 창에서 한 쌍만 뽑고 `break` 하고 있었다.** 그게 「하루 1장」의 원인이다.
같은 원장(업종별 일별 순매수)에서 세 종류를 더 만든다.

| 종류 | 훅 | 조건 |
|---|---|---|
| `rotation` | 반도체에서 돈이 빠지고 전자부품으로 들어오고 있어요 | 3·5·20일 창 중 첫 성립 |
| `concentration` | 방산에 5거래일째 돈이 들어오고 있어요 | 연속 순매수 ≥ 4거래일 |
| `persistent` | 반도체에서 12거래일째 돈이 빠지고 있어요 | 연속 순매도 ≥ 4거래일 |
| `reversal` | 15거래일 만에 처음 반도체로 돈이 들어왔어요 | 직전 15거래일에 순매수 날 0 |

세 가지를 못 박았다.

1. **`에만` 이라고 쓰지 않는다.** 우리가 아는 것은 「가장 오래·많이 들어온 곳」이고
   「거기에만 들어왔다」가 아니다. WO 예시 문구(`방산에만`)를 그대로 쓰지 않은 이유다.
2. **「처음」의 근거를 카드에 남긴다** — `직전 15거래일에는 들어온 날이 없었어요`.
   창을 밝히지 않으면 우리가 안 본 과거까지 단정하는 말이 된다.
3. **사흘은 이야기로 보지 않는다**(`FLOW_STREAK_MIN_DAYS = 4`). 방향이 무작위여도
   여덟 번에 한 번 사흘이 나온다.

선별 규칙(§E-2):

```
하루 최대            3장   (SECTOR_FLOW_MAX_CARDS)
같은 종류            1장   (검출기마다 하나만 돌려준다)
같은 업종 두 번      금지   (rotation 의 반도체 + persistent 의 반도체 = 한 이야기를 두 번)
```

**미구현 두 종류.** `전면 이탈`(외국인이 거의 모든 업종을 팔고 있어요)과 `주체가 갈림`
(기관은 사는데 외국인은 파는 업종)은 만들지 않았다 — 우리 원장은 외국인+기관을
**합친 금액**이라 주체를 갈라 말할 수 없다. 주체별로 나누려면 집계를 주체별로 두 벌
만들어야 하고, 그건 이 WO 의 「종류 3가지 이상」을 이미 채운 뒤의 다음 걸음이다.
지어내지 않고 남겨 둔다.

## PART F — 상세 나머지 걸음 (완료 확인 11)

1걸음(3+3 막대) · 3걸음(거래량 배수) · 4걸음(일별 20거래일) · 5걸음(즐겨찾기)은
DETAIL-01 에서 이미 있었다. 이번에 바꾼 것은 **초점**이다.

```
rotation      초점 = 들어온 업종     (종전과 같다)
persistent    초점 = 빠지는 업종     ← 새로 생긴 경우
```

3·4·5걸음이 초점을 따라간다. 4걸음 문장도 방향을 따라간다 —
들어오는 카드는 `20거래일 중 14일이 순매수였어요`, 빠지는 카드는 `… 순매도였어요`.
거래가 안 붙었을 때도 방향에 맞게 말한다(`조용히 사 모으는` ↔ `조용히 덜어내는`).
