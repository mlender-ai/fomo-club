# CTX-07 — 품질 게이트

> 지시 원문(채팅) 을 그대로 옮긴 정본. 구현 상태는 `docs/quality/INVARIANTS.md`(생성물) 와 `docs/STATUS.md` 에 남긴다.

| 항목 | 값 |
|---|---|
| 선행 | 각 WO 완료 시점마다 해당 불변식 활성화 |
| 성격 | 테스트 인프라 |
| 마감 | 배치 전체와 병행 |

---

## 0. 원칙

> **테스트가 깨지면 코드를 고친다. 테스트를 약화시키지 않는다.**

그리고 이번 배치에서 추가로 배운 것:

> **테스트가 통과하는데 실제로는 아무것도 검사하지 않는 경우가 있다.**
> 가격 무효선이 발행 시점 값끼리 비교하고 있었는데 타입·테스트를 전부 통과했다.
> 소급 스캔이 위반을 찾아도 `exit 0`이었다.
> **모든 불변식은 의도적 위반을 주입해 실패하는지 역검증한다.**

## 2. 기존 불변식 유지

INV-06~14가 계속 적용된다. 특히:

- `INV-08` 출처·시각 동반 — 신규 필드 전부에 적용
- `INV-09` 금지어 사전 — 배경 후보 문안 포함
- `INV-12` 결측 정직성 — `missing_participants` 등
- `INV-14` 렌더 경로 계산 금지 — **504 사고의 재발 방지 장치**

---

## 3. 역검증 (필수)

각 불변식마다 **의도적 위반 케이스**를 만들고, 그 케이스에서 테스트가 실패하는지 확인한다.

```
예시:
  INV-C1  →  "실적이 좋아져서 샀어요" 문안을 주입 → 실패해야 함
  INV-C5  →  결손일을 건너뛰는 연속 계산으로 되돌림 → 실패해야 함
  INV-C15 →  조회 경로에 flow 모듈 import 추가 → lint 실패해야 함
```

**역검증 없이 "위반 0건"을 성과로 보고하지 않는다.** 검사가 약한 건지 구조가 튼튼한 건지 구분이 안 된다.

## 4. 성능 회귀 게이트

504 사고를 반복하지 않는다.

```
CI에서 측정:
  - 발견 덱 조회 응답 시간 (모의 데이터, 종목 수 고정)
  - 각 배치 잡의 소요
  - 임계 초과 시 실패

프로덕션 감시:
  - 발견 API p95 SLO 초과 시 이슈 자동 생성
  - 스케줄 워크플로 연속 2회 실패 시 이슈 자동 생성
```

**이 배치는 카드에 층을 더 얹는다. 성능 예산 감시 없이 진행하면 같은 사고가 난다.**

## 5. 배포 검증 연동

`WO-OPS-DEPLOY`에서 만든 `verify-production.ts`를 **모든 WO 완료 판정의 선행 단계**로 둔다.

```
완료 보고 전에:
  1. verify-production.ts 실행 → 정규 도메인이 최신인지 확인
  2. 정규 도메인 DOM에서 산출물 확인
  3. 그 결과를 인용해 보고
```

## 7. 완료 조건

1. INV-C1~C15가 구현되고 해당 WO 완료 시점에 활성화된다
2. **각 불변식에 의도적 위반 케이스가 있고 그 케이스에서 실패한다**
3. 성능 회귀 게이트가 CI에 있다
4. 프로덕션 SLO 초과·워크플로 연속 실패 시 이슈가 자동 생성된다
5. `verify-production.ts`가 완료 판정 선행 단계로 문서화돼 있다
6. 골든셋 픽스처가 실제 응답이다
7. `INVARIANTS.md`가 기존 + 신규를 통합 문서화한다

## 8. 에이전트에게

- 불변식을 추가할 때 **"이걸 어기면 사용자가 무엇을 잘못 믿게 되는가"**를 먼저 쓴다. 그 문장이 없으면 불필요하다
- 해당 선행 WO가 끝나기 전에 활성화하지 않는다. CI가 상시 빨간색이면 아무도 안 본다
- **"위반 0건"은 역검증을 통과한 뒤에만 성과다**
- `AGENTS.md`의 "CI 그린" 판정 기준(PR 체크 + 스케줄 워크플로)을 계속 적용한다
